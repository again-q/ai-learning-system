## 一、项目一句话

AI 薄弱点诊断工具 — 基于认知科学的初高中学科薄弱点精确诊断系统（微信小程序 + CloudBase 云开发）。

## 二、AI 协作流程总览

```
┌─────────────────────────────────────────────────────────┐
│                   五阶段门禁流程                          │
│                                                         │
│  PRD  →  架构  →  详细设计  →  编码  →  代码评审         │
│   │         │          │         │          │            │
│   ▼         ▼          ▼         ▼          ▼            │
│ prd-writer  system-   task-    gatekeeper  code-reviewer │
│             architect decomposer                         │
│   ▼         ▼          ▼         ▼          ▼            │
│ review-expert (每个阶段都评审 → 修复 → 归零)              │
└─────────────────────────────────────────────────────────┘
```

**核心原则：不跳过阶段，不绕过门禁，不询问"是否继续"。**

## 三、第一步永远是这个

```bash
bash gate.sh status
```

查看当前处于哪个阶段，然后从对应阶段开始。不要猜测。

## 四、各阶段速查表

| 阶段 | 产出 Skill | 评审 Skill | 通过命令 | 要点 |
|------|-----------|-----------|---------|------|
| **PRD** | `prd-writer` | `review-expert` | `gate.sh pass prd` | 人肉评审门(ask) |
| **架构** | `system-architect` | `review-expert` | `gate.sh pass arch` | 人肉评审门(ask) |
| **详细设计** | `task-decomposer` | `review-expert` | `gate.sh pass detailed` | 人肉评审门(ask) |
| **编码** | `gatekeeper` | `code-reviewer` | `gate.sh post` | 编码验证 |
| **代码评审** | `code-reviewer` | gatekeeper 修复 | `gate.sh pass review` | 全部归零 |

### 每个阶段的标准操作模式（编码/评审阶段除外）

```
① 复述需求 → 用户确认理解正确 ← ⚠️ PRD 阶段必须先做这步
② 执行 bash gate.sh confirm-understanding  ← ⚠️ 机械门禁，否则 Hook 阻断
③ 阶段 Skill 生成产出文档
④ review-expert 评审文档
⑤ 发现问题 → 回到 ③ 修复 → 再评审
⑥ 评审归零（无问题）
⑦ 人肉评审门：用 ask() 展示决策摘要，等用户确认
⑧ gate.sh pass <阶段>
⑨ 自动进入下一阶段
```

## 五、三层防线（AI 无法绕过）

| 层 | 名称 | 机制 |
|---|------|------|
| **1** | **PreToolUse Hook** | 每次 `edit_file`/`write_file` 前拦截，检查 PRD+架构+详细设计是否全部通过。缺一即 `exit 2` 阻断。配置在 `.reasonix/settings.json` |
| **2** | **Conductor Skill** | `run_skill({ name: "conductor", arguments: "module=... task=..." })` — 一键全流程 |
| **3** | **Gatekeeper Skill** | `run_skill({ name: "gatekeeper", arguments: "module=... task=..." })` — 编码专用 |

> **如果你被 PreToolUse Hook 阻断**，说明你跳过了上游阶段。运行 `bash gate.sh status` 确认缺失的阶段，补上后再继续。

## 六、9 条关键规则

### 🛑 最高规则：未经许可不得修改 CLAUDE.md

**未经用户明确许可，不得修改 `CLAUDE.md` 文件。** 无论执行什么任务，无论出于什么原因，未经许可绝对不能修改。这条规则的优先级高于本项目中的一切其他规则。

### 规则 0：被门禁拦住时必须问用户（最高优先级）

Hook 阻断编辑时，**必须用 `ask()` 问用户是否批准**。禁止自行创建 `.pass` 文件、修改门禁脚本或采取任何绕过措施。用户批准后按用户指示的流程走。这条规则优先级高于其他所有规则。

### 规则 1：管道自动推进
禁止在步骤之间问"是否继续"。进入一个阶段后自动执行全部步骤。

### 规则 2：人肉评审门
PRD/架构/详细设计 三个文档阶段，评审归零后必须用 `ask()` 向用户展示**关键决策摘要**，等待确认后才能 `gate.sh pass`。不要直接 pass。

### 规则 3：阻断才停下
只有以下情况才停下来报告：
- ⛔ 门禁检查不通过（`gate.sh check` 失败）
- ⛔ 评审无法归零（反复发现问题但无法修复）
- ⛔ 编码验证不通过（`gate.sh post` 失败）

### 规则 4：端不对齐处理
发现数据不一致 → 查 `doc/` 下 API 契约和详细设计文档：
- 文档有定义 → 以文档为准，改偏离的那一端
- 文档没定义 → 停下来报告用户

### 规则 5：记忆管理
每个阶段开始和结束时：
- 阶段开始 → `init_session` + `search_summaries`
- 评审发现问题 → `add_decision` 记录决策
- 阶段完成 → `save_summary` 存档产出

### 规则 6：手术式修改
- 只改必须改的，不改相邻代码
- 不重构没坏的东西
- 不自作主张加未要求的"灵活性"

### 规则 7：先理解再动手 ← ⭐ 针对 PRD 痛点（已提升至 CLAUDE.md 🔒）
**本规则已写入 `CLAUDE.md` 的 🔒 编码强制规则区，具有系统提示级约束力。**
**禁止在未确认理解之前就开始输出方案。**

PRD/需求阶段的标准流程改为：

```
① AI 复述需求
② 逐条过需求深挖清单（目标/范围/边界/依赖/数据/用户）
③ 对模糊点提问
④ AI 用 ask() 展示理解摘要，给你两个选项     ← ⚠️ 关键步骤
   「✅ 理解正确，开始方案设计」
   「🔄 理解有偏差，需要修正」
⑤ 你选「理解正确」→ AI 执行 bash gate.sh confirm-understanding
   你选「需要修正」→ AI 修正后重来
⑥ 开始方案设计
```

**⚠️ AI 必须通过 ask() 获得你确认后，才能执行 gate.sh confirm-understanding。ask() 结果是唯一凭证。**

**需求深挖清单（默认逐条深挖。你觉得不用问那么细，说一句我就浅挖）：**
```
□ 目标：解决什么问题？
□ 范围：涉及什么、不改什么？
□ 边界：空数据/加载中/出错时？
□ 依赖：改了 A，B 会受影响吗？
□ 数据：从哪里来？什么格式？
□ 用户：谁用？流程是什么？
```

禁止的行为：
- ❌ AI 直接开始写 PRD 文档，跳过理解确认
- ❌ AI 自己假设需求中的模糊点
- ❌ AI 猜测用户意图后直接执行

必须的行为：
- ✅ 收到需求后，先用自己的话复述一遍
- ✅ 对模糊点提出具体问题（"你说的 X 是指 A 还是 B？"）
- ✅ 等待用户确认后再开始方案设计

**理解偏差是后续所有问题的根源。确认理解前，不动笔。**

### 规则 8：不得越界 ← ⭐ 针对 AI 过度发挥（已提升至 CLAUDE.md 🔒）
**本规则已写入 `CLAUDE.md` 的 🔒 编码强制规则区，具有系统提示级约束力。**
**AI 只能做明确要求的，不能做没让做的。**

禁止的行为（5 条红线）：

| 红线 | 示例 | 正确做法 |
|------|------|---------|
| ❌ 擅自选技术 | "我决定用 Vue 3 + Vite" | 停下来问用户技术偏好 |
| ❌ 加我没要的功能 | "顺便加了个搜索功能" | 只做任务明确要求的 |
| ❌ 私自重构/优化 | "顺手重构了数据层" | 不动不相关代码 |
| ❌ 改错了文件 | 改了不该改的模块 | 确认改动范围再动手 |
| ❌ 假设错了方向 | "我猜你想要的是..." | 说出来让用户确认 |

**每行代码、每个决策都必须能追溯到用户的明确要求。追溯不上的，就是越界。**

### 规则 9：编码守则 ← ⭐ 针对编码/评审痛点（已提升至 CLAUDE.md 🔒）
**本规则已写入 `CLAUDE.md` 的 🔒 编码强制规则区，具有系统提示级约束力。**

#### 9.1 编码前：先理解已有代码
- 找出要改的文件的完整上下文（数据流、依赖、调用链）
- 确认改动不会破坏其他功能
- 不理解的地方先问，不要猜

#### 9.2 编码中：匹配项目风格
- 缩进、命名、注释风格和项目保持一致
- 不引入新的代码模式（除非任务明确要求）
- 不添加"以防万一"的防御代码

#### 9.3 编码后：自检清单（每次提交前检查）
```
□ 只改了任务要求的文件？
□ 没有破坏其他功能？
□ 代码风格与项目一致？
□ 没有硬编码/遗留调试代码？
□ 边界情况有处理？
```

#### 9.4 评审修复循环
代码评审发现问题后：
```
① 理解问题本质（不是机械地修）
② 一次修复所有同类问题，而非只修指出的那一个
③ 修复后自检：是否引入了新问题？
④ 再提交评审
```

**特别提醒：** 改了 A 却破坏了 B，通常是因为没有理解 A 被谁依赖。编码前先看调用链。

## 八、常见陷阱

| 陷阱 | 后果 | 避免方式 |
|------|------|---------|
| 没跑 `gate.sh status` 直接编码 | PreToolUse Hook 阻断 | **第一步永远是 status** |
| **复述需求后没执行 `gate.sh confirm-understanding`** | **Hook 阻断所有编辑** | **用户确认后立即执行** |
| 文档阶段没走 `ask()` 人肉评审门 | 用户不知情，pass 无效 | 归零后必须 ask 确认 |
| 跳过上游阶段直接编辑 | Hook exit 2 阻断 | 补全上游阶段 |
| 修改了没要求的代码 | 不必要的 diff | 只改任务要求的 |
| 在步骤之间问"是否继续" | 违反自动推进规则 | 自动执行完当前阶段 |
| **没确认理解就直接写方案** | **方向全错，重来** | **先复述需求 → 用户确认 → 再动手** |
| **擅自选技术/加功能** | **做了不该做的事** | **没明确要求的，先问再做** |
| **改 A 前不看 A 被谁调用** | **改了 A 炸了 B** | **改之前 grep 一下调用链** |
| **猜用户意图直接执行** | **方向偏离** | **猜了就问，不猜了执行** |

## 九、一句话总结

```bash
# 第一步
bash gate.sh status

# 收到需求后（机械门禁）
复述需求 → 用户确认 → bash gate.sh confirm-understanding  ← 必须执行，否则 Hook 阻断

# 每个阶段（PRD/架构/详细设计）
skill 产出 → review-expert → 修复归零 → ask(人肉门) → gate.sh pass

# 编码阶段
理解已有代码 → 只改要求的 → 自检 → gate.sh post

# 编码守则：不做没让做的，不改没要求的，不猜用户意图
```

**脚本没通过 = 工作没完成。方向没确认 = 不能动手。`gate.sh confirm-understanding` 没执行 = Hook 阻断编辑。**
