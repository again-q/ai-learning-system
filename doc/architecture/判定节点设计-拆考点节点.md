# 判定节点设计 — 拆考点节点（K·题侧第一环）

> 状态：设计讨论中（2026-09 晚快照）；**只讨论不落地，实现等 LangGraph 环境就绪**。
> 证据：`doc/architecture/冒烟测试-拆考点节点.md`（冒烟方案/结果/修复验证）+ `output/smoke-拆考点/`（原始输出）。

## 1. 节点定位

- 诊断（判定）流水线内一个节点，**纯题侧**：拆"题目本身的标准考察"，不感知学生（同一题任何学生产物一致 → 可缓存、可人工复核一次全批生效）。
- 学生怎么做（路径）、水平到哪 → 全部下游节点处理，不进本节点。

## 2. 内部小图（模型→代码→模型）

```
输入：题面文字
① 模型：识别题涉及哪些教材章（1~N，宁宽勿漏）
       schema：{"chapters":["第一章 集合与常用逻辑用语",...]}（从章名表多选）
② 代码：按章取候选（getPointsByChapter：章=path[2]，只留知识点叶子）逐单元组织
       —— 真实检索已跑通：5 章，候选 36~125/章
③ 模型：逐单元勾选（一次只呈现当前单元，不跨单元混排，单元内编号 1~N）
       → 输出 pointIds + dkps（编号），代码查表还原名字并校验 ∈ 候选
       → 候选外但标准考察确实需要的点 → other（必填：name 五要素 + elementType + reason，缺一不可）
       → outOfSyllabus（课标层标记；粒度问题见待决 3）
产物：考点清单 [{点, 章, D_kp}] + other[] + outOfSyllabus
入选判据：不掌握它，本题就可能做错（题侧"标准考察"，不含学生）
D_kp：纯考察难度 0~1，无比重含义，同题相对可比（归一化手法待定）
```

其他定稿决策：
- 不做向量检索，用图谱分层结构检索（确定性、零向量成本、可解释）；
- 编号输出（模型不抄名字 → 掐断错字/改写源）；编号还原后二次校验；
- 候选是参考不是天花板——other 通道保证图谱缺的知识不被漏（T7 实测核心）。

## 3. 学生能力边界（假设存在，细粒度：已学章 ∪ 超前掌握点）—— 全部下游

```
考点清单 × 学生边界
  → 派生标注（纯代码：考点归属章 ∉ 边界 → 标超前）   ← 超前/超纲不做模型判断
  → 环节判定（下一节点）：逐点打 P_kp（含超前点：真展示了才算，路径无关）
  → 记账：已学点正常记；超前点 P_kp=1 → 记 K + 边界点级前移；P_kp<1 → 不计 D（没学的不会不降）
```

- 超前做对 → 记 K **并更新能力边界**（用户拍板）；边界按**考点级**更新（跟证据走不跟教材章走，建议待确认）。
- 局部超前（题部分已学部分超前）：范围内正常记、范围外走超前规则。

## 4. T7 候选外修复（已验证，见冒烟文档 §8）

- 问题：候选外题（导数）模型硬勾覆盖、不报 other。
- 修法：步③提示词强约束「标准考察独立拆、候选不足核心必报 other、禁止硬勾掩盖」。
- 验证：deepseek 下 C6=pass——导数链完整拆出（other 报 9 条细粒度/或 2 条合并粒度，取决于思考配置）；硬勾消失。
- 遗留观察：other 跨单元重复 → 需整题级收集 + 按名去重（待决 2）。

## 5. 🔴 配置发现（当前最优先待决）

| | thinking 默认开 | thinking disabled（= 线上 judgeOne 判定配置） |
|---|---|---|
| 耗时 | **1 题 2~5 分钟（不可接受）** | **~2.65 秒/题** |
| 质量 | 深：章识别全、other 细、超纲意识有 | 浅：漏章（T7 漏第三章）、other 粗、超纲标丢 |

- 线上 judgeOne 判定 = thinking disabled（决策 023：防"思考开+难题=content 空死锁"）。
- **怀疑**：judgeOne 里 knowledgeUsage 拆解也在 disabled 下跑 → "拆不够/挖掘不到位"可能一半是配置造成（判档类任务 disabled 够用，拆解是穷举深想任务）。
- **实测（2026-09，T7 单题）**：
  | 配置 | 耗时 | 成本/题 | 质量 |
  |---|---|---|---|
  | disabled（线上同款） | ~2.65 秒 | ~¥0.02 | 浅：漏章、other 粒度粗、超纲意识弱 |
  | effort low | **4m00s** | **¥0.12**（output 25008 tok，思考占大头） | 好：章识别全、8 考点 |
  | effort high | 6m20s（不可接受，已掐） | ¥0.1~0.4 级 | 深 |
  → **所有 thinking enabled 档位都是分钟级 + ¥0.1/题以上**（deepseek effort 档对思考量控制弱：low 也思考 2.4 万 tokens）。【用户拍板：路 A（low/high 全开）出局，仅路 B 可行】
- **结论：拆考点节点 = disabled 快扫为默认（2.65s/¥0.02）+ 条件深挖只留给可疑题**（跨章 / 双跑分歧）；深挖单次实测 ¥0.12 / 4min → 触发率须压到 <10%。两段式设计待细化（LangGraph 分支节点落地）。
- **两段式 v1 实测（2026-09，smoke-two-stage）**：
  | 题 | 阶段1 disabled | 触发 | 阶段2 deep(low) | 整题 |
  |---|---|---|---|---|
  | T2 普通 | 1.7s / 6考点 / 无other | 不触发 ✓ | — | **1.7s / ¥0.0017** |
  | T7 可疑 | 2.9s / 漏第三章 / other×3 | 触发 ✓ | 188s / 补出第三章 / other 9 条细化 | ~191s / ¥0.113 |
  → 分流正确（普通题秒级、可疑题才慢）；触发器 v1 = 结构信号（章≥2 或 other>0 或空章），T7 靠 disabled 报 other 触发；质量接近 full-high 但耗时减半。10 题卷估 ~6.5min/¥0.24（2 可疑题占大头）。**v2 优化方向：deep 段只补漏（漏章/other 细化）不整题重跑**。
