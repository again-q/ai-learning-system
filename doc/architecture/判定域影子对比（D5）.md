## 0. 大白话

线上判一道题，是「一个老师傅一个人从头干到尾」（`judgeOne` 800 行）。D4 已经把这 8 件事拆成 8 个小盒子交给新徒弟（`graphEngine` 的 N0–N7），徒弟还配了 43 个测试。**但学生用的还是老师傅。**

D5 = **让徒弟跟老师傅对答案**。对上了才敢换人。

中间有个坑：批改用的 AI **天生手抖**（同一道题今天给 0.65、明天给 0.62）。如果拿「徒弟今天做的」比「老师傅上周做的」，数字不一样时根本分不清是**徒弟手艺不行**还是**AI 这次手抖**。

因此 D5 的做法是：**让 AI 只判一次，把这份原始判定复印两份**，一份给徒弟、一份给老师傅，两人各自把它「整理成最终要说的话」，两句必须一致。这样「人稳不稳」和「AI 抖不抖」就彻底分开了。

---

## 1. 核心原则：把「壳」与「芯」分开

### 1.1 为什么必须同原始输出回放（same-raw replay）

D4 真实验证已实测同题重跑：`D 0.65→0.62`、`P 0.4→0.5`、`eta 0.5→0.6`、`pattern.variant` 措辞不同——**全部来自 AI 重跑抖动，不在壳**。
若直接比「新图重跑结果 vs 线上历史落库值」，抖动量会永久污染闸门：松了分不出壳写错，紧了永远卡死。

### 1.2 为什么 D5 阶段**不可能**出现「徒弟判得更准」

D4 的红线是「只换壳、不换芯」。2026-09-19 逐字比对线上 `judgeOne` 与 `graphEngine`：

| 芯的部件 | 线上 | 新引擎 | 结论 |
|---|---|---|---|
| `RUBRIC_V2` 标尺 | 1921 字 | 1921 字 | **逐字一致** |
| `userMsg` 提示词 | 3509 字 | 3509 字 | **逐字一致** |
| `TRACE_CROP_PROMPT` | 239 字 | 239 字 | **逐字一致** |
| system 角色设定 | 同一句 | 同一句 | 一致 |
| 模型参数 | thinking disabled / temp 0.2 / max_tokens 8000 | 同款 | 一致 |

→ **两点推论**：
1. 两边吃同一份 raw，连「这次 AI 心情好」的偶然变好机会都被排除；
2. 差异**只可能**来自壳（整理规则）——即「故意的修正」或「写错了」，没有第三种。

### 1.3 那「徒弟更好」怎么办？三条正道

| 情形 | 处理 |
|---|---|
| **旧的是错的**（如 `judgeOne:638` const 重赋值 bug） | 进 §7「有意修正清单」，**每条用户签字** + 附「旧的错在哪」的证据 → 从「差异」变成「批准的差异」 |
| **想让判定本身更准**（改 prompt、拆 AI） | 那是 **D6** 的活：固定评测集 + 多次重复（`scripts/eval-golden.mjs`、`doc/architecture/评测数据集预研.md`）。D5 比不出、也不该比 |
| **意外发现新图某字段一贯更合理** | **不许默默接受**：升级成一条「有意修正」走签字，否则回退 |

**业务理由**：现为校内 beta、有学生在用。一次改多个变量 → 出问题定位不了；「更好但没证据」就上线 = 拿学生当测试集。

## 2. 三层对比

```
取一道线上已判过的真题
  │
  ├─ N0 取题 ─ N1 翻旧账 ─ N2 AI 判定   ← 只调用这一次模型，产出 raw
  │                              │
  │        ┌─────────────────────┴──────────────────────┐
  │        ▼                                            ▼
  │   新壳 = N3 纯程序整理                  旧壳 = judgeOne 的整理段（喂同一份 raw）
  │        └────────────► L1 逐字段 diff ◄──────────────┘
  │                   判据：意外差异 0（硬闸门）
  │
  └─ 与「线上历史落库值」比 ──► L3 真实分布回归
                              判据：确定性字段 100% 一致；D/P/η 只出「抖动带」
```

| 层 | 比什么 | 判据 | 写库？ |
|---|---|---|---|
| **L1 壳一致（硬闸门）** | 同一份 raw → 新壳 vs 旧壳：`clamped{D,P,eta}`、`derived{errorType,errorLevel,errorAttribution,patternText,patternFull}`、选填题 `segments/breakpoint/processAvailable`、`fiveDim` 越界处理（决策 045） | **意外差异 0** | 不写 |
| **L2 落库映射** | 隔离环境（临时用户 + 临时题）跑全图 → 与线上同构核对：`questions` 19 字段、`knowledge_progress`（K/A）、`mastery_logs` 字段集（含 embedding/reportText）、`batches.progress` | 字段集/语义一致，无缺无多 | 写临时数据，跑完删 |
| **L3 真实分布** | 全量历史题重跑 vs 线上历史落库值 | 确定性字段（题型 / errorType / errorLevel / 知识点名 / 空白归因 / 三态）100% 一致；D/P/η 只统计抖动带 | 不写（`until:'N3_normalize'`） |

**效率**：一次 AI 调用（N2）同时服务三层——L1 用它的 raw 喂两边壳，L3 用它的落地值与历史值比。

## 3. 闸门口径（2026-09-19 拍板）

1. **意外差异必须 0**：同一份 raw 下，两边整理结果不同 = 壳有 bug（或有意修正，须走第 2 条）。
2. **有意修正**：逐条用户签字 + **每条有单测锁住**；总数 **≤3~5 条**。**超过 5 条 → D5 判不通过**（说明「换壳」没做到，回去改），不许加白名单蒙过去。
3. **数值抖动不进闸门**：D/P/η 只出「抖动带报告」，不当对错判据（避免把噪声当证据）。
4. **全绿即切**：L1/L2/L3 全绿直接切换，**不设「稳定 ≥1 周」观察窗**（用户 2026-09-19 拍板；原计划的一周等待改为「切换后继续跑影子回归」）。

> 闸门回答的是「**徒弟有没有偷偷改动作**」，回答不了「徒弟手艺是否更高」——后者是 D6 + 评测集的职责。

## 4. 样本与成本

- **样本 = 库里全部 38 道线上已判题**（11 批）。库本来就小，全量比精选更省心、也不引入挑选偏差。
- 天然覆盖：空白题 / 选填题（选择、填空）/ 多知识点解答题 / 跨 D 档（L3~L7）/ 有·无 batchId / 有·无裁剪图 / 被判 ≥4 次的知识点。
- **成本**：每题 1 次判定 ≈ 20–25 秒 → 全量一轮 **20–30 分钟**，费用个位数元。
- **数据安全**：L1/L3 一律只读（`until:'N3_normalize'`）；L2 用临时用户 + 临时题，跑完删除（决策 044）。
