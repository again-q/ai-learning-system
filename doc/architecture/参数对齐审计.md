## 9. K 的定稿：用什么参数、什么公式（2026-09-25，决策 052）

### 9.1 K 就用这 4 个参数（全是现有的）

| 用途 | 参数 | 说明 |
|---|---|---|
| 数据 | `knowledgeUsage[].name` | 指向**图谱最细一层**节点（自带类型：定义 / 性质 / 表示） |
| 数据 | `knowledgeUsage[].P` | 该环节作答：1 用对 / 0.5 用漏 / 0 缺失或全错 |
| 分流开关 | `errorLevel` | **concept → 扣 K**；rule → A；skill → S；跨单元组合失败 → T |
| 规则 | `isOutOfSyllabus` | 超纲题做错不扣（宪法 §4.4 原规则） |

**不再使用**：`D`（难度，决策 049 退出）｜`eta`（属 A）｜整题 `P`（属三态与 A）｜`isRecallQuestion`（**已删**，决策 051）。

### 9.2 公式

```
最细一层节点：K = 用对次数 / 被考察次数
              分子 = P_kp = 1
              分母 = P_kp = 1 的次数 + 概念性错（errorLevel = concept）的次数
              rule / skill 的错不计入（那是 A 和 S 的锅）

父节点（话题/单元）：K = Σ(w_i × 子节点K) / Σ w_i     ← 宪法 §4.5，w 未就位前等权
```

**为什么这样就不纠结「能不能 100%」**：
- **最细节点可以 100%** —— 最细一条定义他会就是会（「知道」没有「知道 60%」）
- **父节点到不了 100%** —— 简单题全对只点亮了「定义」这一个子节点，父节点是"一个有值 + 其余为 0"的加权平均（这就是"覆盖面"）

## 10. 治理新建的节点，AI 用得上吗？（第 3 层实测，2026-09-25）

**方法：注入法**（零代码改动、可反复用）。
把候选新节点的名字临时塞进 `output/golden/nodes-dump.json`（= 模型看到的清单），拿**同一批 6 道真实题 × 2 轮**再跑一次，对比「注入前 / 注入后」模型写出的名字。

本次注入三个名字：`集合的运算`、`集合元素的互异性`、`集合的包含关系`（前两个是把库里 `custom_nodes` 的自造名"就地转正"）。

### 结果：会用上，而且会"一拥而上"

| 指标 | A 臂（现状清单） | B 臂（注入后） |
|---|---|---|
| 主知识点命中这三个名字 | **2 / 12** 数据点 | **8 / 12** |
| 任一处命中（主或环节） | 2 / 12 | **10 / 12** |
| `集合的运算` 出现次数 | 3 | **16** |
| `集合元素的互异性` | 0 | **6** |
| `集合的包含关系` | 0 | **6** |

成本：12 次调用（约 1 元）；A 臂直接复用历史缓存，**不额外花钱**。

### 两个结论（一好一坏）

**✅ 好消息：治理新建节点是有效的**——名字一进清单，模型立刻大量使用，不必担心"建了没人用"。所以第 1、2 层（清单可见 + 匹配挂得上）是前提条件。

**⚠️ 坏消息：新节点会抢旧节点的题**（这就是第 4 层"抢题回归"要测的东西，实测成立）：
- 某道题原本主知识点是**「集合运算的基本性质」**，注入「集合的运算」后**主知识点被换成了新名字**；
- 另一道题原本主是「集合相等」，注入后变成「集合的运算」，并且环节里冒出「集合元素的互异性」——而它和图里已有的**「互异性」是同一个东西** → **同一知识点两个节点，账目直接分裂**。

### 对图谱治理的三条硬指导

1. **近义名一律不新建，改成"别名"挂在旧节点上**（这就是第 2 层要的 `aliases`）。否则每建一个近义节点，就等于把一本账撕成两本。
2. **新增节点必须做"抢题回归"**：把新节点注入清单，跑一批已有题，比较**新增前后的挂靠分布**——凡是"某题的主知识点从旧节点换成了新节点"的，都要人工过一遍（要么新节点其实不该建，要么旧节点该退休）。
3. **注入法本身可以当"新节点验收"的标准手段**：建节点 → 注入 → 跑同一批题 → 看命中率与抢题情况 → 达标才正式入库。全程零代码改动，成本约 1 元/批。

> 附带观察：B 臂的难度档位一致率仍是 **66.7%**（与决策 051 记录的清理后一致），而 A 臂旧 prompt 是 100% —— 说明**难度不稳来自 prompt 文案改动，不是清单注入**。
