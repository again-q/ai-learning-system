# 产品形态总设计

> **定位**：把项目设计中的产品形态——输入、处理过程、输出、知识图谱、个性化 AI 教练、数据资产、远期愿景——汇总到一份可共同参照的总览。散件的权威出处见各节「出处」标注；本文档只做汇总与索引，**不替代原文档**。
>
> **状态**：v0.1 汇总稿（2026-09）；凡标注【讨论中】的条目为在途设计，尚未拍板。
>
> **服务对象**：120+ 学生（福州八中校内）。**核心命题**：拍照上传题目就能出诊断报告——不搜题、不讲课、不刷题，只告诉学生"哪里不会、为什么不会、然后怎么学"（宪法 §1/§13）。

## 一、产品演进主线

| 版本 | 定位 | 一句话 | 出处 |
|---|---|---|---|
| **v1.0** | 诊断闭环 | 拍照上传 → 诊断 → 报告 → **自增强存储**（报告入库 + embedding/RAG + 掌握画像随用增强） | ROADMAP 远景（9/1 已上线，持续稳定中） |

## 二、输入形态

### v1 现状（拍照录入）
- **载体**：作业/练习/试卷的照片（整页或分题）。学生做题痕迹随照片进入，作为过程证据。
- **拍照链路**：L1 拍摄引导 + L2 压缩（长边 ≤2000px，wx.compressImage）→ 失败题自动排除/业务层重试（经验 §45）。
- **图像转录**：Qwen 系列主力（题目 + 做题痕迹整体把握）；视觉备胎走业务层重试（GLM 密集页 0 产出、DS vision-exp 已实测否决，经验 §44）→ **转录质量是过程侧判定的信息天花板**【讨论中：转录不完整时判定应如何降级，未定】。
- **题目来源**：照片 → AI 拆题（题干/类型/选项/标准答案 AI 计算；`providedAnswer` 接口预留标准答案人工注入，2026-09-04）。
- **过程证据**：分段转录（segments）+ 断点 + 过程可信标记（涂改/看不清 → processAvailable=false）。

### 远期输入（v2/v3）
- 考试卷、草稿本、多学科（数学优先、图谱暂只覆盖必修一）。
- **对话输入**（拍照产品缺的能力，T/Q/S 依赖）：AI 教练的文本/语音问答、Q 思维链弹窗回答、S 回溯自报、T 深层结构引导（M6/M7；语音 ASR 曾论证后搁置，决策 015）。
- v3.0 头脑风暴共创输入：学生 + AI 共同产出方法 → 收录个人知识图谱。

## 三、处理过程（核心流水线）

### 方向标：六阶段流水线（doc/architecture/诊断引擎-六阶段流水线.md）
采集（小程序端）→ 图像理解（Qwen）→ 核心推理与归因（DS）→ **数值计算（纯代码层，决策 014：AI 填参数 + 硬代码算）** → Q/S 维度（🔴 黑盒待细化）→ 报告生成 + 持久化。
> 早期还有"题型分类门禁"（回忆/单元内/跨单元/无法归类）设计，v1 实现已绕过（见 §十）。

### v1 实现现状（10 云函数）
```
photoUpload/ diagnose(转录) → judgeOne(判定巨石) → updateMastery(纯代码 K/A)
   → ragService(向量检索) → reportService(报告，模块化) / dispute(异议) / statService / graphService
```
- **judgeOne 是唯一"一步生成 18 字段大 JSON"的巨石**：题侧（D/level、correctAnswer、referenceProcess、isOutOfSyllabus、knowledgeNodeName、knowledgeUsage、pattern）与生侧（P、P_kp、segments、breakpoint、processAvailable、errorAttribution、errorDimension、errorType、errorLevel、eta、fiveDim）混在一次 LLM 调用里。
- reportService 已按模块拆分（决策 029：weakpoints/overview/secondary/questionEvolution/dispute 各配模型、失败隔离、模块溢价 70–80%）——**项目里已示范过"节点化"**。

### 设计方向【讨论中，2026-09】：判定流水线节点化
方法论文案：**把"一步生成一大坨"切成职责单一的节点；每节点输出可单独验收**（稳定性 + 可定位 + 可测）。judgeOne 应拆为两条链：
```
题侧链（一次/题，可缓存、可人工复核）：
  题面 → [拆题节点] → 考点清单 + pattern + D + 超纲标记 + 标准解法
生侧链（一次/人/题）：
  题侧产物 + 学生痕迹 → [环节判定节点] → 逐考点 P_kp + segments/断点 + 归因
  分数更新（纯代码，已是 updateMastery）
```
- K 拆解基准 = **题目侧知识链**（学生没碰的环节也要列出、按断点给 P_kp=0），过程只用于给环节打分、不决定拆出哪些点（宪法意图确认，2026-09）。
- 配套：**每节点配验收标准**（即"每新功能配审查 skill"决定，短期不做）。

### 远期：LangGraph/编排
- ROADMAP 规划 LangGraph 迁移窗口 9/8–9/15（绞杀者模式按节点切换、CloudRun 部署 langgraph-server），前提 = 试点稳 ≥1 周。节点化是编排的前提，编排是载体，两者解耦。

## 四、输出形态

### v1 现状（报告 v2，2026-08-31 原版设计语言恢复）
- 总结页（够厚硬约束，决策 027-b）：战绩 + coreHint + mood + 主攻 + 对错速览 + 错题逐题 + 次要模式 + 怎么用报告 + 异议入口 + 看诊断。
- 每题详情：题干/判定（D/P/归因/知识点）+ 过程分段 + 断点 + **AI 参考过程**（判错才生成，2026-09-04）+ 进阶分析 + 题型异议。
- 掌握度连带：本次批次涉及的每个知识点 判定前→判定后 掌握度变化（reportService buildMasteryChange）。
- 掌握度画像 → 知识图谱页（progressMap 染色，颜色档位目前用 75/50 自定义，**与宪法 §4.6 四档 80/60/40 不一致**【未决】）。
- 题型轨迹/断点移动（statService patternTrajectory）：断点位置是否在移动（起步即停→中途断→收尾断→做对），不做错误黑账。
- 单题历史演化（questionEvolution：这道题的过去和现在）。

### 输出契约
- 报告 JSON v1：overview / weakpoints（四段式主模式）/ secondaryPatterns（折叠次模式）→ 前端组件映射（doc/architecture/报告JSON结构.md）。
- 报告五层结构与行动模块（补缺漏计划 v2：含行为设计）见 doc/architecture/诊断报告设计.md。
- 掌握度四档：🟢≥0.80 / 🟡0.60~0.79 / 🟠0.40~0.59 / 🔴<0.40（宪法 §4.6）。

### 远期输出
- **v2.0 AI 教练个性化输出**：基于个人画像的讲解/答疑/练习建议/补缺漏计划/复习提醒。
- **v3.0 训练场输出**：方法卡片（规则提炼，收录个人图谱）、跨单元联想链。

## 五、知识图谱（诊断底座）

### 结构
- **树**：学科 → 章 → 节 → 知识点；节点 JSON 五段：basic（身份）/ tree（path/parentId 层级）/ concept（语义）/ relations（**reference 前置依赖链**，供演化模式溯源）/ importance（**curriculum_weight 课标权重 1~5 + exam_frequency 考频**——§4.5 父节点聚合的权重输入已就绪）。（knowledge-base/项目独有/知识图谱结构规范.md）
- **WWH 五要素判定**（决策 028）：定义/表示/性质/操作/关系 → 建节点；推导链/思想/来源/应用实例 → 不建（思想 16/来源 4/应用 41 归档 knowledge_extras）。
- **官方 vs 自定义双集合**：官方 knowledge_nodes（上线后仅官方可改）；AI 提炼走 custom_nodes（无 path/父级，标记来源，防丢 K 数据）。**图谱目前只覆盖必修一（第 0 章+第一~五章），必修二~五/选必未建**【待办】。
- **思想方法层**：thinking-cards 数学思维扑克 54 张骨架（外部授权，仅牌名+一句话定义）——参考层，不计 K。
- 三层结构：知识层（计 K）/ 模型层（生成题型结构供 RAG，不计 K，宪法 §4.2 修订）/ 思想方法层（参考输出，不计 K）。

### 学生状态与各维度关系
- 学生掌握度**独立存储**（knowledge_progress：sValue/dValue/mastery/attempts/correctCount），图谱节点本身不存掌握度。
- K 绑定知识地图（加权得分法 S_k/D_k）；A 独立计算（不修改图谱）；T 全局（跨连接）；Q 来源思考路径；S 来源时间序列表现。

### 图谱应用
- 诊断挂载：知识点拆解按清单归一（buildNodeNames 喂全量清单给 LLM）；A 单元定位取 path[2]。
- AI 教练读取面：学生知识状态 + 相关节点 + 五维报告，**不直接读教材**（图谱规范 §六）。

## 六、个性化 AI 教练（v2.0 核心）

### 定位
**个人数据全掌握的 AI 助教**：v1.0 积累的诊断画像、掌握度、题型轨迹、错因、断点——全部成为教练的输入。

### 数据依赖（教练吃什么）
学生知识状态（knowledge_progress）+ 知识节点（含 relations/path/importance）+ 五维报告 + 题型轨迹/演化记录。**教练价值 = 个人数据资产**，不是通用大模型问答。

### 对话能力缺口（为什么 T/Q/S 暂缓）
产品形态为"拍照单向"，缺对话采集能力。依赖对话的机制全部后置到 AI 教练模块（决策 026）：
- **Q 思维链采集**（宪法 §7/M6）：高价值题（做错/过程复杂/关键节点）弹窗"你是怎么想的"→ LLM 按 Q1~Q5 评分；频率自适应 base_prob×(1−Q)；Q5 下次同类题验证。
- **S 回溯自报**（宪法 §8/M7）：S1~S4 失常自报（计算/时间/审题/步骤）+ S5/S6 状态自评。
- **T 深层结构引导**（宪法 §6/M6 后置）：r 需"学生说出为什么跨单元能连"——多轮追问。
- **AI 教练对话原型**：Dify 原型候选（决策 022），工具包复用（诊断引擎 + AI 教练共用）。
- 现状：小程序"AI 教练"tab 与首页"AI 助手"均为占位入口。

### 形态规划
弹窗采集（轻）→ 单题追问（中）→ 完整对话私教（v2.0）逐步升级；T/Q/S 的工程化随对话能力一起落地。

## 七、思维训练场（v3.0）

- **不内置题库**；应试化落地，专练思维。三方向：
  - **广度 = 联想能力**（已定）：头脑风暴模式——学生 + AI 共创解题方法 → 提炼规则成「方法卡片」→ 收录进**个人知识图谱**。
  - **深度 / 熟练度**：占位。
  - **正确性校验**：AI（L1~L7 能判）+ 学生共同检验。
- **雏形 = 复盘功能**（现在可做）：AI 不解题，与学生一起复盘思路 → 跨单元联想引导 → 方法提炼。

## 八、数据资产与自增强闭环

- RAG（轻量自建）：判定记录带题型三层 pattern（domain/pattern/variant）+ 文本 embedding 写入 mastery_logs → 检索时 cosine top-5 → 注入判定上下文（自增强）。
- 报告入库（自增强存储）：报告与判定记录沉淀为历史，随用随增强。
- mastery_logs 双用途：K 变更趋势（weighted_score_v1）+ RAG 检索源（diagnose_v1）——**两类记录共用一个集合，schema 不同**【需审视】。

## 十、贯穿原则

1. **宪法最高权威**：文档没有的不引入或先补文档（决策 025）；宪法修订只追加标注、不篡改原文（决策 016）。
2. **确定性计算**：AI 只填参数，公式由硬代码算（决策 014）。
3. **信号独占**（宪法 §9）：各维度独占信号源；工程上同一次 LLM 判定产生的字段天然相关——理论理想与实现的已知妥协。
4. **节点化 + 逐节点验收**【讨论中】：巨石一步生成 → 职责单一节点 → 每节点单独测输出。
5. **审查 skill**（2026-09 决定，短期不做）：每个新功能落地前先设计审查/验收 skill。
