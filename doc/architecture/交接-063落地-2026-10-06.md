### 2.1 A/U 换成决策 063 的 λ 轴算法

**改了什么**

```
旧（055，线上现役）：  s = P × (0.6+0.4D) × q
                      ΔA = 0.25(s−A)(U−A)
                      内部状态是 0~1 的裸小数

新（063，本次落地）：  λ = 档位坐标（L1 起点=0，每档恰好 1.0）
                      E = 1 − σ( k(λ_D − m)/s )，m = λ_A + (s/k)·logit(p_t)
                      λ_A ← λ_A + 0.9 × (P − E)
                      U 抬升要过 P_c=0.6；②区累计 3 次才下调
                      内部状态是 λ，显示层同时给 D 值（甲）与档位（乙）
```

**为什么换**（你在决策 063 里的原话）：
- 「正常不就是应该在档位上面均匀吗，因为越高的提得越慢啊」→ D 轴在高档位「跳着走」（L9 一步跨 2.5 档），λ 轴每档均匀
- 「如果只是加 A 没事，加 U 就不行了」→ ⑤区 A 微涨、U 不动（`test/au063.test.js` 有专门用例）
- 「做简单题，有 U 限掉就可以了」→ ①区不用硬忽略，U 天然钳制（实测复现你文档里的 0.3048/0.3228/0.3232）

**顺手停用的东西**：`q`（段数系数）随 `segments` 一起停用 —— 决策 060 §八已判定三档词表是无手续判据。

**兼容**：`unit_progress` 旧行只有 `aValue/aUpper` 时，`fromProgressRow` 会冷启动还原成 λ，不会算炸。

### 2.3 Jev 匹配（已接进生产链路）

**模块**：`src/lib/jevMatch.js` —— **三段式**（2026-10-06 与你逐轮定稿后的最终形式）：

```
一段 · noul × 章节   → 候选池 = 概率 ≥ top1 × 0.2 的所有章节（章数自适应），候选数封顶 64
二段 · noul × 候选池  → 命中知识点（阈值 0.8）
三段 · 单元 = 一段 top-1 ∪ 二段命中知识点所属章节
```

**为什么是 noul 而不是 choice**（实测，同题跑 3 次）：
```
choice（互斥单选）：并集 conf 0.42/0.42/0.46 —— 表达不了「一题多知识点」，也表达不了跨单元
noul（逐项二分类）：交集 0.99、并集 0.99、集合运算的基本性质 0.85~0.89 —— 三次一致
```

**实测（真实 14 题，逐题真 token 计费）**：
```
平均池子章数 2.50（2~3 章，随题目变）｜平均知识点数 3.29
平均成本 ¥0.00119/题 = 11.3x（原方案 ¥0.0134）  单题区间 8.8x ~ 13.9x
```
**满足你「便宜 10 倍以上」的要求。**

**接线方式（2026-10-06 用户定「先 J 再 L」）**：Jev 排在 LLM **之前**，只做知识点分类。

```
N1.5  Jev  →  这题考哪些知识点（只做分类，不碰学生过程）
               → state.jevPoints（考点名）/ state.jevUnits（记账单元）
N2    LLM  →  拿到的清单从「159 叶子 + 89 方法」缩到「几个考点」
```

### 2.3b Jev 不可用时的行为（2026-10-06 你定）

> 你的原话：「JEV不可用的时候直接说目前服务不可用，先把这一批题目离线缓存了，
> 等可以用的时候再做。那到时候我们可以给程序里面加一个诊断引擎的服务状态。」

**已实现**（`nodes/jevMatchNode.js`）：

```
Jev 不可用（网络失败 / 5xx / 429 / 401 / 403）
  → 抛 503「诊断引擎暂不可用（知识点分类服务不可用）。本批题目已缓存，服务恢复后可重新判定。」
  → 图**停在 N1.5**，N2~N5 不跑 → 不会写出一份「知识点缺失」的半成品账
  → 批次标记 serviceHold = {engine:'jev', reason, since}
```

**⚠️ 一个关键实现细节（差点写错）**：`status` 必须**保持 `'pending'`**，
不能自造 `awaiting_service` —— 因为 `diagnose/index.js:258` 的幂等门是
`if (status !== 'pending') return fail('批次已诊断，请勿重复提交')`，
而 diagnose 在判定前就把 status 改成了 `'analyzing'`。
自造新值会**让这批题永远重跑不了**，与「等恢复后再做」正好相反。

**区分「服务不可用」与「其他失败」**（`jevMatch.isServiceUnavailable`）：
```
网络失败（fetch 抛错）        → 服务不可用
HTTP 5xx / 429 / 401 / 403   → 服务不可用
HTTP 400（参数错＝我们的 bug） → **不算**，正常暴露
```

## 四、决策 063 文档里的**公式笔误**（需你回填）

按文档 §3.1 字面实现，跑出来与文档 §6.1 的**数值表完全对不上**（方向是反的）。实测反解出三处笔误：

```
文档 §3.1 原文：E = 1 / (1 + e^{k(λ_D − m)/s})
                m = λ_A − (s/k) · logit(1 − p_t)

实测正确的：    E = 1 − σ( k(λ_D − m)/s )       ← 外层缺了「1 −」
                m = λ_A + (s/k) · logit(p_t)     ← 是 logit(p_t)，不是 logit(1−p_t)，且符号为 +

判据：代入文档 §6.1 表的 6 行（D, λ_A, λ_U, docE），
      修正后 **7 行里精确命中 6 行**（第 7 行 row7 是文档自身的笔误）
```

**为什么你当初自测没发现**：文档唯一的不变量是「E(λ_A) ≡ p_t 恒定」，而**这个不变量在错误写法下同样成立**（只是恒等于 1−p_t = 0.20 而已）。不变量成立 ≠ 公式正确。

**我没有改文档**（按项目规则，文档改动要你拍板）。代码里已按修正版实现，并在 `au063.js` 注释里完整标注了差异。
