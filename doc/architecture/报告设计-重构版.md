## 〇、一句话

**报告的主体不是「错误模式」，是「这批题让我看清了什么」。**

```
V3：首屏(正确率) → 主模式四段式 → 次模式
新版：事实 → 单元情况 → 该改的 → 想一想 → 一个动作 → 逐题 → 纵向
```

---

## 一、先定一条地基：**报告不能依赖官方分**

### 实测

```
61 道题 → 只有 23 道有 official* 字段（38%）
且这 23 道里，满分 0 道（做对的题抓取漏了）
```

### 用户定调（2026-10-05）

> **「做对的题，其实有官方分，只是那个接口没抓到而已。
> 然后，大部分场景其实是没有官方分的，就比如说我们学生自己做题的时候」**

### 结论：两条数据来源，报告必须同时支持

| 来源 | 什么时候有 | 覆盖 | 可信度 |
|---|---|---|---|
| **官方分**（智学网） | 考试后同步 | 少数 | 最高（阅卷给的） |
| **系统判定**（AI） | 每次拍照都有 | 全部 | 中（有抖动） |

**代码里已经有这个机制**（`assemble.js`）：

```js
// 三态：官方有判定就用官方（零抖动），否则用 AI 过程分 P 推
status: ['对','半对','错'].includes(q.officialStatus)
        ? q.officialStatus
        : (q.processScore >= 1 ? '对' : (q.processScore > 0 ? '半对' : '错')),
scoreSource: officialTotal > 0 ? 'official' : 'ai',   // ← 已有
```

**报告设计必须尊重这条**：
- **有官方分** → 用官方分（更硬）
- **没有官方分** → 用系统判定，**且报告里不能假装它是官方分**

## 二、报告结构

### ① 这批的事实（只摆，不判）

```
19 道题：做了 10 道，9 道没作答
本批判定来源：系统判定（无官方分）

数列 · 3 道
  都在"确定范围"这一步开始偏 —— 其中 2 道此处有涂改
  3 道都没走到最后

导数 · 4 道
  都走到最后，没有涂改
```

**设计要点：**
- **不出现正确率数字**（V3 的 `dataAnchor` 违反了自己第 10 条原则）
- **明确标注判定来源**（系统判定 / 官方分）
- **"同一性"才是价值**：「3 道都在同一步」是他自己看不出来的

### ② 单元情况（A 的展示位）

```
数列单元
  常考的：确定范围 / 化简变形 / 求和
  你的表现：确定范围 2/5，化简变形 5/5

导数单元
  常考的：分类讨论 / 求导 / 验证
  你的表现：分类讨论 0/3
```

**设计要点：**
- **按单元组织**（A 是单元级，`path[2]`）
- **给"动作维度的表现"，不给分数**（"2/5"是次数，不是能力值）
- **不跨单元比较**（单元难度不同，比了不公平）

### ③ 该改的（差异 + 凭什么）

```
「确定范围」这个动作，你这批 5 道里有 3 道没做。

凭什么：
  · 另 2 道同类题你做了这个动作，都走到最后
  · 没做的 3 道里，有 2 道在这个位置有涂改
    （笔迹：你在这一步划掉过重写）

                          [ 我不服 › ]
```

**设计要点：**
- **必须附「凭什么」** —— 三种依据至少一种：引题目条件 / 引笔迹事实 / 引官方分
- **三种都拿不出就不报**（宁可只报 2 条真的）
- **「我不服」是地基** —— 能反驳"这步扣不扣分"

### ④ 想一想（问题 + 参考答案折叠）

```
想一想：你涂改的那一刻，是觉得哪里不对？
        那 2 道没涂改的，和这 3 道，差别在哪？

        （想不出来再看 ›）
        ┌────────────────────────────────┐
        │ "我写到这发现 x 得大于 0，但想着   │
        │  先把式子化简完再说，结果后面就    │
        │  不对劲了。"                     │
        │                                │
        │ "那 2 道一开始就写了范围，所以     │
        │  中间没返工。"                   │
        └────────────────────────────────┘
```

**设计要点：**
- **问题要问在他答不出的地方** —— 高分段能秒答的问题没价值
  - ❌"你涂改时觉得哪里不对"（他答得出）
  - ✅"那 2 道没涂改的和这 3 道，差别在哪"（跨题比较，他做不到）
- **参考答案默认折叠**，示范的是"怎么自我观察"，不是标准答案
- **参考答案用第一人称**（学生视角自述）

### ⑤ 一个动作 + 框架

```
一个动作：
  把这道题讲给一个同学听，讲到他听懂为止。

下次可以自己过一遍：
  摆过程 → 找从哪开始不对 → 想为什么 → 问自己下次在哪停一下
```

**设计要点：**
- **动作要宽泛**（换了题型依然成立）—— "讲给同学听"训练的是表达能力，不是这道题
- **框架是可撤的脚手架** —— 让产品能被丢掉

### ⑥ 逐题（材料层）

```
第 3 题
  题目：…
  你的过程：［照片］
  这一步：确定范围 未做
  凭什么：这个动作在笔迹里找不到
                              [ 我不服 › ]
```

**设计要点：**
- **逐题是"反驳的落点"**，不是"讲这道题"（他会做，不需要讲）
- 每条聚合结论都要能点回具体某题

### ⑦ 纵向（能力变化）

```
数列递推求通项 + 错位相减       5 道题

      确定范围  化简  求和  验证
9/04 │    ✗      ✓    ✓    ✓
9/11 │    ✗      ✓    ✓    ✗
9/18 │    ✓      ✓    ✓    ✗
9/25 │    ✓      ✓    ✓    ✓
              ↑ 这一列从 ✗✗ 变成 ✓✓
```

**设计要点：**
- **不画"走完率"**（我造的怪词），画**动作的 ✓✗ 序列**
- **必须有样本量标注**（5 道题）——否则 1 道也画线
- **答案变化 = 某个动作从 ✗ 变 ✓**

## 四、V3 与新版对照

| 维度 | V3 | 新版 |
|---|---|---|
| **主轴** | 错误模式 | **三件事：事实 → 该改的 → 怎么补** |
| **组织单位** | 错误模式（跨单元） | **单元**（A 是单元级） |
| **首屏** | `dataAnchor` 给正确率 | **纸面事实，无数字** |
| **主体结构** | 四段式（breakpoint/rootcause/hook/check） | **问题 + 参考动作 + 框架** |
| **历史** | `vectorSearch` 相似题 | **题型纵向（时间序列）** |
| **依据** | `segments` + 工具检索 | **笔迹事实（算子/涂改）+ 官方分（有则用）** |
| **数值** | 有 `{rate}%`（违反自己的原则 10） | **禁止所有数值型能力指标** |
| **反驳** | 无「我不服」 | **「我不服」能反驳扣不扣分** |
| **判定来源** | 未标注 | **明确标注"系统判定/官方分"** |
| **动作** | 有按钮/打卡（"我讲懂了"） | **一个动作，不设通关条件** |

## 五、判定来源的处理（用户 2026-10-05 补充后的设计）

**三种情况，三种措辞：**

| 数据情况 | 报告怎么写 | 示例 |
|---|---|---|
| **有官方分** | 直接用官方 | "这道题拿 6/15" |
| **无官方分，有过程** | 用系统判定，**标注来源** | "这道题的过程看下来，确定范围这一步没做" |
| **无官方分，无过程** | 只出事实 | "这道题没有作答" |

**关键：报告里不能把"系统判定"说成"阅卷结果"。**

**这也解释了为什么"算子/笔迹事实"比分数更重要：**
```
有官方分时：分数 + 笔迹事实（互相印证）
无官方分时：只有笔迹事实（唯一可靠的东西）

→ 笔迹事实是两种情况下都有的共同基础
→ 所以报告应该以【笔迹事实】为主轴，官方分为辅
```
