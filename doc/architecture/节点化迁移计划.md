## 一、要解决的问题（为什么改）

现在的 `judgeOne`（判定）一个文件约 800 行，把下面 9 件事**一口气连着做完**：

1. 查这个学生以前做过的最像的 5 道题（翻旧账）
2. （可选）对着裁剪图精读学生笔迹
3. 让 AI 一次性判断这道题（难度/作答分/逐知识点打分/卡壳点/错因…）
4. 程序检查并整理 AI 的输出（钳制、归一、空白的防毒处理）
5. 把判定结果写进题目库
6. 更新学生的掌握档案（知识 K / 应用 A）
7. 把这道题记进"旧题库"（向量化，供以后翻旧账）
8. 更新本批次的进度（判完最后一道 → 整个批次完成）
9. （复核时）学生改知识点 → 掌握度迁移

**坏处**：
- 像一个环节坏掉就整条线报错的流水线，说不清错在哪一步；
- AI 输出不稳时，无法区分是"AI 判断那步"的问题还是"程序整理那步"的问题（都糊在一起）；
- 想单独改进某一小步（比如让 K 拆解更准），必须动整个 800 行的大文件。

## 二、目标长什么样（小盒子 + 传送带）

```
    ┌─────────────────────────────────────────┐
    │  云函数入口：只负责收请求、叫图开始跑      │   ← 不做业务
    └───────────────────┬─────────────────────┘
                        │
    ┌───────────────────▼─────────────────────┐
    │  LangGraph 图：把盒子按顺序/条件串起来     │
    │  负责"下一步走哪个盒子"、"走到一半存档"     │
    └───────────────────┬─────────────────────┘
                        │ 依次调用
    ┌───────────────────▼─────────────────────┐
    │  小盒子们：每个盒子做一件事               │
    │  输入一份数据 → 输出一份数据              │
    │  需要数据库/调用 AI 时，从外部"递给"它     │  ← 关键
    └─────────────────────────────────────────┘
```

**每个盒子的规矩**（这是能"单独测试"的根本）：
- 它**不在自己肚子里创建**数据库连接、AI 密钥这些（现在的大文件是全局变量直接用的，这是测试不了的根源）；需要什么，从外面递进来。
- 你可以在**不跑整个程序**的情况下，单独喂它一份假输入，看它输出对不对。

**盒子里没有 AI 的（纯程序）**最好先切——例如"检查整理 AI 输出"那段：不用联网、不用数据库，喂什么吐什么，测试最干净。

## 三、怎么安全地换（不惊动学生）

铁律：**线上老程序一路不动**，直到新盒子串被证明和它一模一样。

1. 在**新地方**（新云函数 `graphEngine`）搭盒子；
2. 让新老两边**同时处理同一批题**，逐字段对比落库结果（叫"影子对比"）；
3. **两边结果 0 差异、连续稳定 ≥1 周** → 才把线上切换到新盒子；
4. 老代码保留一段时间，出问题可秒回退。

> 一句话类比：新员工先跟老员工对答案，全对才让新员工独立上岗。

## 四、分期推进（每期一个可验收的里程碑，天然适合一次一个会话）

| 期 | 做什么 | 怎么算完成 | 碰不碰线上 |
|---|---|---|---|
| **P0** | 搭骨架：新云函数目录 + 测试脚手架；**先抽 1 个纯代码盒子**（"检查整理 AI 输出"那段）+ 给它写一批测试 | 该盒子的测试全过 | 不碰 |

| **P2** | 把第 3 步"AI 一口气判断"按关卡拆成小步（想解决 AI 不稳） | 用现有评测集对比：新版比旧版 schema 通过率更高 | 影子验证 |
| **P3** | 认题域（拍照转录/拆题/建题）同样盒子化 | 影子对比 | 影子验证 |
| **P4** | 报告域盒子化 + 异议申诉用上"存档续跑" | 报告对比 + 中断续跑演示 | 影子验证 |
| **P5** | 复盘（Q/S，v1.5 挂起）作为新盒子插进链条 | — | 未来 |

**第一步具体做什么（P0）**：从 `judgeOne/index.js` 里把"AI 原始输出 → clamp 钳制 + 空白防毒 + 错型/错层回退 + 题型 pattern 整理"这一整段（代码约 621–657 行）抽成独立函数，放新云函数，然后为它写测试：喂各种"AI 乱输出"的假数据，断言输出都被正确整理/钳住。做完你就直观理解"可单独测试的盒子"是什么感觉。

## 五、术语对照（写代码 / 读老代码时会遇到）

| 大白话 | 文档/代码里叫 | 一句话 |
|---|---|---|
| 小盒子 | 节点（node） | 做一件事、输入输出明确的函数 |
| 传送带 | LangGraph 图 / StateGraph | 决定下一步走哪个盒子、维护中间状态 |
| 每个盒子的输入输出规矩 | zod schema 契约 | 类型声明：进来几个字段、出去几个字段、各什么类型 |
| 盒子需要的东西从外面递进来 | 依赖注入（注入 db / llm / embed） | 不在盒子内部偷偷建连接，测试才能替换成假的 |
| 检查整理 AI 输出那个盒子 | N3 校验归一节点 | 见判定域节点表 |
| 新老对答案 | 影子 A/B（shadow mode） | 同时跑、比 diff、0 差异才切 |
| 存档续跑 | checkpoint（云端） | 判到第 5 题挂，从第 5 题续，不重跑 1–4 |
| 老程序 | judgeOne / reportService / diagnose（云函数） | 现在线上跑的，改造期间不动 |
| 新地方 | graphEngine（新云函数） | 搭盒子的地方，线上暂不引用 |
