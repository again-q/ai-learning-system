# 判定节点设计 — 拆分 AI 判定（D6）

> 状态：**设计初稿，待拍板**（2026-09-25，SOP 第①步·设计先行）· 待决 6 项见 §7
> 上游：D5（影子对比 4 层全 0 差异、已切到 `graphEngine`）｜D4（单题判定图 N0–N7，N2 是「一口气大 JSON」）
> 定位：把 N2 拆成两段 —— **段 A 认题（题侧）** 与 **段 B 看过程（学生侧）**；并用固定评测集证明「新版更稳」

## 0. 大白话

现在 AI 一次要干四件事、吐 20 个字段：感受难度 → 判档+判对错 → 题型归类 → 过程分段。
打个比方：让一个医生**一次**同时「看片子 + 问诊 + 下诊断 + 写病历」，他容易手抖；
改成两步就好很多 —— **第一步只看片子**（这题本身多难、考什么、答案是什么），
**第二步带着片子看病人**（这个学生写得怎么样、错在哪）。

**关键点**：第一步的信息（题多难、答案是什么）**和学生的作答无关**，所以它天然是「题目属性」；
第二步才是「学生属性」。现在把两类混在一次生成里，模型会互相污染 —— 证据见下。

## 0.5 大白话：原本 / 现在 到底差在哪（2026-09-25 实验后补）

**原本（= 线上此刻正在跑的）**：一位老师，**把题目和学生的答卷一起摊在桌上**，一次看完，顺手写下四件事 —— 这题多难、考什么、学生答得怎么样、过程怎么分段。

**现在（= 我这次试的「两段」）**：把题目复印成两份，让**两个老师分两次**干：

| | 手里有什么 | 只负责写什么 |
|---|---|---|
| 老师 A（认题） | **只有题目**（学生的答卷被藏起来） | 这题多难、考什么、标准答案是什么 |
| 老师 B（看过程） | 题目 + **标准答案 + 标准解法** + 学生的答卷 | 学生答得怎么样、错在哪、过程怎么分段 |

**一字没动的部分**（所以这次实验很干净，只动了一个变量）：判难度的标尺（L1~L11）、所有约束文字、模型、温度、输出字段清单。

**为什么一动就差**（两条，都是实测出来的）：

1. **老师 B 变成了「批改者」**：手里握着标准答案，就忍不住一条条对 —— 而学生写的是手写简写、跳步、口语，本来就不是标准格式，于是被挑出「这步没写、结论不对」。实测：**完整做对的题里 33% 被判成「结果错」**（原本只有 7%）。
2. **老师 A 变成了「盲判难度」**：原本判难度是「看着学生的卷子，模拟自己是个学生会卡在哪一步」，学生的答卷一藏起来，这把尺就没了参照。实测：A 给出的难度档位只有 **40%** 和原本一致。

> 一句话：**「同时看题又看人」和「先看题、再看人」不是同一件事** —— 前者模型是在做整体判断，后者是在做批改。

## 2. 两段怎么切（推荐口径）

| | **段 A · 认题（题侧）** | **段 B · 看过程（学生侧）** |
|---|---|---|
| 输入 | **只给题干**（明确不给作答痕迹） | 题干 + A 产出的 `correctAnswer`/`referenceProcess` + 学生痕迹 |
| 输出 | `questionType`、`correctAnswer`、`referenceProcess`、`questionCategory`、`level`+`D`、`knowledgeNodeName`、`knowledgeUsage`、`pattern`、`isRecallQuestion`、`isOutOfSyllabus` | `P`、`errorType`、`errorLevel`、`errorAttribution`、`errorDimension`、`eta`（钳制后）、`segments`、`breakpoint`、`processAvailable`、`fiveDim` |
| 为什么这么分 | 这些是**题目固有属性**，与学生写没写无关 → 可复用、可缓存 | 这些**只有看到作答才能判** |
| 有争议的 | `fiveDim` 的 K（知识储备）/A（分析推理）/T（迁移）——按定义是「学生能力表现」，我倾向归 B | 待拍板 §7-1 |

## 3. 图的形状

```
START → N0 取题 → N1 翻旧账 → **N2a 认题** → **N2b 看过程** → N3 整理 → N4 写库 → N5 掌握度 → N6 RAG → N7 批次
```

- **必须串行**：B 段要用 A 段产出的标准答案与参考过程（否则 B 只能自己再算一遍答案，等于把「算答案」做两遍）
- **N2a 可按题缓存**（题干不变 → 题侧属性不变）：收益是省一半调用 + 题侧天然稳定；与决策 037「不作题库」的边界待拍板 §7-3

## 4. 同步落地的两项（审计 P2/P3，改的就是判定数值本身）

1. **η 钳制**：解答题钳到标尺区间 `0.4~1.0`，选填题恒 `null`（现在原样透传）
2. **043 判据同步**：把「三问」（① 出现了吗 → 没出现 `noEvidence`；② 本身做对吗；③ 本身对但完整吗）写进 B 段 prompt，使 `knowledgeUsage` 的 `P_kp` 三档与 D3 环节判定节点**同一口径**

## 5. 评测方案（D6 的判据）

> 💰 **成本纪律（2026-09-25 用户明确：「下次测试不要这么多，我没钱这么造，而且时间还慢」）**：默认 **6 例 × 2 轮 + 并发 6**（脚本 `--limit` / `--rounds` / `--concurrency` 可调）；**大跑（>10 例或 >3 轮）先问用户**；raw 逐轮缓存，重跑只补缺。

- **语料**：`output/golden/dataset-v2.json`（436 题）的题面 + L2 合成痕迹（`scripts/synth-traces.mjs` 已跑通，4 角色 `correct/wrong/blank/alt`）。**先扩到 20 题 × 4 角色 = 80 条**（当前只有 6 条）
- **对比**：同一批语料，**旧（一口气）vs 新（两段）各跑 3 轮**
- **指标**
  - 题侧：`level` 档位一致率、`D` 抖动中位/最大、知识点名一致率、题型一致率
  - 学生侧：`P` 一致率、三态（对/半对/错）一致率、`errorType`/`errorLevel` 一致率、`segments`/`breakpoint` 一致率
- **通过线**（待拍板 §7-4）：建议 **三态一致率 ≥ 90% 且 level 一致率 ≥ 95%，且两项都高于旧版**
- **成本**：80 条 × 3 轮 ×（旧 1 次 / 新 2 次）≈ **720 次调用**，估几十元（待你确认上限 §7-5）

### 5.1 旧版基线（2026-09-25 实测，`scripts/eval-stability.mjs --label=old --rounds=3`）

语料 = `output/golden/traces/traces-v1.json` 合成痕迹（11 题 × 4 角色，剔除 `quality` 后 38 例）；每例同输入跑 3 轮。

| 指标 | 旧版（一口气） | 通过线（§7-4 建议） | 达标？ |
|---|---|---|---|
| 三态（对/半对/错）一致率 | **91.4%** | ≥ 90% | ✅ 刚过 |
| level 档位一致率 | **85.7%** | ≥ 95% | ❌ |
| errorType 一致率 | 88.6% | — | — |
| errorLevel 一致率 | **77.1%** | — | ❌ 明显不稳 |
| 知识点名一致率 | **60.0%** | ≥ 90% | ❌ |
| 题型 pattern 一致率 | **22.9%** | — | ❌ 基本每次都不一样 |
| D 抖动（中位 / 最大） | 0 / 0.15 | 中位 ≤ 0.05 | ✅ |
| P 抖动（中位 / 最大） | 0 / 0.5 | — | 🟡 中位 0、极端 0.5 |
| 不稳定用例（level 或三态翻过） | **8 / 35 = 23%** | — | ❌ |

**读法（重要）**：
- 稳定的是**数值**（D/P 中位抖动 0），不稳的是**类别**（level 档位、知识点名、题型）→ 与审计 P1 的观察一致：细粒度数值反而不抖，**分类判断在抖**
- **题型 pattern 一致率 22.9%** 是最大黑洞：同一道题 3 轮给出 3 个不同题型描述——而 pattern 是 RAG 检索主键（决策 026），主键不稳 = 检索不稳
- **3 例解析失败**（`Unexpected non-whitespace character after JSON` / `Expected property name`）说明旧版会产出坏 JSON；我们的括号配平解析（线上同款）也救不回来 → 这类题线上直接走「判定失败请重试」
- 结论：**旧版有明确的、可量化的改进空间**，D6 的两段拆法有了可对照的靶子（要在这 6 个指标上分别对比，而不是只看一个总数）

**基线口径声明**：本地不注入图谱节点清单与 RAG 历史（线上会注入）；prompt 与模型参数与线上逐字一致。结果文件 `output/golden/results/stability-old.{json,md}`（raw 逐轮落盘，可复查）。

| 三态一致率 | 91.4% | 82.9% | ⬇️ |

| 题型 pattern 一致率 | 22.9% | **5.7%** | ⬇️⬇️ |
| D 抖动（中位） | 0 | 0.03 | ⬆️ |
| 不稳定用例 | 8 / 35 | **18 / 35** | ⬆️ |

**结论：朴素的「拆成两段」不能让判定更稳，反而全面变差 —— D6 第一版方案被否决**（按决策 016 体例，否决理由留档）。

可能原因（按可能性排序，都是**可廉价证伪**的假设）：
1. **A 段失去了作答上下文**：决策 023 的判档方式是「学生视角体验」，线上是**看到真实痕迹**时模拟体验；A 段只看题干 → 难度判定失去锚（level 一致率腰斩最像这一条）
2. **A 段 prompt 里残留越界指令**：「（第二步）同时判定对错/作答质量」——我为保逐字派生没删，于是它被要求判作答却拿不到作答
3. **B 段可能把「标准答案」当成学生的答案**（把 `correctAnswer` 明文给了 B）
4. 两段各自 0.2 温度的抖动叠加到同一结果上

**下一步（严格按上面的成本纪律）**：假设 2、3 可以**零调用成本**修（改 prompt）——A 段删掉「同时判定对错/作答质量」并写明「你没有作答信息」；B 段加一句「【正确答案】是标准答案，不是学生的答案」。然后 **6 例 × 2 轮（约 24 次调用，并发下 1–2 分钟）** 看 level 一致率有没有回升：
- 回升明显 → 继续沿拆段方向迭代
- 不回升 → 主因是假设 1（拆段与决策 023 的判档方式冲突），需要换方案（例如只把「过程/归因」拆出去、难度判定仍与痕迹同一次生成）

### 5.5 「候选编号勾选」实验：一致性与正确性**双升**（2026-09-25，6 例 × 2 轮 = 12 调用 / 4.2 秒）

**改动只有一个变量**：清单从「名字用、连接」改成「**带编号**」（`1.并集 2.补集 …`），并要求模型额外输出 `knowledgeNodeIds` / `knowledgeUsageIds`；名字与知识点名由**代码按编号回填**，模型不得改写、不得造近义词。prompt 其余部分一字未动。

| 指标 | 基线（普通清单） | **编号勾选** |
|---|---|---|
| 名字命中云端清单 | 83.3% | **100%**（⚠️ 由代码回填保证，**不算成绩**） |
| 同题多轮名字一致 | 4 / 6 | **5 / 6** |
| level 档位一致率 | 83.3% | **100%** |
| 三态一致率 | 100% | 100% |
| **与历史落库值一致率** | **33.3%**（4/12） | **75.0%**（9/12） |
| 模型给出的编号有效性 | — | **37 / 37 = 100%** |

**真正的证据是最后一行**：命中率 100% 是「代码按编号回填」的必然结果，不能当成绩；能说明问题的是**与历史落库值的一致率从 33% 提到 75%**。逐例更直观——基线把「并集」题判成「集合相等」「求并集交集的方法」，编号版直接给出「并集」「交集」。

**剩余问题**：仍有 1/6 例第二轮选了明显错的节点（一道集合题给了「一元二次方程的解法」）→ 说明编号**只能防「漂移」，不能防「选错」**。

⚠️ **这个结论有前提（2026-09-25 用户提醒后核实）**：上面「与历史落库值一致率 33%→75%」**混着图谱质量的影响**——云端图谱 271 节点里 `type=method` 有 **89 个（33%）**，按决策 028 的 WWH 规则**方法/套路类本该不建**；且实测同一内容挂多个节点（并集/集合的并集；集合的子集计数/集合的子集与元素计数/子集）。模型在冗余选项间摇摆**不全是漂移，也可能是图谱给了两个都说得通的答案**。→ **修图谱之前，任何「知识点」相关指标都不能用来比较模型版本。**

⚠️ **样本量警示**：N=6 是小样，**别当定论**；要下结论建议 12 例 × 2 轮（约 48 次调用，含基线共约 48 次）。
### 5.4 harness 失真修复 + 「收窄输出空间」方向的第一组证据（2026-09-25）

**发现两处 harness 失真**（都会让基线不可比）：
1. **没注入【知识点节点清单】**——线上 `judgeAI.js` 会注入（`kg.buildNodeNames()`，取自云端 `knowledge_nodes` 271 节点 / 270 名字 / 约 2943 字）。→ 已修：导出云端清单 `output/golden/nodes-dump.json`（gitignore），harness 按线上同位置注入。
2. **语料与图谱覆盖不对齐**——合成痕迹那批跑的是 2010 高考真题（全 syllabus），而图谱**只覆盖必修一**（数列/几何概型 0 命中）→ 模型**根本不可能**从清单里挑，测出来的「清单命中率 0%」是覆盖问题，**不是模型不听话**。→ 已加 `--source=db`：用线上真题（多为必修一）当代替语料。

**对齐语料的小样 A/B**（6 道真题 × 2 轮 = 12 次调用，**4.7 秒**）：

| 指标 | 结果 |
|---|---|
| `knowledgeNodeName` 命中清单 | **83.3%**（10/12） |
| `knowledgeUsage` 命中清单 | **97.1%**（34/35） |
| 同题多轮名字一致 | 4 / 6 |
| level 一致率 / 三态一致率 | 83.3% / **100%** |
| D 抖动（中位） | 0 |

**两条结论**：
1. **清单约束是有效的**（命中 83%/97%）→ 说明「收窄输出空间」这个方向有实测支撑；同时**旧的 60% 名字一致率是在没注入清单的条件下测的，不能代表线上**（后续对比要用新 harness）
2. **剩下的不稳定非常具体**：模型在「清单里有近义名」时会**自己造一个**——例如输出「集合的运算」，而清单里是「集合运算的基本性质」。**这正是「让模型输出编号而不是名字」能消灭的那一类差异**（D2 拆考点节点已用同一模式：候选 → 编号勾选）

**下一步（仍按成本纪律：6 例 × 2 轮 ≈ 12–24 次调用，约 10 秒）**：把知识点与题型改成**候选编号勾选**，用 `eval-stability.mjs` 同口径对比「名字命中率 / 同题一致率」。

| 假设「合并丢信息」 | 考点合并命中率 **100%** | ❌ 实现层没问题 |
| **独立发现（与拆段无关）** | 题型 pattern 一致率 **22.9% → 5.7%**；样例 3 轮给出 3 个不同措辞 | ⚠️ pattern 是**自由文本**，天然不可复现——而它是 **RAG 检索主键（决策 026）** → **「检索不稳」的真凶在这里** |

**结论**：朴素拆段同时触发两个**结构性**副作用——① 学生侧变成「批改者视角」（判过严）② 题侧判档失去锚（决策 023 冲突）。**不是参数没调好，而是这条路线与既有设计冲突**。按决策 016 体例：**方案「一口气 → 朴素两段」已否决并留档理由**。

**接下来该做的（按性价比排序，都比再跑一轮全量便宜）**：
1. **修 pattern 可复现性**（证据最硬，且与拆段无关）：把「题型描述」从自由文本改成**先选候选集 / 后生成**，或规范化成可复现结构 —— 它是 RAG 主键，收益直接落在检索稳定上
2. **η 钳制**（审计 P2）：纯程序改动，**零 AI 成本**
3. **043 判据同步**（审计 P3）：改 prompt，用 **6 例 × 2 轮（≈24 次调用）** 小样验证
4. 拆段若要复活，必须**重新划界**：例如「难度判定仍与痕迹同段，只把过程分段/归因拆出去」——但先做 1–3 更划算

**成本台账**：本轮 D6 共约 **380 次调用**

## 6. 边界（D6 不做）
