## 0. 大白话

现在 AI 一次要干四件事、吐 20 个字段：感受难度 → 判档+判对错 → 题型归类 → 过程分段。
打个比方：让一个医生**一次**同时「看片子 + 问诊 + 下诊断 + 写病历」，他容易手抖；
改成两步就好很多 —— **第一步只看片子**（这题本身多难、考什么、答案是什么），
**第二步带着片子看病人**（这个学生写得怎么样、错在哪）。

**关键点**：第一步的信息（题多难、答案是什么）**和学生的作答无关**，所以它天然是「题目属性」；
第二步才是「学生属性」。现在把两类混在一次生成里，模型会互相污染 —— 证据见下。

## 1. 要解决的问题（都有实测证据，不是猜）

| 证据 | 内容 | 出处 |
|---|---|---|
| 一口气判不稳 | 同题重跑 `D 0.65→0.62`、`η 0.5→0.6`；本机 55 题重跑 **D 最大抖 0.32、17/55 题难度档位改变** | 审计 P1、D5 抖动带 |
| η 没有区间钳制 | 抖 0.2 正好跨 `0.6 扣分 / 0.7 加分` 悬崖 → 一次判定决定某知识点涨还是跌 | 审计 P2 |
| 两套判据并存 | 决策 043 的「三问」只进了 D3 环节判定节点；**线上整题判定 prompt 里 `noEvidence` 出现 0 次** | 审计 P3 |
| prompt 自己都在打补丁 | 标题就写着「**严禁用作答过程评估难度**」——等于承认一次生成里两类任务会互相污染 | `graphEngine/src/lib/prompts.js` |

## 2. 两段怎么切（推荐口径）

| | **段 A · 认题（题侧）** | **段 B · 看过程（学生侧）** |
|---|---|---|
| 输入 | **只给题干**（明确不给作答痕迹） | 题干 + A 产出的 `correctAnswer`/`referenceProcess` + 学生痕迹 |
| 输出 | `questionType`、`correctAnswer`、`referenceProcess`、`questionCategory`、`level`+`D`、`knowledgeNodeName`、`knowledgeUsage`、`pattern`、`isRecallQuestion`、`isOutOfSyllabus` | `P`、`errorType`、`errorLevel`、`errorAttribution`、`errorDimension`、`eta`（钳制后）、`segments`、`breakpoint`、`processAvailable`、`fiveDim` |
| 为什么这么分 | 这些是**题目固有属性**，与学生写没写无关 → 可复用、可缓存 | 这些**只有看到作答才能判** |
| 有争议的 | `fiveDim` 的 K（知识储备）/A（分析推理）/T（迁移）——按定义是「学生能力表现」，我倾向归 B | 待拍板 §7-1 |

## 3. 图的形状

```
START → N0 取题 → N1 翻旧账 → **N2a 认题** → **N2b 看过程** → N3 整理 → N4 写库 → N5 掌握度 → N6 RAG → N7 批次
```

- **必须串行**：B 段要用 A 段产出的标准答案与参考过程（否则 B 只能自己再算一遍答案，等于把「算答案」做两遍）
- **N2a 可按题缓存**（题干不变 → 题侧属性不变）：收益是省一半调用 + 题侧天然稳定；与决策 037「不作题库」的边界待拍板 §7-3

## 4. 同步落地的两项（审计 P2/P3，改的就是判定数值本身）

1. **η 钳制**：解答题钳到标尺区间 `0.4~1.0`，选填题恒 `null`（现在原样透传）
2. **043 判据同步**：把「三问」（① 出现了吗 → 没出现 `noEvidence`；② 本身做对吗；③ 本身对但完整吗）写进 B 段 prompt，使 `knowledgeUsage` 的 `P_kp` 三档与 D3 环节判定节点**同一口径**

## 5. 评测方案（D6 的判据）

- **语料**：`output/golden/dataset-v2.json`（436 题）的题面 + L2 合成痕迹（`scripts/synth-traces.mjs` 已跑通，4 角色 `correct/wrong/blank/alt`）。**先扩到 20 题 × 4 角色 = 80 条**（当前只有 6 条）
- **对比**：同一批语料，**旧（一口气）vs 新（两段）各跑 3 轮**
- **指标**
  - 题侧：`level` 档位一致率、`D` 抖动中位/最大、知识点名一致率、题型一致率
  - 学生侧：`P` 一致率、三态（对/半对/错）一致率、`errorType`/`errorLevel` 一致率、`segments`/`breakpoint` 一致率
- **通过线**（待拍板 §7-4）：建议 **三态一致率 ≥ 90% 且 level 一致率 ≥ 95%，且两项都高于旧版**
- **成本**：80 条 × 3 轮 ×（旧 1 次 / 新 2 次）≈ **720 次调用**，估几十元（待你确认上限 §7-5）

## 6. 边界（D6 不做）

1. 不动 N0/N1/N3–N7 的壳逻辑（D5 刚验完，改了会白验）
2. 不拆报告域 / 认题域（转录、拆题、建题）→ 那是 D8 / D7
3. 不改模型选型（仍 `deepseek-v4-flash`）」
