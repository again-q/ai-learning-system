## 一、把需求拆成三层（关键：三层来源完全不同）

| 层 | 我们跑功能需要什么 | 公开数据集能满足吗 |
|---|---|---|
| **L1 题面层** | 题面文本 + 标准答案 + 题型 | ✅ 公开很多（高考真题、教材习题） |
| **L2 痕迹层** | **学生作答过程**（转录文本，非照片） | ❌ 几乎不存在 → **必须自建** |
| **L3 标注层** | 期望的考点清单 / P_kp / 对错 | ⚠️ 外部基本没有，自建（D2 拆考点跑 + 人工抽检） |

**核心判断：公开数据集只能白送 L1；L2/L3 是私有数据，公开市场买不到。**

### L2 痕迹层（几乎无公开）
| 数据集 | 内容与规模 | 评价 |
|---|---|---|
| **DrawEduMath**（allenai，NeurIPS'24 Math Reasoning Workshop） | **2,030 张真实 K-12 学生手写数学作业图 + 11,661 条由真实老师标注的 QA 对**（"VLM 能看懂学生手写过程吗"） | **语义最贴近我们**（学生手写过程理解）；但**英文/西方 K-12、非高中专属**，且数据走 HF/官网（HF ❌） |

### L3 标注层
- **K12-KGraph**（HF 上的 K12 知识图谱数据集，带 SFT 基线）→ HF ❌ 不可达；**即便拿到，标注口径也不是我们的五维/P_kp**
- 结论：**L3 自产**（D2 拆考点就是我们的标注器），外部无替代

## 四、自建方案（建议）

```
L1 题面层  ← GAOKAO-Bench 高考数学真题（GitHub 直拉）+ 教材习题
              ↓ 转成现有格式 { id, type, q, answer, points[] }
L2 痕迹层  ← ① AI 合成：按角色生成 4 类痕迹（做对完整 / 做错带断点 / 整题空白 / 野路子多解）
              ② 线上 questions 表导出真实痕迹（脱敏）→ 用来校准"合成得像不像"
              ③ DrawEduMath 作外部对照（能拿到时）
L3 标注层  ← D2 拆考点跑出的考点清单 + P_kp 期望值，交你抽检确认
```

**为什么"合成痕迹"是解决拍照麻烦的钥匙**：我们的判定管线吃的是**痕迹文本**，不是照片 —— 让 AI 扮演不同水平的学生写解题过程，一次生成几百条，回归测试就能全自动跑。行业里已有同类做法：手写图像合成用于主观题批改系统训练、LLM 角色扮演模拟学生学习行为。

**现有本地资产盘点（实测）**：
- `output/golden/golden-2025-I.json` = **8 题**，字段仅 `{id,type,q}`，**无答案、无考点标注**；`scripts/eval-golden.mjs` 自己注释写明"gold 考点标注为空待人工填" → **这正是要补的第一块**
- `output/raw/` 248 个 json = **腾讯 OCR 的页级文本检测结果**（`TextDetections`），**不是学生痕迹**（`traceReport` 命中 0）→ 不能当 L2 用

## 七、进展（2026-09-13 当天落地）

- **L1 题面集已建成**：`scripts/build-eval-dataset.mjs` → `output/golden/dataset-v1.json`，**426 题**（214 选择 / 81 填空 / 123 解答 + 旧 2025-I 卷 8 题），覆盖 2010–2025；每题含 `q / answer / analysis / type / year`，`trace` 与 `expect` 留空待填。原始拉取件在 `output/golden/_src/`（已 gitignore，版权原因不推仓库）
- **L2 痕迹层已跑通（自建）**：`scripts/synth-traces.mjs`，4 角色 —— `correct`（完整做对）/ `wrong`（中途出错）/ `blank`（整题空白）/ `alt`（野路子做对，专测"标准考点没被走到"）；产出 `output/golden/traces/traces-v1.json`，按 `(id, role)` 幂等合并、逐条落盘。已跑 2 题 × 4 角色 = 6 条，实测成本：单题 4 角色 ≈ 生成+判定共 4 次调用（in 3.4k / out 1.5k tokens）
- **L2 的正确性必须二次判定**（实测教训，详见开发经验 §51）：wrong/alt 的"真错/真对"**不能用字符串比对** —— 公式展开/通分后与正确答案字符串不同但数值完全相等。脚本内置 `--audit`（重判全库）+ `quality` 标记；**消费约定：忽略带 `quality` 的条目**（不删数据、留证据）
- **已知适配边界**：概念型填空题**天然没有出错空间** → wrong 角色会被判等价（实测 `gk-2010-Math_I_Fill-in-the-Blank-0`，模型直接回 `errorStep: 无（本题作答正确）`）。这类题只跑 `correct`/`blank`
- **待办**：① 批量生成（先 20 道解答题 × 4 角色建库）② 真实痕迹对照（线上 `questions` 表导出脱敏痕迹，校准"合成得像不像"）③ L3 期望标注（D2 拆考点跑 + 人工抽检）

- **🆕 顺带挖出的实锤：题侧漂移已经在我们的数据里发生了** —— 冒烟 **T3 与 T8 题面完全相同**（"求 f(x)=√(x−1)+1/(x−2) 的定义域"），T3 拆出 **1 个点 / 1 章**、T8 拆出 **3 个点 / 2 章**。这正是 D3 问题 6（题侧无人工确认兜底 → 对题投影会把漂移直接灌进 K 账）的直接证据；"缓存冻结 vs 接受漂移"的决策现在**有数可依**，不再是空想
