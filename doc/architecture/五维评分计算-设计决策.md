> 关联：`doc/architecture/诊断引擎设计.md`、`doc/decision-log.md`、`doc/theory/五维能力向量框架-理论文档.md`

## 一、核心决策

**五维评分 = AI 填公式参数 + 硬代码计算，不是 AI 直接给分数。**

```
Flash（诊断 Agent）调用 scoreFiveDim 工具:
  输入: 对错/过程质量(η,r)/归因/学生自述/历史掌握度 等证据
  输出: 公式参数（各维度的观测值、置信度…）
      ↓
云函数硬代码: scoreFiveDim(参数) → 五维分数
  （确定性计算，同参数同结果，可复现/可解释/可校准）
```

## 二、原则

**「诊断引擎已落地公式的用硬代码算；引擎侧尚未落地的不硬凑」**——不让 AI 直接编分数。理论文档五维公式齐全；本决策说的是 **scoreFiveDim / 诊断引擎管线里已经接入的公式**。

| 维度 | 引擎侧公式 | 说明（以理论文档为准） |
|------|-----------|----------------------|
| K（知识掌握） | ✅ 算法已定 | 加权得分法：掌握度 = S_k/D_k = Σ(D×P)/ΣD（理论 §4.4）。**非 BKT**。⚠️ **何时更新未拍板**（理论「仅回忆类」vs 旧「有答案即更新」，见《诊断引擎设计》待讨论 + 流水线 M4）；无答案降级冻结为草案（决策 011） |
| A（应用能力） | ✅ 已定 | A/U 框架：E = D×η（η∈0.4~1.0）；ΔA = 0.25×E×(U−A)；含 U 上下浮与做错时 E 符号规则（理论 §5.5） |
| T（迁移能力） | ✅ 已定 | T/U 框架：E_t = W×D×r；ΔT = 0.20×(T_shown−T)×(TU_new−T)（理论 §6.5） |
| Q（思维品质） | 🔴 引擎未落 | **理论 §7.6 公式已有**（Q1~Q5 移动平均 + 加权聚合）。诊断引擎本阶段不把 Q 写入 scoreFiveDim 硬算，只采集思维链信号；工程化见流水线 M6 |
| S（稳定性） | 🔴 引擎未落 | **理论 §8.4–8.5 公式已有**（S0 波动指数 + S_global）。诊断引擎本阶段不硬算 S 总分，可采自评偏差等信号；工程化见流水线 M7 |

## 三、为什么这样设计（第一性原理）

1. **可复现**：同参数同分数——学习工具的基本要求，今天跑和明天重跑必须一致
2. **可解释**：每个分数能追溯到「哪个公式 + 哪些参数」，报告可写「ΔA = 0.25 × E0.7 × (U−A) …」
3. **可校准**：公式在硬代码，调参只改一处，不碰 prompt
4. **可信**：AI 不「编分数」，只提供证据参数——诊断质量核心是评分可靠，不是 AI 会说话
5. **防污染**：AI 直接给分容易带幻觉；参数 + 硬算把幻觉限制在「参数」这一层，且参数可校验

## 四、与已有设计的衔接

- **η/r（决策 011）**：η（A，0.4~1.0）与 r（T，0~1）是传给公式的参数，不是终值
- **algorithm 版本号**：公式版本在代码，mastery_logs 记 `algorithm:'score_v1'` 等，可回溯重算
- **工具包（诊断引擎设计 §八）**：新增 `scoreFiveDim` 工具，与 vectorSearch/getNodeHistory/getTrend/getErrorPattern 并列
- **Q/S 引擎未落**：mastery_logs 本阶段先写 K/A/T；Q/S 留空不编造。理论公式在 `五维能力向量框架-理论文档.md`，待流水线 M6/M7 工程化后再补算法版本
