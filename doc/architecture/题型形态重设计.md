# 题型形态重设计 + 规则生成

> 状态：**设计稿，未动代码**
> 日期：2026-10-05
> 依据：用户定调（2026-10-05）+ 线上 59 条 pattern 实测

---

## 〇、一句话

**题型从「一个自由文本字符串」改成「三层结构：教材单元 / 母题 / 变式」，
并由 LLM 生成母题的区分性规则（criteria），供决策模型使用。**

---

## 一、现在的问题（实测）

### 1.1 现状

```
AI 输出：{domain, pattern, variant}
存入库：pattern = "domain / pattern / variant" 拼成一个字符串

例："集合 / 由集合相等求参数值 / 二次方程解集对应集合相等，需先求参数再解另一方程"
```

### 1.2 三个结构性问题

**① variant 污染检索主键**

```
检索主键本应是 pattern（母题）
实际存的是整串（含 variant）
variant 是"这道题的细节"，每题都不同
→ 做 embedding 时 variant 的噪声占大半
→ 同一母题的题，向量距离被 variant 拉开
```

**② domain 写法不统一（实测 5 种，实际只有 3 个板块）**

| 出现次数 | domain 写法 |
|---|---|
| 50 | 集合 |
| 5 | 集合与常用逻辑用语 |
| 2 | 集合与逻辑 |
| 1 | 函数 |
| 1 | 方程与不等式 |

**③ 没有稳定 ID，只有自由文本 → 无法表达"这个母题的历史"**

### 1.3 长尾实测（59 条 → 38 个 pattern）

```
出现 ≥2 次：12 个     ← 真母题
出现 1 次：  26 个     ← 其中明显有同义重复：
    "含参一元二次方程解集与集合包含关系求参数范围"
    "含参方程解集与集合包含关系求参数范围"        ← 同一母题
    "由集合包含关系求参数范围（含空集讨论）"       ← 也是同一类
→ 38 个里真实母题约 15~20 个
```

## 二、新形态（用户定调）

### 2.1 三层结构

| 层 | 名称 | 内容 | 受控？ | 用途 |
|---|---|---|---|---|
| **第一层** | **教材单元** | "集合与常用逻辑用语" | ✅ 受控枚举 | 分组、报告展示 |
| **第二层** | **母题** | "由集合相等求参数值" | ✅ 受控清单（可增长） | **检索主键** |
| **第三层** | **变式** | "二次方程解集相等，用韦达定理" | ❌ 自由文本 | 仅展示 |

### 2.2 存储形态

```json
// 现在
"pattern": "集合 / 由集合相等求参数值 / 二次方程解集对应集合相等…"

// 改成
"pattern": {
  "unitId":    "ch1",                      // 受控
  "unitName":  "集合与常用逻辑用语",
  "patternId": "p_set_eq_param",           // 受控，检索主键
  "patternName": "由集合相等求参数值",
  "variant":   "二次方程解集相等，用韦达定理",  // 自由
  "embeddingOf": "集合与常用逻辑用语 / 由集合相等求参数值"   // ★ 只编码前两层
}
```

**关键：`patternEmbedding` 只对 unit + pattern 两层编码，不含 variant。**

## 三、规则（criteria）由 LLM 生成

### 3.1 为什么这件事重要

**决策模型（Jev）的工作方式：**

```
输入 = state（内容）+ criteria（我们提供的规则/选项定义）
输出 = 从选项里选一个 + 概率

→ 【它不判断规则本身对不对】
→ 规则是我们给的，它只负责"按规则选"
```

**所以：**

```
规则的质量 = 决策的质量上限
规则错 → 它稳定地给出错的答案（且置信度可能很高）
```

### 3.2 今天实测印证

```
我给「并集」的 criteria = "由所有属于A或属于B的元素组成的集合"
「集合的运算」没有对应选项

→ 交集题：Jev 正确选「交集」（conf 1.00）✅

但唯一不稳的案例：
   题目：{1,2,3} 与 {3,2,1} 是否相等
   它同时考查「无序性」和「集合相等」
   我的 criteria 没有排除这种重叠
   → Jev 三轮里有一轮选了另一个（conf 0.47，它自己也犹豫）
```

**结论：criteria 的质量直接决定决策质量。**

### 3.3 criteria 该写什么（关键区分）

**注意：criteria 的用途和 embedding 不同。**

| | embedding 的输入 | **criteria 的内容** |
|---|---|---|
| 用途 | 算相似度 | **给决策模型做选择** |
| 该写什么 | **概念名本身** | **区分性特征** |
| 依据 | 实测：`name only` 最准（加定义反而稀释） | LLM 最擅长"这两个概念容易混在哪" |

**所以 criteria 要写的是"与相邻母题的区别"，不是"教材定义"。**

例：

```
母题：由集合相等求参数值
criteria（LLM 生成）：
  "已知两个集合相等，反求参数。
   注意与『由包含关系求参数范围』区分：
   相等是双向包含（A⊆B 且 B⊆A），包含是单向。
   注意与『由元素属于集合求参数』区分：
   属于是单个元素与集合的关系，相等是整体对应。"
```

### 3.4 生成时机（用户定调）

> **「criteria 到时候跟知识图谱一起生成，就是到时候治理的时候」**

```
即：图谱治理那一轮，同时做
  · 知识点节点治理
  · 母题清单建设
  · 每个母题的 criteria 生成

→ 一次做完，避免分两次动
```

### 3.5 生成方式（三种可选）

| 方式 | 做法 | 优劣 |
|---|---|---|
| **A** | 从历史误判里学：哪些描述让判断更准 | 最准，但需要标注数据 |
| **B** | 让 LLM 读教材定义 + 相邻母题，生成区分性描述 | 快，可批量 |
| **C** | 人工写关键几个，LLM 补其余 | 质量可控 |

**建议：先 B（批量生成初稿）→ 人工过一遍 → 用 A 持续优化**
