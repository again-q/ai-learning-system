## 一、架构总览

```
📸 拍照（1题或多题，含做题痕迹）
       │
       ▼
┌─────────────────────────────────────────────┐
│             诊断引擎（云函数 diagnose）        │
│                                             │
│  ① 图像理解  Qwen3.7Plus（HTTP 调阿里 API）  │
│     → Markdown 报告（题目+公式+图表+做题痕迹） │
│                                             │
│  ② 推理诊断  Flash max 思考（TokenHub）      │
│     → 结构化 JSON（题目/知识点/对错/错因/     │
│        归因/五维评分/行动建议）               │
│                                             │
│  ③ 写入     questions + mastery_logs        │
│     + embedding（text-embedding-v4）→ RAG   │
└─────────────────────────────────────────────┘
       │
       ▼
  诊断报告（五层结构，见《诊断报告设计》）
```

## 二、双 AI 管线（已定）

| 阶段 | 模型 | 部署 | 职责 |
|------|------|------|------|
| ① 图像理解 | Qwen3.7Plus（多模态） | 云函数 HTTP 调用阿里 API（按调用付费，免部署） | 整体把握图片：提取题目文字/公式/图表 + 观察做题痕迹（涂改、草稿、答题路径）→ 输出 Markdown 报告 |
| ② 推理诊断 | DeepSeek V4 Flash（max 思考档） | CloudBase TokenHub | 结合历史知识状态 + RAG 检索 + 当前结构化数据 → 输出诊断报告 + 五维评分 |

**模型策略**：固定 Flash max 思考，不做动态升级、不做用户自选。

## 三、诊断触发流程

```
前端：拍照（逐张上传）→ 点「完成」→ 调 diagnose（一次分析整批）
```

- **非逐题出报告**：一批拍完统一分析，出单次报告（已定）
- 进度展示：`ai分析中(预计耗时)` → `ai生成报告中(预计耗时)`（已定）
- 错误处理：失败图标记「分析失败」+ 展示原图 + 引导重新上传（已定）

## 四、单题诊断管线（详细）

```
① Qwen：图片 → Markdown 报告（题目+痕迹）
     ↓
② Flash：Markdown + 历史 + RAG → 结构化 JSON（直接输出，不另加解析步骤）
     ↓
③ 对错判定（决策 013）：
     有标准答案（学生录入>AI识别）→ Flash 对比 → isCorrect（高置信）
     无标准答案 → 三层流程（决策 011）
     ↓
④ 归因（决策 012）：
     证据（Qwen 痕迹 + 学生口述）→ 直接原因 → 行动建议
     信号题（反复错/明明会却错/变形就崩）→ 深挖思想根源
     ↓
⑤ 五维评分 K/A/T/Q/S（决策 014：AI 填参数 + 硬代码算）
     有公式的维度（K/A/T）→ scoreFiveDim 工具 → 硬代码公式算分
     无公式的维度（Q/S）→ 搁置不硬凑，只采集信号（S 自评偏差）
     有答案题 → K 正常更新（BKT）
     无答案题 → K 冻结，A/T 靠过程质量（η/r）更新
     ↓
⑥ 写入：questions + mastery_logs（含五维快照+算法版本）
     + embedding（text-embedding-v4）→ RAG 自增强
```

## 五、无标准答案题的三层流程（决策 011）

```
【第一步】AI 判可解性（不看学生答案）
    ├─ 能（有确定答案）→ AI 算标准答案 → 正常 K/A/T 全过程
    └─ 不能（主观/无确定解/图形残缺）→ 进第二步

【第二步】放弃对错标记，只做过程诊断
    ├─ 分析学生步骤 → η（路径质量）+ r（解题质量）
    ├─ 更新 A（单元内题）或 T（跨单元题）；K 冻结不更新
    └─ 触发思维链弹窗，重点采集 Q 维度

【第三步】S 维度轻量自评
    └─ 弹窗「这题你觉得能拿几分？」→ 比对 AI 过程分析 → 稳定性报告
```

**待确认 3 细节**：① η/r 定义与取值（建议 0-1，Flash 计算，存 mastery_logs）② 可解性置信度阈值（建议 ≥0.8）③ AI 算的答案标记 `answerSource:'ai_computed'`，低置信不更新 K（防污染）

## 六、RAG（轻量自建，已定）

| 项 | 结论 |
|----|------|
| Embedding 模型 | text-embedding-v4（¥0.50/百万 tokens） |
| 向量存储 | **轻量自建**：embedding 存 mastery_logs 同一条记录 |
| 检索方式 | 云函数内 for 循环 cosine 相似度 |
| 检索时机 | 每次生成报告时实时计算（~7200 条/学期，无缓存必要） |
| 检索数量 | top-K = 5 |
| RAG 库内容 | 每次的题目 + 诊断结果 |
| 增强方式 | Flash 输出后 → embedding → 存入 → 下次被命中 |

**用途**：T 维度（迁移能力）需要语义模糊检索——识别表面不同但内核相同的题目（例：分段函数错 → 检索到绝对值分类讨论 → 结论是「分类讨论思维模型没建立」）。

## 七、云函数拆分（已定，待拍板项之一，推荐 ✅）

| 云函数 | 类型 | 职责 | 超时 |
|--------|------|------|------|
| `photoUpload` | Event | 登记上传（fileID + 状态 pending）；删除清理 | 默认 |
| `diagnose` | Event | 读批内 pending → Qwen（逐张）→ Flash（推理）→ 写入库 → 返回报告 | 120s |

API 规范：`{ code, data, message }` + `event.action` 路由，错误码 0/1xxx/2xxx（见 API-GUIDE.md）

## 八、工具包（已定）

| 工具 | 用途 |
|------|------|
| vectorSearch | RAG 语义检索 |
| getNodeHistory | 知识点历史掌握度 |
| getTrend | 五维历史趋势 |
| getErrorPattern | 错误模式识别 |
| **scoreFiveDim** | **五维评分：AI 填公式参数，硬代码算分（决策 014）** |

**复用**：诊断引擎（单次报告）+ AI 教练（深度查询）共用工具包；数据写入权限只有诊断引擎，教练只读。

## 九、性能与成本（已定）

| 项 | 结论 |
|----|------|
| Token 预算 | ~8-10K tokens/次（Qwen 1-2K + 图谱历史 2-3K + RAG 3K + prompt 1K）✅ 可接受 |
| 云函数超时 | 120s |
| 冷启动 | 接受首调延迟，MVP 不预热 |
| 数据量 | 7200 条/学期，无需分表归档 |

## 十、边界与明确不做（MVP）

- ❌ AI 教练（Phase 2）
- ❌ 逐题出报告（统一批量）
- ❌ 完整思想根源七层深挖（只对信号题）
- ❌ 老师端/学校系统（只面向学生）
