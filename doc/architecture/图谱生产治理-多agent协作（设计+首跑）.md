## 0. 大白话

你一个人管 271 个节点，靠肉眼找问题太累。改成：**几个 agent 分头读节点、出「提案」，你只按「批准 / 否决」批。**

- agent 只出提案，**不写库**（官方图谱保护：修改权在你）
- 每条提案必须带：**判据出处**（如 §七 How）+ **教材原文证据片段** + 一句话理由
- **代码当裁判**：值域校验 / 编号合法 / 成环检测都在代码侧——agent 说错就当场拒收，不让脏提案进队列

## 1. 五个角色（按治理任务切）

| 角色 | 看什么 | 吐什么 | 判据 | 代码收口 |

## 2. 首跑证据（10 个 method 节点，前两章）

| 节点 | 判定 | WWH | 依据/理由（摘要） |
|---|---|---|---|
| 因式分解 | keep | operation | 独立运算操作，可独立考核（§七 操作） |
| 配方法 | keep | operation | 可独立考核的操作方法（§4.2 method） |
| 列举法 | keep | operation | 回答「怎么做」且可独立考核 |
| 求补集的方法 | keep | operation | 集合运算变换，可独立考核（名字宜改动宾短语） |
| 列举子集的方法 | **rename** | operation | 应归入规范节点「列举法」 |
| **Venn图** | keep | **notation** | **图形表示工具 → 原 type 标成 method 是错标** |
| 或与且 | **drop** | other | 逻辑联结词辨析，§4.2 明确不是独立知识点 |
| 四种条件关系 | **drop** | other | 关系辨析，并入相关节点 |
| 求并集交集的方法 | **drop** | how | 应用步骤 → 归 A/题型（§七 How 不建） |
| 描述法 | keep | **REJECTED** | 模型给出枚举外的 wwh → **代码裁判拒收** |

提案分布：**keep 6 / rename 1 / drop 3**。

### 三条发现

1. **「一刀切全移方法区」确实粗了**：89 个 `type=method` 里**混着合法的「操作」**（因式分解/配方法/列举法/求补集——WWH 明确允许），也混着「How/思想/辨析」（求并集交集的方法/或与且/四种条件关系）→ **必须逐条分诊**，不能按 type 一刀切
2. **type 错标被自动抓到**（Venn图 应是 notation）→ 印证治理报告 P1「type 标注错误」
3. **「代码当裁判」这层真的有效**：「描述法」那条 wwh 落到了枚举外，代码当场拒收，没有混进队列

## 3. 成本与节奏

- 单节点 **1 次调用**；首跑 10 节点 ≈ 5.6k tokens ≈ **一分钱量级**
- 全量分诊 89 个 method 节点 ≈ 89 次调用 ≈ **几毛钱**；若含 182 知识区节点 ≈ 271 次 ≈ **一两元**
- **正好匹配你的时间**：提案出来后可**分批批**（每天 15~30 分钟批一批），不必一次看完
