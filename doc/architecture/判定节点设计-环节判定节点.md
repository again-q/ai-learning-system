## 0. 大白话：一句话

> 拆考点（D2）告诉你"这题考哪几个点"；**这个节点告诉你"这个学生做这题时，每个点用上没有、用对没有"**。

## 0.5 白话版 · 分步看（决策 033：先白话后术语）

### ① 它在流水线里站哪？

- 前面是 D2 拆考点：**只看题** → "这题考哪几个知识点"，全校共用一次
- 本节点：**看学生** → 同一题每人写的痕迹不同，所以每人每题单独判一次

### ② 怎么判？（4 步）

1. **标超前点**：考的点在学生还没学的章节 → 代码直接标（不用 AI）
2. **查空白**：整张空白？→ 直接判"没写"，不请 AI（看了也是编）
3. **AI 逐点核对**：拿"点清单"对着"学生写的痕迹"，每点给一句依据（引原文）
4. **代码兜底**：AI 有没有乱编新点、漏点、分不规范 → 查出来

### ③ 一个点 → 三种判法 → 三种记账

| 学生的表现 | 账本 | 一句话 |
|---|---|---|
| 用对了 | 加分 | 会 |
| 用了一半（漏条件/漏讨论） | 加一半 | 会但毛糙 |
| 做错了 | 不加分，记一次"考过" | 有证据的不会 |
| 没写到这个点（绕过去了） | **账本不动** | 没证据，不冤枉不乱夸 |
| 整张空白 / 题超纲 | 整题跳过 | 没做不降分 |

### ④ 最难：野路子做对了怎么办？→ 三层分账

> 例：代数题不用标准步骤，用几何一眼看穿，还做对了。

| 层 | 问什么 | 怎么处理 |
|---|---|---|
| K 账 | 这个点会不会？ | 没走到 → 没证据 → **不动账**（不冤枉） |
| A 账 | 这招好不好？＝路径分 | 简洁直击要害 → 高奖（涨快 + 上限抬）<br>绕远硬算 → 低分（老这样压上限） |
| 报告页 | 学生看得见吗？ | 夸"这条路很聪明" ／ 委婉说"这条路绕远了" |

> 你说的"**冗余 = 负面、优雅 = 正向**"，就落在 A 账这一行。

### ⑤ 为什么不搞"创新就加分"？（4 个坑）

1. **字看不清**：拍照转录本来就糊，AI 评"优不优雅"＝戴墨镜评画
2. **AI 不稳**：同题判两遍分都可能不一样 → 拿不稳的分去奖 ＝ 乱奖乱罚
3. **样本少**：野路子太少，"该加多少"调不准
4. **带歪人**：乱夸 → 学生追花哨；乱罚 → 学生不敢试

→ 先做"不冤枉 + 该给照给"。等两件事到位再谈"创新大奖"：
**路径分稳（有实测）＋ 野路子样本够（能校准）**

### ⑥ 怎么证明它能用？（冒烟）

- 5 类题真跑：做对 / 做错 / 空白 / 选择 / **一题多解**（专测野路子点不被冤枉）
- 2~3 道题**同题判 3 遍** → 看路径分稳不稳（决定 ⑤ 的创新大奖做不做）

## 1. 节点定位

## 1. 节点定位

- **生侧、逐人判、不可缓存**：同一题不同学生痕迹不同 → 结果不同。这与 D2 的"纯题侧、可缓存"正好相反（D2 拆一次全校共用，本节点每生每题判一次）。
- **只判 P_kp，不判 D_kp**：D（考察难度）由拆考点（题侧）给出并随 pointList 带入——保持"D 是题目固有难度、与作答无关"的语义纯洁（线上 D 是判定时和作答一起给的，天然有被污染的风险）。
- **只判不记**：超前点记账规则（P_kp=1 → 记 K + 边界前移；P_kp<1 → 不计 D）属于下游记账节点职责，本节点只输出判定 + 标注（state: judged/noEvidence/blank + isAhead），不写库、不更新档案。
- **代码先于模型**：能纯代码推导的（超前标注、空白短路、名字校验、三档规整）一律代码做；模型只干"看痕迹打 P_kp"这一件事。

## 2. 输入输出契约

### 输入（依赖注入：llm 从外面递；其余来自图状态 / 上游产物）

```
{
  question: {
    questionText,          // 题面
    questionType,          // 选择|填空|解答|其他 —— 选填无过程走简化判定（见 §3 ②）
    traceText,             // 学生痕迹文本（N1 精读优先：裁剪图精读 → 整页 traceReport，与线上同款回退）
    studentAnswer,         // 学生答案（选填题的主要证据）
    segments,              // 过程分段 [{step,status,evidence}]（上游产物，非本节点自判）
    breakpoint,            // {index,nature} | null
    processAvailable,      // 痕迹可信标记（涂改乱/看不清=false）
  },
  pointList: [             // D2 拆考点产物（pointList ∪ other 都进判定面）
    { name, chapter, dkp } // dkp 0~1（题侧）；图谱外点 other 的 dkp=null → 本节点补判（§5 待决 A 已拍板 a1）
  ],
  outOfSyllabus: false,    // D2 整题级课标超纲标记（照传，语义与线上 isOutOfSyllabus 对齐）
  learnedChapters: [...],  // 学生已学章（能力边界）；影子对比期传 null = 全已学（线上无此档案）
  llm,                     // 注入：({system,user}) => 已解析 JSON（测试传假 llm）
}
```

### 输出

```
{
  judgements: [            // 与 pointList 按 name 对齐（LLM 输出顺序无关）
    { name, chapter, dkp, state: 'judged'|'noEvidence'|'blank', P_kp: 0|0.5|1|null, isAhead, auto, basis }
    // state（每点三态，§5 待决 C 定稿产物）：
    //   judged      —— 痕迹中能找到该点对应环节 → P_kp 三档有效（1 用对/0.5 漏边界/0 缺失全错）
    //   noEvidence  —— 痕迹中完全没有该点环节（被替代路径绕开/无对应动作）→ P_kp=null，
    //                   本节点不给分；K 不进 S 也不进 D（无观测不记账 = 防毒原则延伸，见 §3 规则表）
    //   blank       —— 整题空白代码短路 → P_kp=0 + auto=true（记账端据 derived.blank 整题跳过）
    // isAhead：代码派生（该点章 ∉ learnedChapters，超前不做模型判断）
    // auto=true：该点 P_kp/state 是代码直接给的，非 LLM 判定
    // basis：判定依据（引用痕迹原文片段；noEvidence 明写 no evidence 不许脑补；供复核展示与 D4 diff）
  ],
  derived: { blank: bool },// 整题空白标记（供下游记账决策；判定逻辑与线上 isBlank 同款）
  ok: bool,                // name 全覆盖校验通过 && LLM JSON 可解析
  issues: [...],           // LLM 自造名/越界等 → 丢弃该点并记录（不阻塞主流程）
}
```

## 3. 内部小图（代码 → 模型 → 代码）

```
输入（§2）
① 代码：边界派生标注 —— point.chapter ∉ learnedChapters → isAhead=true
        learnedChapters=null → 全部 isAhead=false（影子对比期与线上行为可比）
② 代码：空白短路 —— 整题空白（breakpoint=起步即停，或 无答案且 segments 空）
        → 全部点 state=blank + P_kp=0 + auto=true，derived.blank=true，【不调 LLM】（省钱 + 防脑补）
        无过程题（选填 processAvailable=false）：不短路，但 prompt 明示只能用答案/题面反推
③ 模型：逐点打判定（一次调用；点 ≤15 不分块，见 §5 待决 B 的成本账）
        system：P_kp 三档锚点（规范 §2.1 原文）+ state 判定锚点：
                judged=痕迹能引用到该点对应环节；noEvidence=痕迹无该点对应环节（被替代/无动作）
                强约束：【只许对给定点判，禁止新增/改名/漏点】+ 每点给 basis（引用痕迹原文，禁止编造；
                证据不足 → 该点标 noEvidence，不许脑补成 0 或 1）
        user：题面 + 痕迹 + 点清单（name + chapter；other 点附 reason；不在 prompt 里给清单外任何候选名）
④ 代码：校验规整 —— name 对齐 pointList（自造/越界 → 丢弃记 issues）
        state=judged 的点：P_kp 三档规整（≥1→1；>0→0.5；否则 0 —— 与 updateMastery.js 同款 clamp）
        state=noEvidence：P_kp 置 null（不进账，见 §3 规则表）
        LLM 未覆盖点 → 记 issue，补 state=noEvidence + auto=true（宁中性不错杀，防毒原则）
输出（§2）
```

### 与上下游的边界
- **上游依赖**：segments / breakpoint / processAvailable 由上游盒子喂（完整图里是 N1 精读 + N2A 判其余/防毒的产物），本节点不自己判过程分段——它们只是"判 P_kp 时能用的事实"。
- **下游移交**：记账节点决定 blank / 超前点的记账动作。本节点只输出判定 + 标注，不写库、不更新档案。

### K 记账规则表（下游 N5 记账盒子落实，本节点不执行）

> 本表是 D3 判定输出 → 记账动作的唯一口径；N5 记账盒子设计时照表实现，避免线上"对的三口径"式混乱重演（经验教训：同一概念多口径 → 读侧/统计侧打架）。

| 本节点输出 | 记账动作（K：S_k += dkp×P_kp，D_k += dkp） | 依据 |
|---|---|---|
| derived.blank=true（整题空白） | K 整题跳过（任何点都不进 S/D） | 已拍板 D：空白=没有行为，防无谓降 K |
| outOfSyllabus=true 且整题没做对 | K 整题跳过 | 对齐线上 isOut 绕过语义（updateMastery 同款） |
| judged + P_kp=1 | S+=dkp，D+=dkp；correctCount+1 | 规范 §2.1 |
| judged + P_kp=0.5 | S+=0.5dkp，D+=dkp | 规范 §2.1 |
| judged + P_kp=0 | S+=0，D+=dkp | 有证据的缺失/全错 = 负样本 |
| noEvidence | **不进 S 不进 D**（中性） | 无观测不记账（防毒原则延伸，§5 待决 C） |
| isAhead=true 且 P_kp=1 | 记 K + 能力边界点级前移 | D2 设计 §3（下游实现，需边界档案） |
| isAhead=true 且 P_kp<1 或 noEvidence | 不计 D（没学的不会不降） | D2 设计 §3 |
| 路径质量（冗余/优雅） | **不进 K**——走 A 维 η（见 §5 待决 C 定稿） | 维度分工：K 只记点，A 只记路径 |

### C · 替代路径 / 环节缺失：收敛版定稿（待用户 review）

**问题**：点清单是"标准考察"；学生走非常规（替代）解法时，某标准点可能"没走到"——判 0 冤枉做对的人，判 1 是撒谎（他没展示）。

**从学习本质出发的推导**（2026-09-06 用户口述方向，第一性推导）：
1. 非常规做法**要二分，不能一刀切**：冗余绕远 → 负面信号；优雅简洁 → 正向奖励。路径好坏与"是否标准"无关，与"是否接近本质"有关——这正是 **η（路径质量系数）的定义域**（宪法 5.5：η = 判断解法是否接近本质，0.4~1.0；5.4-4：暴力计算 A 涨得慢 U 不涨甚至下浮，本质解法 A 涨得快 U 持续上浮）。
2. 因此**路径的奖与罚是 A 维 η 的职责，不是 K 维**：K 只回答"这个点用没用对"；路径绕不绕、美不美与 K 无关。
3. K 维对"没观测到"的点唯一诚实的动作 = **无观测不记账**（noEvidence 不进 S/D）——这不是宽容补丁，是防毒原则（经验 §39：没证据不做推断）在记账侧的延伸。

**落法（三层分账，各归各）**：
- **本节点（K 维）**：state=judged 三档照判；state=noEvidence 不进 S/D。不做任何路径判断、不判 η。
- **η 判定（判定盒子，衔接标记）**：把"非常规但接近本质 → 高 η / 绕远暴力 → 低 η"写为 **η 判例锚**（对齐经验 §8：例子锚比抽象描述有效）。优雅非常规自然高 η → A 快涨 + U 上浮 = 正向奖励；绕远 → 低 η → A 慢涨 + U 累计下浮 = 负面信号。
- **报告层（衔接标记）**：对优雅路径显式认可、对绕远委婉指出——"大大奖赏"先在此层可感知兑现（与 Q 弹窗被否→报告页回顾同路径：理想信号降到产品现实能承载的层）。

**为什么 v1 不做"新颖度轴 / 数值超额"（历史教训索引，防理想化）**：
- **判据悬空**：判"是否优雅新颖"需看清完整推理脉络 → 拍照转录给不了（T 维因此暂缓；经验 §40/§44 密集页转录会挂/降级、processAvailable=false 常见）——判据吃不到可靠数据；
- **判定漂移**：η 边界本身会抖（经验 §9 同题随评估方式漂移），细差值放大 → 同题重判不同果。U 上下浮的**累计/低频设计是抗抖动特性，不是缺陷**，不改单题；
- **prompt 禁令不是保证**（经验 §36）：LLM 遵守约束是概率性 → "新颖度"会被误判（花哨当优雅/绕远当新颖）→ 乱奖乱罚比不奖不罚更伤学生（误导追花哨、吓退尝试）；
- **样本稀疏**：非常规本来就少，参数无法校准（拍脑袋参数 = 决策 030 式事故）；
- **多口径教训**：η 已兼"A 增速系数 + U 上下浮条件"，再加"新颖放大"在同一判定上叠更多语义角色。
- **启用条件（挂起）**：① η 判定过 golden 稳定性评测（§6 冒烟含此预检）② 真实样本攒够校准——两者到位前，数值超额不进 v1。

**替代路径信号反哺 D2**（观察项）：替代路径能做对 = 拆考点入选判据"不掌握它就可能做错"的反例 → 该点 dkp 该降/该拆出。积累 noEvidence 高频点，回填拆考点 F 清单（D2 冒烟遗留治理），不做即时惩罚。

### 待决（未拍板，按默认处理推进，实现前复核）

## 6. 冒烟方案（SOP 第②步，定稿后跑）

- **目的**：证明"对着点清单看痕迹打 P_kp"在真模型下可跑、与线上 knowledgeUsage 同语义、成本在预期档。
- **方法**：仿照 smoke-decompose-points.mjs 的 SMOKE_* 注入模式，建 `scripts/smoke-judge-points.mjs`：
  1. 构造 5 类题：T1 解答做对（过程完整）/ T2 解答做错（有断点）/ T3 整题空白（断言短路：llm 调用计数=0、全 state=blank、derived.blank=true）/ T4 选填（无过程简化判定）/ **T5 替代路径题**（用一道有多种解法的题，验证 noEvidence 落点与预期一致、不冤枉）；

- **输出**：output/smoke-环节判定/ 报告；预期成本 T1–T5 ≈ 5 次调用 + 稳定性预检 6~9 次调用，disabled 秒级。
