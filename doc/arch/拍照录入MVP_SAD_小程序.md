## 2. 执行摘要

微信原生小程序，提供拍照诊断（拍照→报告→异议）与知识图谱浏览。沿用现有小程序骨架（首页/知识树已有雏形），体验占位优先，P0 只保证链路可用。

## 3. 需求分析

来自 PRD：拍照入口、拍照/选图（≤9）、提交分析、报告展示、报告异议、失败降级、图谱层级浏览、知识点详情。NFR：拍照→报告 ≤3min、首屏 ≤2s。

## M1. 小程序技术栈

| 项 | 选型 | 理由 |
|----|------|------|
| 开发框架 | 微信原生小程序 | 与现有代码一致（miniprogram/ 已有骨架），无需引入 Taro/uni-app |
| UI 组件库 | 不引入（占位体验） | P0 体验占位；设计规范见 PRD §5.7（后续可评估 Vant Weapp） |
| 状态管理 | 原生 globalData | 页面少、状态简单，无需引入状态库 |
| 网络请求 | wx.cloud.callFunction 封装层 | 云函数调用统一封装（现有工程已有） |

## M3. 分包策略

- **主包**：tabBar 3 页 + 登录页（<2MB）
- **分包**：无分包需求（页面少、体量小）
- **预估**：主包 <1MB（无大依赖）

## M4. 微信能力集成

| 能力 | 业务目的 | 集成方式 |
|------|---------|---------|
| 登录 | 识别学生身份 | 沿用现有登录云函数（userLogin），openid 体系 |
| 拍照/相册 | 拍做题照片 | 选择媒体后上传云存储（经云函数 photoUpload） |
| 云开发 | 数据读写 | 云函数调用（照片上传/诊断/报告/图谱），前端不直连外部 AI |

## M5. 状态管理

- **globalData**：当前用户信息、最近批次 ID、当前报告数据
- **页面间传递**：批次 ID / 题目 ID 通过页面参数传递
- **报告状态**：分析中（两阶段进度）→ 完成 → 异议修正后刷新单题

## M6. 小程序安全与性能

- **安全**：所有 AI 调用走云函数（key 不落前端）；照片仅本人可见（后端按 openid 隔离）
- **性能**：图片压缩后上传（单张 <1MB）；报告页懒加载分题渲染；首屏只拉摘要
- **体验占位**：P0 不做精细动画，但遵守基础可用性（触控 ≥44pt、加载态、空态、错误引导——PRD §5.6）

## 10. 跨端契约

| 交互 | 小程序动作 | 云函数 | 数据流 |
|------|-----------|--------|--------|
| 上传照片 | 选图 → 调 photoUpload | 存云存储 + 建批次 | 照片 → fileId + batchId |
| 触发诊断 | 调 diagnose(batchId) | 管线跑完写库 | batchId → 报告 JSON |
| 查看报告 | 调 getReport(batchId) | 读三集合 | 报告数据 |
| 异议修正 | 调 disputeQuestion(questionId,修正) | 单题重诊 | 修正 → 新判定 |
| 图谱浏览 | 调 getGraph(节点ID) | 读 knowledge_nodes | 节点树/详情 |
