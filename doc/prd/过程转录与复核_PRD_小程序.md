## 第 1 节：执行摘要

- **一句话定义**：本次改动的学生侧表现是——**复核页面第一次真正有内容给学生看**：系统把手写内容认成的文字摆出来，学生能一眼看出"这不是我写的"，当场改正，系统重新判断。
- **核心业务价值**：
  - 学生**从"只能接受系统的判断"变成"能纠正系统看错的字"**，这是信任的前提。
  - 学生不再遇到"我明明写了，它说我没写"这种一眼假的结论。
- **预期成功指标**：
  - 复核页能显示每一道题的认字原文（当前为空白）。
  - 学生能对照答题卡图片核对文字，并在 3 步内完成修改。
  - 学生修改后，该题重新判断，报告随之更新。

## 第 2 节：项目背景与目标

### 2.1 背景描述

学生做完作业后，系统会把手写的答题卡内容转成文字，再据此判断对错。但**这份文字从未展示给学生看过**：

- 学生打开复核页面，看到的是一片空白——没有文字可核对。
- 系统认错的字（例如把 `xy/(x−y)` 认成 `1/(1/xy)`），学生**没有任何机会发现**。
- 更严重的是，当系统没认出学生写的字时，会直接判定"整题空白未下笔"——学生明明写了答案（实测中为「454」），却被报告告知"没写"。

复核环节在流程上存在，但因为没有内容可核，**实际上是一个空转的步骤**。

### 2.2 业务目标

| 目标 | 说明 |
|---|---|
| G1 | 复核页必须显示系统认字的原文，让学生有东西可核 |
| G2 | 学生能对照真实答题卡图片核对文字，不必凭记忆 |
| G3 | 学生发现认错时，能简单快速地改正 |
| G4 | 改正后系统按新内容重新判断该题，报告同步更新 |
| G5 | 学生能看出"哪些地方系统自己也不确定"，集中核对可疑处 |

### 2.3 成功指标

| 指标 | 当前 | 目标 |
|---|---|---|
| 复核页显示认字原文 | 空白 | 完整显示 |
| 学生能修改认字结果 | 不支持 | 支持 |
| 修改后报告更新 | 不支持 | 支持 |
| 学生可对照答题卡图片 | 部分支持 | 每题可点开图片 |
| 复核完成所需步数 | 无法完成 | ≤ 3 步 |

### 2.4 项目范围

**范围内：**

- 复核页展示认字原文（题目文字 + 学生过程文字分开显示）。
- 复核页标出"系统不确定"的地方。
- 复核页提供查看答题卡原图的入口。
- 学生修改认字结果并保存。
- 修改后触发该题重新判断，报告同步。
- 学生跳过复核时，报告标注"过程未经核对"。

**范围外：**

- 不新增任何要求学生额外操作的动作（核对既有内容不算新增）。
- 不改变答题卡图片的呈现方式（裁剪保持不变）。
- 不重做报告页的视觉设计（另行立项）。
- 不做社交、分享、排行榜等超出诊断的功能。

## 第 3 节：用户角色与场景

### 3.1 用户画像

| 角色 | 描述 | 本次关注点 |
|---|---|---|
| 高中生（主要） | 数学中上水平，做完作业想快速知道哪里会被扣分 | 系统看错我的字，我要能改，且不要太麻烦 |
| 高中生（次要） | 成绩中等，需要知道哪里不会 | 报告不要说我"没写"，我明明写了 |

### 3.2 使用场景

**场景 A：核对无误（多数情况）**

学生进入复核页，看到"你写的：454"，与自己卷面一致，点"确认"，进入分析。

**场景 B：发现认错**

学生看到系统把 `xy/(x−y)` 认成了 `1/(1/xy)`，点"修改"，改成正确的，保存，系统重新分析该题。

**场景 C：系统没认出（本次重点修复）**

学生明明在横线上写了答案，复核页却显示空白。此时页面**不能**让学生以为"自己没写"，而应提示"这里没认出来，请补一下或查看原图"。

**场景 D：直接跳过复核**

学生急着看结果，点了"全部确认，开始分析"。系统按未核对的内容判断，但报告中标明"此题过程未经核对"。

### 3.3 用户旅程

```
学生提交作业
   ↓
系统认字（学生在等待页看到"正在识别手写内容"）
   ↓
进入复核页
   ├─ 每题卡片：题目文字 / 你写的 / 不确定处标记 / 查看原图
   ├─ 看到可疑处 → 点"修改" → 可用大白话说明 → 系统改写 → 学生确认 → 保存
   └─ 全部核对完 → 点"开始分析"
   ↓
进入分析（学生看到进度）
   ↓
查看报告
```

## 第 4 节：功能需求

### 4.1 业务流程

```
① 提交作业（已有）
      ↓
② 等待识别手写内容（新增等待态）
      ↓
③ 复核页（改造）
   · 显示系统认字原文
   · 区分"题目"与"你写的"
   · 标出系统不确定之处
   · 提供查看原图入口
   · 允许修改（支持用大白话说明改什么）
      ↓
④ 学生确认全部 → 开始分析
      ↓
⑤ 报告（本次不改，但增加"未经核对"标注）
```

### 4.2 功能列表

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 复核页显示每题的认字原文 | M | 当前为空白，需补上 |
| F-02 | 题目与学生过程分栏显示 | M | 让学生清楚"哪句是题、哪句是我写的" |
| F-03 | 标出系统不确定之处 | M | 视觉上突出，便于集中核对 |
| F-04 | 每题可查看答题卡原图 | M | 对照核对，不靠记忆 |
| F-05 | 修改认字结果并保存 | M | 已有表单，需与新数据打通 |
| F-06 | 用大白话说明要改什么，由系统改写 | M | 已有能力，保留 |
| F-07 | 修改后单题重新分析 | M | 不重跑整批 |
| F-08 | "没认出来"时给出明确提示 | M | 不得让学生误以为是自己没写 |
| F-09 | 跳过复核时报告标注"未经核对" | S | 保持诚实 |
| F-10 | 复核进度提示（还有几题没看） | S | 降低遗漏 |
| F-11 | 识别过程中的等待反馈 | S | 让学生知道系统在工作 |

### 4.3 权限逻辑

| 操作 | 学生 | 说明 |
|---|---|---|
| 查看自己的题目与作答 | ✅ | |
| 修改自己的题目与作答 | ✅ | |
| 查看他人内容 | ❌ | |
| 查看原图 | ✅ | 仅本人答题卡 |

### 4.4 验收标准

> 覆盖全部 M 级与 S 级功能。每条以"假定 / 当 / 则"描述业务行为与业务结果。

**F-01 复核页显示每题的认字原文（M）**

- 假定系统已完成识别，当学生进入复核页时，则每道题的卡片上都显示出识别出来的文字内容（当前为空白，需补上）。
- 假定某道题确实没有任何文字可显示，则卡片明确指出该题没有可核对的内容，而不是留一片空白。

**F-02 题目与学生过程分栏显示（M）**

- 假定某题的图片上同时有题目和手写作答，当学生查看该卡片时，则"题目"与"你写的"分别在两个区域显示，学生能一眼分清。

**F-03 标出系统不确定之处（M）**

- 假定某题的识别结果中有不确定的地方，当学生查看该卡片时，则该处被明确标记出来，并提示学生重点核对。
- 假定某题没有不确定之处，则该题不出现任何标记。

**F-04 每题可查看答题卡原图（M）**

- 假定学生想核对外面识别的文字，当学生点击"查看原图"时，则显示该题的答题卡原图，学生可对照查看后返回。

**F-05 修改认字结果并保存（M）**

- 假定学生发现识别有误，当学生点击修改、改动内容并保存后，则页面上显示的内容更新为修改后的内容，并提示已保存。

**F-06 用大白话说明要改什么（M）**

- 假定学生不会写公式，当学生用一句日常话说明要改什么并提交后，则三个内容区域按学生的意思更新，学生可再次确认后保存。

**F-07 修改后单题重新分析（M）**

- 假定学生修改了某题并保存，则系统只对这道题重新分析，学生看到该题的进度提示，其他题不受影响。

**F-08 "没认出来"时给出明确提示（M）**

- 假定某题学生明明写了但系统没识别出来，当学生查看该卡片时，则页面提示"这里没认出来，你看一下原图补上"，不得显示成学生没有作答。

**F-09 跳过复核时报告标注"未经核对"（S）**

- 假定学生没有核对某题就开始了分析，当学生查看报告时，则该题标注"过程未经核对"。

**F-10 复核进度提示（S）**

- 假定学生还有 2 道题没有核对，当学生停留在复核页时，则页面显示剩余未核对的题目数量。

**F-11 识别过程中的等待反馈（S）**

- 假定系统正在识别手写内容，当学生等待时，则页面显示识别进行中的提示与进度，学生可判断系统仍在工作。

### 5.2 底部导航结构

**本次不改动底部导航**（保持现有结构）。复核页与报告页均为从首页进入的功能页面，不在底部导航中。

### 5.3 页面清单

| 页面名称 | 所属业务模块 | 优先级 | 页面业务说明 | 入口来源 |
|---|---|---|---|---|
| 复核页 | 诊断 | M | 展示系统认字原文，供学生核对与修改；确认后开始分析 | 同步完成后的自动跳转 |

```

│ [ 文本框 ]                   │
├─────────────────────────────┤

└─────────────────────────────┘
```

### 5.5 状态与边界

| 状态 | 表现 |
|---|---|
| 识别中 | 显示"正在识别手写内容…"与进度，学生可等待 |
| 识别完成 | 显示复核页，逐题卡片 |
| 某题没认出来 | 该题明确提示"这里没认出来"，不得显示为空白作答 |
| 识别失败 | 提示可重试，其余题不受影响 |
| 学生跳过 | 允许，报告标注"过程未经核对" |
| 修改后保存成功 | 提示"已保存"，该题标记为已核对 |
| 修改后保存失败 | 提示重试，不丢失已输入内容 |
| 无任何题目 | 显示空状态，引导返回首页 |

### 5.6 视觉与文案要求

- **全程不出现系统内部词汇**：不出现"转录""分段""断点""通/断"等词，一律用学生日常说法。
- **卡片单列展示**，不使用左右并排布局。
- **不确定处用颜色突出**，不使用感叹号等夸张符号。
- **文案示例**：
  - 识别中：「正在识别手写内容…」
  - 没认出来：「这里没认出来，你看一下原图补上」
  - 核对提示：「对着卷子看一眼，认错了就改」
  - 跳过提示：「没核对的题，报告里会标出来」

## 第 7 节：非功能需求

### 7.1 业务性能要求

| 项目 | 要求 |
|---|---|
| 复核页打开速度 | 学生无明显等待感 |
| 原图加载 | 点击后快速显示 |
| 保存修改 | 点击后立即反馈 |
| 单题重新分析 | 学生可接受等待，需有进度提示 |

### 7.2 安全与合规要求

- 答题卡原图**仅本人可见**，不得生成可被他人访问的链接。
- 学生的作答内容与修改记录不得公开展示。
- 不采集与诊断无关的个人信息。

### 7.3 可用性要求

- **断网可提示**：操作失败时明确告知"网络异常，请重试"，不丢失已输入内容。
- **失败不阻塞**：单题修改失败不影响其他题。
- **状态可恢复**：中途退出后重新进入，已完成核对的状态保留。

## 第 8 节：假设与风险 ⭐

### 8.1 假设条件

| 编号 | 假设 | 如果不成立的后果 |
|---|---|---|
| A-01 | 学生愿意在复核页停留并核对 | 修改率低，误判依旧发生 |
| A-02 | 认字结果多数正确，需要改的是少数 | 若多数都错，复核负担过重，学生会放弃 |
| A-03 | 学生能看懂系统标出的"不确定"提示 | 提示不起作用，等于没标 |
| A-04 | 学生能对照原图判断系统认得对不对 | 无法完成核对 |

### 8.2 风险清单

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| R-01 | 复核步骤让学生觉得麻烦，直接跳过 | 高 | 默认只突出"可疑处"，多数题一键确认；不强制逐字核 |
| R-02 | 学生看不懂数学公式的呈现 | 中 | 沿用现有公式呈现能力；提供大白话改写入口 |
| R-03 | 跳过复核导致错误结论进入报告 | 中 | 报告标注"未经核对" |
| R-04 | "没认出来"的提示被误解为系统故障 | 低 | 文案强调"看一下原图补上"，指向动作而非报错 |
| R-05 | 单题重判耗时让学生以为卡死 | 中 | 提供进度提示 |

## 第 10 节：发布策略 ⭐

### 10.1 发布方式

| 步骤 | 内容 | 目的 |
|---|---|---|
| 第一步 | 复核页显示认字原文 + "没认出来"提示 | 让学生第一次看到系统认了什么，并消灭"说我没写" |
| 第二步 | 修改后单题重新分析 + 报告"未经核对"标注 | 学生真正能纠错，且报告保持诚实 |

### 10.2 灰度策略

- 先在小范围学生上验证复核页的可用性与理解成本。
- 观察复核完成率与修改率，判断负担是否可接受。
- 通过后全量发布。

### 10.3 上线检查清单

- [ ] 复核页能显示认字原文（不再是空白）
- [ ] 题目与"你写的"分开显示
- [ ] 系统不确定处有明确标记
- [ ] 每题可查看答题卡原图
- [ ] 认错时修改流程 ≤ 3 步
- [ ] 修改保存后该题重新分析
- [ ] "没认出来"时不会显示为空白作答
- [ ] 跳过核对的题在报告中有标注
- [ ] 断网/失败有明确提示且不丢内容
- [ ] 中途退出后核对状态保留

## 第 11 节：名词解释与缩写

### 11.1 业务术语

| 术语 | 含义 |
|---|---|
| **认字** | 系统查看答题卡图片，把手写内容转成文字的过程（学生侧表述为"识别手写内容"） |
| **认字原文** | 系统认出来的文字，学生看到的"你写的"部分 |
| **不确定标记** | 系统标出自己没看准的地方，提示学生重点核对 |
| **复核** | 学生核对系统认字结果的环节（学生侧页面名为"题目核对"） |
| **核对完成** | 学生确认某题认字无误或已改正 |
| **未经核对** | 学生跳过的题，报告中会标注 |
| **答题卡原图** | 学生作答所在的扫描图片，供对照核对 |
