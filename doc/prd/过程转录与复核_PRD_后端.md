## 第 1 节：执行摘要

- **一句话定义**：本次改动让系统**把"看学生的答题卡图片、把上面的字认成文字"这件事单独做好一次并保存下来**，学生核对无误后，后续的所有判断都只基于这份文字，不再反复看图。
- **核心业务价值**：
  - 学生**第一次有机会纠正系统认错的字**——认错会导致整道题判错，这是当前最伤信任的问题。
  - 判断题目的对错时**不再需要重新看图**，处理更快、结果更稳定（同一份文字，判断结果可复现）。
  - 为后续"用学生写的过程去检验官方给分是否合理"打基础。
- **预期成功指标**：
  - 学生答题卡上的手写答案，被认成文字后**不再出现"分明写了却说没写"**的情况（当前至少有 1 例实测）。
  - 每道题**只看图一次**；同一道题重复判断时不再产生新的看图次数。
  - 复核环节中，学生能看到**认字原文**并进行修改（当前复核页看到的是空白）。

## 第 2 节：项目背景与目标

### 2.1 背景描述

系统的判断链路原本是：**拍下答题卡 → 认字 → 判定**。其中"认字"这一步一直是在"判定"发生的那一刻顺手做的，**做完就用掉了，不保存**。

这带来四个连锁问题：

1. **学生写了却被告知"没写"**：认字结果不保存，判定环节只看得到空的文字位置，于是把"写了但没认出来"误判为"整题空白未下笔"。实测中学生的填空答案「454」就这样消失了。
2. **认错字无人能纠**：认字结果不保存，学生复核时**无字可核**。实测中学生写的 `xy/(x−y)` 被认成 `1/(1/xy)`，这个错误直接导致判定结论偏离（系统认为"只差最后一步"，而老师实际扣了 5 分）。
3. **复核环节名存实亡**：复核页面在流程里存在，但它展示的三个内容全部来自"已保存的文字"，而认字结果从未被保存，所以页面是空的。
4. **成本随题量线性增长**：每判断一道题就重新看一次图，一份 19 道题的作业最多触发 19 次图像识别。

### 2.2 业务目标

| 目标 | 说明 |
|---|---|
| G1 | 学生写在答题卡上的内容，都能被保存成文字，不再"用过即弃" |
| G2 | 认字结果必须让学生先核对，学生确认后才进入判定 |
| G3 | 判定环节不再依赖看图，只依赖已确认的文字 |
| G4 | 认字时如果拿不准，必须显式标出来，不要假装确定 |
| G5 | 认字结果里，"题目"与"学生写的过程"必须是分开的两段 |

### 2.3 成功指标

| 指标 | 当前 | 目标 |
|---|---|---|
| "写了却判为空白"的错误 | 实测存在 | 0 例 |
| 每题看图次数 | 每次判定都看（可重复） | 每题 1 次（不重复） |
| 复核页可见的认字内容 | 空白 | 完整可见、可改 |
| 认字不确定处的标注率 | 无此机制 | 不确定处 100% 被标出 |
| 学生修改认字结果后，判定随之更新 | 不支持 | 支持 |

### 2.4 项目范围

**范围内：**

- 认字（看图转文字）独立成一步，结果保存。
- 认字结果拆分为"题目文字"和"学生过程文字"两段。
- 认字结果附带"不确定标记"。
- 判定只读取已保存且经学生确认的文字。
- 学生修改认字结果后，重新判定该题。
- 认字质量可被观测（多少处不确定、多少处被学生修改）。

**范围外：**

- 不改变答题卡图片的裁剪方式（裁剪经实测正确）。
- 不改变官方分数的权威地位（官方分仍是事实基准）。
- 不改变"一个学生只拍一次照"的采集约束。
- 不重做报告的视觉设计（另行立项）。
- 不新增任何要求学生额外操作的动作（核对既有认字结果不算新增采集，因为学生本就在复核环节停留）。

## 第 3 节：用户角色与场景

### 3.1 用户画像

| 角色 | 描述 | 本次关注点 |
|---|---|---|
| 学生 | 高中在读，用系统查看自己做题的对错与过程问题 | 系统认错我的字，我要能改 |
| 系统运营者 | 维护判定质量与成本 | 少看图、认字质量可观测 |

### 3.2 使用场景

**场景 A：学生写了答案，系统认出来了（正常路径）**

学生做完作业，系统认字后保存，学生在复核页看到"你写的：454"，确认无误，系统据此判定。

**场景 B：系统认错了字（本次要解决的核心场景）**

学生写的式子是 `xy/(x−y)`，系统认成 `1/(1/xy)`。复核页把认字原文摆出来，学生发现不对，改成正确式子，系统按改正后的内容重新判定。

**场景 C：系统完全没认出学生写的字**

学生明明在横线上写了答案，但认字结果为空。此时系统**不能**下"没写"的结论，而应标记为"未确认"，并在复核页提示学生补填。

**场景 D：学生跳过复核直接看报告**

系统使用未经核对的认字结果进行判定，但需在报告中标注"此题过程未经核对"，避免把不确定的结论当成确定的事实。

### 3.3 用户旅程

```
学生做完作业
   ↓
系统看答题卡图片 → 认成文字（题目 / 过程 分开）→ 保存
   ↓
学生进入复核 → 看到认字原文 → 逐题核对
   ├─ 无误 → 确认
   └─ 有误 → 修改（可用大白话让系统改写）→ 确认
   ↓
系统只依据已确认的文字判定
   ↓
生成报告
```

## 第 4 节：功能需求

### 4.1 业务流程

```
① 学生提交作业（已有能力）
        ↓
② 【新增】认字（独立一步，只做一次）
   · 输入：答题卡图片
   · 输出：题目文字 + 学生过程文字 + 不确定标记 + 认字可信度
   · 结果立即保存
        ↓
③ 【改造】复核
   · 展示上一步保存的认字原文
   · 学生核对 / 修改 / 确认
   · 记录哪些题被改过
        ↓
④ 【改造】判定
   · 只读已保存并确认的文字
   · 不再请求看图
   · 遇到"未确认"的内容要显式标注，不得当作确定事实
        ↓
⑤ 生成报告（已有能力，本次不改）
```

### 4.2 功能列表

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 认字独立执行并保存结果 | M | 每道题只执行一次；已存在结果时直接复用 |
| F-02 | 认字结果拆成"题目"与"学生过程"两段 | M | 图片里两者混在一起，认字时必须分开输出 |
| F-03 | 认字时标注不确定之处 | M | 拿不准的字符/式子要显式标出，不得含糊带过 |
| F-04 | 认字结果带可信度标记 | M | 用于判定环节决定"能否下确定结论" |
| F-05 | 判定只读文字、不读图 | M | 成本与稳定性的关键 |
| F-06 | 学生修改认字结果后单题重新判定 | M | 只重判该题，不重跑整批 |
| F-07 | "未确认"内容不得被判为"空白" | M | 修复"写了却说没写"这一实测缺陷 |
| F-08 | 记录认字被修改的情况 | S | 用于观测认字质量 |
| F-09 | 认字质量统计（不确定率 / 修改率） | C | 供运营查看 |

### 4.3 权限逻辑

| 操作 | 学生 | 系统运营者 |
|---|---|---|
| 查看自己的认字结果 | ✅ | ✅ |
| 修改自己的认字结果 | ✅ | ❌ |
| 查看他人的认字结果 | ❌ | ✅ |
| 查看认字质量统计 | ❌ | ✅ |

### 4.4 验收标准

> 覆盖全部 M 级与 S 级功能。每条以"假定 / 当 / 则"描述业务行为与业务结果。

**F-01 认字独立执行并保存结果（M）**

- 假定某道题尚未认过字，当系统处理该题时，则系统执行一次认字并把结果保存下来。
- 假定某道题已经保存过认字结果，当系统再次需要该题的文字时，则系统直接读取已保存的结果，不重新执行认字。
- 假定系统需要同时处理 19 道题，则每道题各自认字一次，同一道题不重复认字。

**F-02 认字结果拆成"题目"与"学生过程"两段（M）**

- 假定一道题的图片上同时印有题目和手写作答，当完成认字时，则产出的内容中"题目文字"与"学生过程文字"是两个独立部分，可分别读取。
- 假定某题是客观题（只有答案没有过程），当完成认字时，则"学生过程文字"为空，"题目文字"仍有内容。

**F-03 认字时标注不确定之处（M）**

- 假定图片上某处字迹模糊，当完成认字时，则该处被标记为不确定，且不因为不确定而省略该处内容。
- 假定整道题字迹都清晰，当完成认字时，则不确定标记数量为 0。

**F-04 认字结果带可信度标记（M）**

- 假定某题存在不确定标记，当进入判定时，则判定能读到该题"内容不确定"的状态，并在结论中体现不确定性。

**F-05 判定只读文字、不读图（M）**

- 假定某题已有保存的认字结果，当执行判定时，则判定过程不访问该题的答题卡图片。
- 假定同一道题被判定两次且中间无人修改文字，则两次判定使用的输入内容完全一致。

**F-06 学生修改认字结果后单题重新判定（M）**

- 假定学生修改了第 17 题的认字结果并保存，则第 17 题的原有判定结论作废并重新生成，同批其他题的判定结论不变。
- 假定学生修改后重新判定完成，则报告的展示内容与该题最新结论一致。

**F-07 "未确认"内容不得被判为"空白"（M）**

- 假定某题的作答内容处于不确定或未确认状态，当执行判定时，则不得给出"整题空白未下笔"的结论。
- 假定某题学生确实完全没有作答，当执行判定时，则可以给出"整题空白未下笔"的结论。

**F-08 记录认字被修改的情况（S）**

- 假定学生修改了某题的认字结果，则系统记录该题、被修改的部分、修改前后的内容，且原始认字结果不被覆盖。

**F-09 认字质量统计（C）**

- 假定运营者查看某日的认字质量统计，则能看到当日的认字成功数、不确定处数量、被学生修改的题目数量。

## 第 5 节：业务规则与数据规范（后端专属）

### 5.1 核心业务规则

| 规则编号 | 业务规则描述 | 适用场景 | 违反后果 |
|---|---|---|---|
| BR-001 | 同一道题的认字（看图转文字）**只执行一次**；已有认字结果时直接复用，不重复执行 | 判定、重新判定 | 重复认字将导致同一道题的文字内容漂移，判定结果不可复现 |
| BR-002 | 认字结果**必须**拆分为"题目文字"与"学生过程文字"两个独立部分，不得混为一段 | 认字 | 二者混在一起会使判定无法区分"这是题目"还是"这是学生写的" |
| BR-003 | 认字遇到拿不准的内容，**必须**显式标注为不确定，不得默认为正确 | 认字 | 伪装确定的错误认字会直接污染判定结论 |
| BR-004 | 判定**只允许**读取已保存的认字文字，**禁止**在处理判定时重新看图 | 判定 | 成本回升，且判定结果不再可复现 |
| BR-005 | 当某题的作答内容处于"未确认"状态时，**不得**判为"整题空白未下笔" | 判定 | 会把"系统没认出"错报成"学生没写"，实测已发生过 |
| BR-006 | 学生修改认字结果后，**该题**的判定结论必须作废并重新生成；同批其他题不受影响 | 复核修改 | 沿用旧判定会产生自相矛盾的报告 |
| BR-007 | 判定使用的文字必须可追溯来源：标明是"系统认字结果"还是"学生修改后的结果" | 判定、报告 | 无法区分事实与学生主张，数据失去可追溯性 |
| BR-008 | 官方分数的权威地位不变；本次改动不改变对错的事实来源 | 判定 | 动摇事实基准会使全盘数据不可信 |
| BR-009 | 某道题**没有答题卡图片**（客观题、或来源未提供图）时，不生成认字结果；该题按"无过程材料"处理并显式标注，**不得**据此判为"整题空白未下笔" | 认字、判定 | 把"没有材料"误报成"学生没写"，与 BR-005 属同类错误 |
| BR-010 | 判定结论与官方给分差异超过约定阈值时，该题必须被标记为"待复查"，并在报告中如实呈现差异，不得静默掩盖 | 判定、报告 | 静默掩盖会让"认字错导致的误判"永远不可见（实测已发生） |

### 5.2 业务数据规范

- **数据保留策略**：认字结果与学生修改记录需长期保留，与学生的做题记录同生命周期；修改记录用于追溯判定依据的变化。
- **数据归档规则**：认字结果不单独归档，随所属作业批次一并归档。
- **数据清理规则**：学生主动删除某次作业时，其认字结果与修改记录一并删除。
- **数据一致性要求**：
  - 一道题的认字结果、学生修改记录、判定结论三者必须能互相追溯。
  - 学生修改后，判定结论与报告展示内容必须同步更新，不允许出现"报告显示旧的、数据已是新的"。

### 5.3 业务流程约束

- **认字必须在判定之前完成**：判定环节不得触发认字。
- **复核在判定之前**：学生确认（或明确跳过）后，才进入判定。
- **单题可重判**：学生修改某题的认字结果时，只重判该题。
- **失败可重试**：认字失败时该题保持"未完成"状态，可单独重试，不阻塞整批。

## 第 6 节：数据需求

### 6.1 数据埋点

| 埋点事件 | 触发时机 | 记录内容 |
|---|---|---|
| 认字开始 | 每道题开始认字 | 题目标识、图片来源 |
| 认字完成 | 认字成功 | 耗时、题目文字长度、过程文字长度、不确定处数量 |
| 认字失败 | 认字异常 | 失败原因、是否可重试 |
| 认字被复用 | 命中已有认字结果 | 题目标识（用于验证"只做一次"） |
| 复核查看 | 学生进入复核页 | 题目数量、其中带不确定标记的数量 |
| 认字被修改 | 学生保存修改 | 题目标识、修改了哪个部分、修改前后长度 |
| 判定开始/完成 | 判定执行 | 题目标识、耗时、是否使用了未经核对的认字结果 |

### 6.2 数据报表

| 报表 | 用途 | 关键指标 |
|---|---|---|
| 认字质量日报 | 监控认字是否可靠 | 认字成功率、不确定率、学生修改率、修改幅度 |
| 认字成本日报 | 监控看图次数 | 每日看图次数、题均看图次数（目标 ≤ 1） |
| "空白误判"监控 | 验证 BR-005 生效 | 被判"空白"但实际有作答的题数（目标 0） |

### 6.3 数据迁移

- 存量题目没有认字结果，**不做批量补认**（成本高且历史价值有限）。
- 存量题目在需要重新判定时，按新流程补做认字。
- 存量数据中已被误判为"整题空白未下笔"的记录，**列入待清理清单**，由运营确认后逐条处理，不自动批量修改。

## 第 7 节：非功能需求

### 7.1 业务性能要求

| 项目 | 要求 |
|---|---|
| 单题认字耗时 | 学生无明显等待感 |
| 判定耗时 | 相比现状不增加（因不再看图，应更快） |
| 单批处理时长 | 不因新增认字步骤而显著变长（认字与判定串行，但各只做一次） |
| 并发能力 | 支持同时处理多道题，且不因资源竞争导致失败 |

### 7.2 安全与合规要求

- 学生的答题卡图片与认字文字**仅本人及系统运营者可访问**。
- 认字文字中不得包含答题卡图片的公开可访问链接。
- 学生修改记录需保留来源标识，不得篡改原始认字结果（原始结果与修改结果并存）。

### 7.3 可用性要求

- **认字失败不阻塞整批**：单题认字失败时，该题标记为待重试，其余题正常流转。
- **判定服务不可用时立即停止**：不得用剩余题目反复撞击不可用的服务。
- **认字结果持久可用**：认字成功后，即使图片链接失效，文字内容仍可用于判定。

## 第 8 节：假设与风险 ⭐

### 8.1 假设条件

| 编号 | 假设 | 如果不成立的后果 |
|---|---|---|
| A-01 | 答题卡图片上的手写内容可以被认成文字，且多数情况准确 | 认字质量不达标，复核环节负担过重 |
| A-02 | 学生愿意在复核环节花时间核对 | 大量题目跳过核对，误判依旧发生 |
| A-03 | 图片中"题目"与"学生过程"可以被可靠区分 | BR-002 无法落地，两者仍混在一起 |
| A-04 | 判定环节确实不需要看图（文字已足够） | 判定质量下降 |
| A-05 | 官方分数与系统判断的差异，可以作为"值得复查"的信号 | 无法发现类似本次实测的判定偏差 |

### 8.2 风险清单

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| R-01 | 认字准确率不够，复核变成学生的负担 | 高 | 优先保证"不确定处必须标出"，让学生在少数可疑处集中核对；并观测修改率 |
| R-02 | 学生直接跳过复核 | 中 | 报告中标注"过程未经核对"；不强制，遵守采集零新增 |
| R-03 | 认字只做一次，若第一次就错且学生没发现，错误被固化 | 中 | 保留"重新认字"入口；判定与官方分差异大时提示复查 |
| R-04 | 存量数据无认字结果，新旧流程并存 | 中 | 存量题在重新判定时补做；不批量补，避免成本失控 |
| R-05 | 判定不再看图后，某些依赖图像细节的判断（如涂改痕迹）能力下降 | 中 | 认字时要求把"涂改/圈画"等痕迹一并描述，作为文字保留 |
| R-06 | 已被误判"整题空白"的历史记录未清理，报告中残留错误结论 | 低 | 列入待清理清单，运营确认后处理 |
| R-07 | 某道题没有答题卡图片（客观题或来源未提供图），认字无从进行 | 中 | 见 BR-009：无图题不生成认字结果，判定按"无过程材料"处理并标注，不得据此判"空白" |
| R-08 | 认字结果与学生修改之间的差异长期无人关注，认字质量劣化不可见 | 中 | 设"认字修改率"观测指标；修改率异常升高时触发认字质量排查 |
| R-09 | 判定与官方给分差异大时，系统既可能冤枉学生（认字错），也可能低估学生错误（如实测中系统判"只差一步"而官方扣 5 分） | 高 | 差异超阈值时标记该题为"待复查"，在报告中提示，并作为认字质量的检验信号 |

## 第 9 节：约束与依赖

### 9.1 业务依赖

| 依赖 | 说明 |
|---|---|
| 答题卡图片可获得 | 认字的前提；当前已有能力 |
| 官方逐题分数可获得 | 用于与系统判断比对，发现偏差 |
| 复核页面已存在 | 本次改造而非新建 |
| 报告生成能力已存在 | 本次不改造 |

### 9.2 业务约束

- **采集层零新增**：不得要求学生多拍、多填、多说；核对既有内容不算新增采集。
- **官方分数为事实基准**：系统判断不得覆盖官方分数（除学生明确说明官方有误）。
- **只做解答题的过程审阅**：客观题没有过程，认字只需取其答案。

### 9.3 合规约束

- 学生数据仅限本人与运营者访问。
- 学生的修改主张需留痕，与系统原始结果并存，可追溯。

## 第 10 节：发布策略 ⭐

### 10.1 发布方式

分两步发布，先保证"不再误判空白"，再启用完整流程：

| 步骤 | 内容 | 目的 |
|---|---|---|
| 第一步 | 认字结果保存 + 判定不再看图 + 修复"写了却判空白" | 先止血，消灭最伤信任的错误 |
| 第二步 | 复核页展示认字原文 + 学生修改后单题重判 | 让学生真正能纠错 |

### 10.2 灰度策略

- 先在单份作业上验证：认字准确率、判定与官方分的差异、复核可用性。
- 验证通过后，逐步放开到全部新作业。
- 存量作业不回溯处理（除待清理的误判记录）。

### 10.3 上线检查清单

- [ ] 认字结果确实被保存，且再次判定时被复用（看图次数不增加）
- [ ] 认字结果中"题目"与"过程"是分开的两段
- [ ] 不确定处被显式标出
- [ ] 判定环节不再触发看图
- [ ] "未确认"内容不会被判为"整题空白未下笔"
- [ ] 复核页能显示认字原文
- [ ] 学生修改后该题判定被重新生成
- [ ] 学生修改后，报告展示与数据一致
- [ ] 认字失败不阻塞整批
- [ ] 认字质量埋点数据可查

## 第 11 节：名词解释与缩写

### 11.1 业务术语

| 术语 | 含义 |
|---|---|
| **认字** | 系统查看学生的答题卡图片，把上面的印刷题目与手写内容转成文字的过程 |
| **认字结果** | 认字产出的文字，分为"题目文字"与"学生过程文字"两部分 |
| **不确定标记** | 系统认字时对自己拿不准的内容所做的显式标注 |
| **复核** | 学生查看系统认字结果、核对并修改的环节 |
| **判定** | 系统根据题目与学生作答，给出对错、过程问题与错因的过程 |
| **官方分数** | 学校老师在智学网上给出的批改分数，作为事实基准 |
| **整题空白未下笔** | 系统的一种判定结论，指学生完全没有作答；本次要修复的是它被误用 |
| **答题卡图片** | 学生作答所在的扫描图片 |
| **认字可信度** | 系统对本次认字整体准确程度的自我评估 |
