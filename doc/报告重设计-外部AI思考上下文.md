# 报告重设计 · 外部思考上下文

> 用途：本文档是自包含的最小上下文，供与外部 AI 一起从零重新设计「诊断报告」。
> 日期：2026-08-30 · 状态：旧版报告设计已判弃用，重设计推导中
> 说明：文中所有英文字段名均为系统真实字段（实码核实），术语表在文末。

## 1. 产品是什么

- 微信小程序「AI 学习诊断助手」：学生拍数学作业照片 → AI 转录拆题 → 逐题判定（对错/难度/归因/断点）→ 生成诊断报告
- 用户：产品作者本人（高中生）+ 120 名同学（9/1 体验版上线）
- 核心链路：拍照上传 → 视觉转录 + 自动切题（单题裁剪图）→ 学生复核 → 逐题判定 → 报告生成
- 判定引擎输出：每题的对错（连续过程分 P）、难度 D、错因一句话、错因维度（K/A/T/Q/S）、过程分段（每段 通/断/空白 + 原文证据）、断点位置、知识点使用清单、题型三层结构——这些是报告的「确定事实」

## 2. 为什么重设计（用户原话与决策）

- 用户原话：**全方面，很多地方是针对单一问题的过拟合了，也过拟合了认知科学**
- 解读：①每条设计规则都是某个具体问题/评审样本的补丁，补丁摞补丁；②认知科学概念（断点、根因、钩子、自我效能、蔡格尼克）直接变成了模块结构——理论驱动而非学生场景驱动
- 决策：**底层管线全部不变**（判定/检索/采集/接口/数据库），报告的模块组织、提示词、渲染层**全部推倒重设计**
- 时间：**9/1 直接换新版上线**（约 2 天窗口：设计定稿 → systemV3 重写 → 渲染层重写 → 验证）

## 3. 旧版报告结构（要推倒的现状，简要）

- **回执层**（overview）：战绩一行 + 情绪半句 + 主结论一句 + 模式列表 + 预期管理 + 状态照顾，共 5 件套
- **深读层**：以「主错误模式」为中心展开四段式——断点 → 根因 → 钩子（提问不给答案）→ 行动检验；次模式只折叠预览；三步导航逐步看
- **按需模块**：单题历史演化（每题入口，点击才生成）；异议机制（每模块可点「我有异议」触发重生成）
- **旧版哲学**：明白 = 看见断点 → 理解根因 → 顿悟内化；成绩提高是副产品；永不给答案
- **旧版生成原则**：13 条（证据硬规则/判断权在学生/禁给答案/禁模板/认知负荷两层/情绪真实/禁数值指标/空白禁令/禁复述归因/历史看见重复…）——每条都是某个样本问题后的补丁
- **旧版生成机制**（可保留的机制层）：LLM（DeepSeek V4 Flash）+ 4 个检索工具（历史同类题向量检索/错误模式聚合/趋势/知识点历史）+ 注入确定数据 + 确定性清洗层（正则改写毒点）+ 前端实时进度推送

## 4. 重设计可用的全部输入（数据面，全部实码核实）

### 4.1 每题级（判定产出，报告的核心原料）

| 输入 | 内容 |
|---|---|
| questionText | 题面转录全文（LaTeX 公式可渲染） |
| cropFileID | 单题裁剪图：学生真实笔迹照片（含涂改/圈画/答案），自动切题产出 |
| traceReport | 做题痕迹的文本转录 |
| segments[] | 过程分段：每段 {摘要, 状态=通/断/空白, 原文证据片段} |
| breakpoint | 断点：{断在第几段, 性质=起步即停/中途断/收尾断} |
| processScore (P) | 过程分 0~1 连续值，≥0.5 即答对（无独立对错字段） |
| difficultyValue (D) | 题目难度 0~1 |
| eta | 路径质量 0~1（仅解答题） |
| errorAttribution | 错因一句话（只写可观察事实，如「分类讨论遗漏 B={-2}」） |
| errorDimension | 错因维度 K/A/T/Q/S |
| knowledgeUsage[] | 知识点使用清单：{名称, 该环节作答质量 1/0.5/0, 环节难度} |
| knowledgeNodeName | 映射到的知识点（教材术语，361 节点图谱） |
| pattern | 题型三层 {知识板块, 中粒度题型, 变体} |
| questionType | 选择/填空/解答/其他 |
| isOutOfSyllabus / isRecallQuestion | 超纲标记 / 回忆类标记 |
| reviewed + revisions[] | 复核状态 + 学生修正历史 |
| processAvailable | 过程可信标记（空白/涂改乱 = false） |

### 4.2 批次级

- 本次统计：总题数/对数/正确率（P≥0.5 计对）
- 上次批次正确率对比 → 趋势（±0.1 判升降）
- 生成过程真实进度（可实时推送）

### 4.3 历史/画像级（跨批次自动积累）

| 数据 | 内容 |
|---|---|
| mastery_logs（判题即写，每题一条） | 判定快照全字段 + 语义向量 ×2（整题 + 题型）——历史检索的唯一燃料 |
| knowledge_progress | 每个知识点：掌握度（加权得分法 Σ得分/Σ难度）、作答次数、对数 |
| unit_progress | 单元级应用能力数据 |
| 历史同类题检索 | 按题型向量近邻（0.70 阈值）捞历史题：相似度/对错/错因/断点/分段 |
| 错误模式聚合 | 近 30 天错题按知识点分组：次数/最近出现/最近错因/时间线 |
| 趋势 | 正确率前后半段对比 |
| 知识点历史 | 单知识点掌握度逐次变化序列 |
| 题型轨迹 | 每类题的断点移动序列（起步即停→中途断→收尾断→做对） |
| 全局掌握度 | Σ得分/Σ难度 + 最弱知识点排名 |
| 知识图谱 | 361 个教材知识点节点 + AI 提炼的自定义节点 |

### 4.4 还没有的输入（想用需先建采集）

- 学生自述（「你觉得自己哪不会」——从未采集）
- 做题时长（无法算执行稳定性）
- 订正行为追踪（看完报告后是否订正、结果）
- 同题重做识别

## 5. 硬约束（重设计不可违背的边界）

1. 底层不变：判定产出字段、4 个检索工具、数据库集合、云函数接口形态均保持
2. 客户端能力：LaTeX 公式渲染（rich-text）、图片、折叠/导航、实时进度推送、按需触发的二次生成
3. 生成机制保留：LLM + 检索工具 + 注入确定数据 + 确定性清洗层——但提示词内容随新模块全重写
4. 旧报告不兼容：反正会清空重传，新 schema 可不兼容旧报告
5. 可信底线建议保留（是否算过拟合由思考判断）：结论必须引用学生过程原文（防编造）；异议出口（学生可纠正 AI）

## 6. 开放问题（请外部 AI 重点思考）

1. 报告的第一性职责：学生拍照后等 2 分钟拿到报告——从那一刻到离开页面，理想体验的完整动线是什么？报告应该回答学生的哪几个问题、按什么顺序？
2. 组织中心：以「题」为中心 / 以「错误类型」为中心 / 以「知识点」为中心 / 混合？各自的信息流长什么样？
3. 给不给答案：分级提示（标卡点→要点拨→关键步骤，学生自己选深度）/ 坚决不给 / 直接给？「防依赖」这个担心本身成立吗？
4. 认知科学的正确用法：概念应该隐式指导文案，还是可以显式成为结构？边界在哪？
5. 聚合的价值：「这几道题是同一类问题」这类聚合，对学生有没有价值？放在哪？还是完全删掉？
6. 过程呈现：单题裁剪图（真实笔迹）/ 文本分段 / 图文结合？
7. 单题历史演化与报告主体的关系：独立入口保留 / 并入卡片 / 删除？

## 7. 已被否的推导（避免外部 AI 重复掉坑）

AI 协作者此前的推导：「一句话结果 → 错题卡（以题为中心）→ 同类线索折叠 → 下一步动作」，并建议保留「证据引用/异议/数值禁令」三条底线。

用户判定：**大方向不对，推导过程不太对**（具体原因用户未说明，正在自行思考）。已知线索：用户认为旧版「全方面过拟合」——既过拟合具体问题，也过拟合认知科学理论。因此：

- 不要以「修补旧结构」的思路推导
- 也不要默认保留旧哲学框架（用户选择「连哲学一起重新想」——从「学生拿到报告后要做什么」重新出发）
- 用户的思考会另行补充，本节仅声明：上述结构已被否

## 8. 术语表

| 术语 | 含义 |
|---|---|
| P | 过程分 0~1（≥0.5 答对，无独立对错字段） |
| D | 题目难度 0~1 |
| K/A/T/Q/S | 知识掌握/应用/迁移/思维品质/执行稳定（五维能力模型） |
| 断点 | 学生过程里「从哪一步开始走不通」 |
| 切题 | 把整页照片按题自动裁成单题图 |
| 毒点 | 报告中 LLM 编造/复读归因/无中生有的句子 |
| 清洗层 | LLM 输出后、入库前的代码确定性改写 |
| 复核 | 学生在判定后、报告前，逐题确认/修正 AI 的转录与判定 |
| 体验版 | 微信小程序的内部测试分发方式 |
