## 三、分类评审结果

### 3.1 系统边界与模块划分 ✅
- 模块职责清晰：photoUpload / diagnose / dispute / clamp / graphService，单一职责
- 接口契约定义：5 端点覆盖 F-001~F-010 功能
- 上下游关系明确：小程序 ↔ 云函数 ↔ 外部 AI（同步调用）
- 数据所有权明确：questions 由 diagnose/dispute 写入，mastery_logs 仅追加

### 3.2 非功能属性 ✅
- 响应时间：单题 ≤60s、整批 ≤3min（已量化）
- 成本：月 <30 元（120 学生，已量化）
- 安全：openid 隔离 + key 仅存环境变量 + HTTPS（CloudBase 默认）✅
- 数据一致性：BR-002 追加修正兜底 ✅
- 其余高可用/并发/容灾类 → MVP 豁免，降 P2

### 3.3 单点故障分析 ⚠️（P2）
- 外部 AI 不可用：降级方案含描述（C2 + 重试）但无显式熔断超时设计 → P2
- 诊断重复提交：无幂等标记 → P2
- 云存储/文档数据库：CloudBase 托管服务，单区域（MVP 可接受）

### 3.4 技术选型 ✅
- Qwen3.7Plus：有替代方案对比（OCR 专精模型 vs 多模态实测完败），选型依据充分
- DeepSeek：rubric 治漂移 POC 实证
- CloudBase 云函数：与现有项目一致 + 零运维
- 所有组件含"为什么选/为什么不选其他/已知权衡" ✅

### 3.5 数据一致性 ✅
- 跨服务事务无（单函数编排，无需分布式事务）
- 缓存一致性问题无（无缓存层）
- 幂等设计缺失 → P2
- 数据迁移无（空库新建，图谱一次性导入）

### 3.6 安全性 ✅
- 认证：沿用现有微信登录（userLogin 云函数），openid 校验
- 权限：数据按 userId 隔离，仅本人可读
- 加密：key 存环境变量，不入 git（.env 已 gitignore）
- 传输：CloudBase 默认 HTTPS

### 3.7 轻量向上追溯（SAD → PRD）
| PRD 功能 | SAD 对应 | 状态 |
|---------|---------|------|
| F-001 拍照批次接收 | photoUpload + API 端点 | ✅ |
| F-003 对错判定 | diagnose 管线（judge 模块） | ✅ |
| F-005 难度分档 | clamp 模块（L1~L11 钳制） | ✅ |
| F-009 异议重诊 | dispute 模块 + API 端点 | ✅ |
| F-010 图谱数据 | graphService + knowledge_nodes | ✅ |
| NFR 单题 ≤60s | §12 性能优化（并行化 + enable_thinking:false） | ✅ |

无误漏映射。
