## 1. 总评（给接手人的一句话）

叙事主线正确（同卷会做 vs 空白 → 第一步没发生），但**判定层的「未理解」仍渗进根因**，且对无过程题**证据不足却写成确定结论**——这是内容可信度的主伤，优先修管道，不是再拧文案模板。

## 3. 硬伤清单（按优先级）

### P0-1：根因复读「未理解××」（打脸）

- **位置**：`weakpoints[0].rootcause.directCause`
- **原文要点**：仍写「判定给出的归因：例 2 是『空白未作答，**未理解**复合函数定义域求解方法』……」
- **问题**：总结/断点全文在说不是不会，根因又把错误标签当权威引用。
- **改法**：
  - `reportService` 生成时：若注入的 `errorAttribution` 含「未理解 / 没理解 / 不会××」，**禁止原样写入** `directCause`；改写为可观察事实或「原因待确认」。
  - 与 `systemV3.js` 已有「空白禁令 / 禁止复述未理解」对齐，检查是否未生效或旧报告未重生。
- **涉及文件**：`cloudfunctions/reportService/systemV3.js`、`assemble.js` / 生成主流程；可选前端二次清洗（已有部分 sanitize，但旧字段仍可能漏网）。

### P0-2：无过程题写成知识层「直接原因」

- **位置**：同薄弱点 `breakpoint.processAvailable === false`，`segments: []`
- **问题**：无书写痕迹时，仍用例 2 讲复合函数认知故事并写成「直接原因是……」。教学假设可以，观测事实不行。
- **改法**：
  - `processAvailable === false`（或整题空白）时：
    - **禁止**伪装分段断点；
    - `directCause` 上限 = 可观察现象 +「原因待确认」；
    - `sources` = **2～3 个并列假设**（未认出题型 / 知道但没下笔 / 跳过），判断权给学生；
    - 同卷同类做对必须写成**能力证据**，用于压低「知识缺失」先验。

### P0-3：无工具结果却写历史叙事

- **位置**：`rootcause.history === null`，但 `closing` 写「检索记录显示……一直很稳……第一次集中暴露」
- **问题**：违反证据硬规则（指不到工具结果不写）。
- **改法**：`history` 为空时，closing **禁止**「检索/历史一直很稳」类句子；走降级：「若这是第一次集中出现，也先把这一步找回来」。

### P1-1：例 1 与例 2 揉成同一断点（分辨率不足）

- **现象**：例 1（分式/根式指数定义域）与例 2（复合 \(f(2^x)\)）认知动作不同，却合成一个主薄弱点。
- **影响**：钩子第 2 问只服务例 2；例 1 被捎带。
- **改法（产品可选）**：
  - 方案 A：同一 pattern 下分 `variants` / 两道题各自一段 contradiction；
  - 方案 B：拆成两个弱模式，主攻仍可选「空白」痛感更强的那个，但文案勿混成一个「直接原因」。

### P1-2：有过程的值域题被压成 secondary

- **现象**：值域题有过程、「减函数」痕迹、收尾断——证据强于两道空白；却仅 secondary 预览。
- **改法**：主模式选择加入**证据强度**权重；或主攻空白时明示「本次主攻偏对照推断，另有一道证据更硬的收尾断已记下」。

### P1-3：钩子与根因同义反复 + 题量偏多

- **库内**仍为 3 问；前端可截 2 问，生成侧应直接 ≤2。
- 第 1 问与 rootcause「不会还是没敢」高度重复。
- **改法**：生成约束 `hook.questions` 最多 2；且不得与 `directCause` / `sources` 同义反复。

### P2：「第一步没发生」略万能

- 对空白几乎总能这么说；若不区分「没认出」vs「执行未启动」，可迁移性差。
- **改法**：与 P0-2 并列假设绑定，避免单一万能句当根因标题。

| 原则 | 样本表现 | 目标 |

## 5. 建议改动顺序（给实现者）

1. **报告生成清洗层**（不依赖重新判定即可改善新报告）  
   - 禁「未理解」入库文案；空白题根因模板；history 空则禁历史叙事。  
2. **确认 judgeOne 空白禁令**是否已部署且新判定生效（旧题需重判才干净）。  
3. **主模式 / 多题分辨率**（P1，可第二迭代）。  
4. **钩子 ≤2 + 去重**。  
5. 可选：对样本 `reportId` 跑一次 `disputeModule` 或重生报告做验收。

### 验收标准（重生或新批次）

- [ ] `directCause` / 全文无「未理解××方法」作为空白默认归因  
- [ ] `processAvailable === false` 时根因是并列假设，非单一知识结论  
- [ ] `history === null` 时 closing 无「检索显示一直很稳」类编造  
- [ ] `hook.questions.length ≤ 2`  
- [ ] 同卷同类做对仍作为能力锚点出现在断点或根因
