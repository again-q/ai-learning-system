## 六、P1 详情

### CR-P1-01：抢救判据与正常路径口径不一致（业务规则遗漏）

**位置**：`miniprogram/pages/photo/photo.js` — `recoverDiagnoseBatch()`

**问题**：初版抢救实现以「题目总数 > 0」判定可进复核页。但 `diagnose` 在**视觉识别失败时同样会入库**，且 `status` 为 `'failed'`：

```js
// cloudfunctions/diagnose/index.js（vision 失败分支）
questions.push({ questionId: qIns._id, status: 'failed', error: vr.error });
```

而正常（未中断）路径按 `status === 'pending'` 过滤后才判断能否进复核页：

```js
// photo.js 正常路径
const pendingQ = (diagData.data.questions || []).filter((q) => q.status === 'pending');
const total = pendingQ.length;
if (total === 0) { /* 提示「未识别到题目，请换清晰照片后重试」 */ }
```

**后果**：一张照片全部识别失败的批次，走正常路径会提示「未识别到题目」，而走**抢救路径会被错误地导入复核页**——复核页将展示零条可用题目（或残缺条目），用户看到空页面却得不到解释。同一业务状态**两条路径行为分叉**。

**等级判定依据**：属「业务规则遗漏」（P1），非 P0（不造成数据丢失或安全问题）。

**修复**（已实施）：

```js
// 返回 {total, pending}；pending 按 status==='pending' 过滤，与正常路径 pendingQ 同口径
total = r.data.length;
pending = r.data.filter((q) => q.status === 'pending').length;
// ...
if (total > 0 && key === lastKey) return { total, pending };
```

```js
// 调用侧
if (rec && rec.pending > 0) { /* 跳复核页 */ return; }
if (rec && rec.total > 0) {
  // 全部识别失败：与正常路径同口径提示
  this.setData({ analyzing:false, submitting:false, pipelineError: '未识别到题目，请换清晰照片后重试' });
  return;
}
```

**同步更新**：`doc/detailed/小程序_拍照页.md` §7 抢救判据已改为「两重判据」并说明理由。

**复验**：`node --check` 通过；详设 §7 与代码逐条对照一致；稳定判据键由「题目数」改为「总数:待判定数」，可识别"总数不变但 pending 变化"的中间态（更严格）。
