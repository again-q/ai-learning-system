## 二、整体架构（当前形态）

```
📸 拍照（≤9 张）
  ↓
① photoUpload：收 fileIds → 校验归属 → 建批次（pending）
  ↓
② diagnose：Qwen 视觉转录（并行）→ AI 拆题（v4-flash disabled）→ 建 pending 题 → 批次 analyzing
  ↓
③ 前端进度条：拆题 5% → 逐题 10-95%（1/8…8/8）→ 100%
  ↓
④ judgeOne（并发 2）：单题判定（v4-flash + thinking enabled + reasoning_effort high）
    → RAG 检索历史 → 完整版标尺判定 → clamp → 更新题 + 报告+embedding 入库
    → 每题更新批次 progress，最后一题 → 批次 completed
  ↓
⑤ 报告页：逐题卡片（对错/难度Lx/D/题型/η/归因）+「我觉得不对」异议
  ↓
⑥ RAG 闭环：下次诊断检索本次报告 → 越用越懂
```

## 三、5 个云函数

| 云函数 | 职责 | 关键实现 |
|--------|------|---------|
| photoUpload | 收图+批次 | fileIds 归属校验（`/photos/{openid}/`） |
| diagnose | 转录+AI拆题+建题 | Qwen 并行转录 → v4-flash disabled 拆题 → 建 pending 题 |
| judgeOne | 单题判定+RAG+入库 | v4-flash + enabled + effort high；括号配平提取 JSON；clamp；报告+embedding |
| dispute | 异议单题重诊 | 修正落 revision → 重判 → keptOriginal 降级 |
| graphService | 图谱/报告查询 | getGraph + getReport（orderBy createdAt） |

## 四、关键设计决策（本轮沉淀）

| 决策 | 内容 |
|------|------|
| 模型名 | `deepseek-v4-flash`（chat/reasoner 已弃用）；**无 v4-max 模型** |

## 八、已踩的坑（避免重蹈）

1. `clampParams` 字段名与模型输出不匹配（level/D/P/eta vs difficultyLevel/...）→ D 恒 0.01
2. 批量判定 content 空（reasoning 吃光 token）→ 拆题逐题
3. JSON 提取用 lastIndexOf(`{`) 命中 prompt 示例 → 括号配平
4. thinking:enabled 的 reasoning 会复述长标尺 → 精简标尺
5. low 档会把"OCR 前缀误读"当学生真错 → effort high
6. 门禁 hook 曾超时（python3 冷启动 ~6s）→ 编辑重试/批量
