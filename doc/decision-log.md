## 决策 010：知识图谱构建经验总结

### 🔴 TOC 页码偏移（最贵的一课）

**问题**：TOC 记录教材印刷页码，PDF 物理页码偏移 +6，直接按印刷页码跑 OCR 导致 155 页全错，重跑浪费数小时。

**预防**：OCR 前必须用 PyMuPDF 验证 TOC 页码与 PDF 物理页的偏移量，每章第一页检查内容是否含章节标题。

### 🔴 AI 生成的 JSON 内引号问题

**问题**：Agent 2 输出的 JSON 字符串内部包含 ASCII `"`（如 `称为"补集"`），破坏 JSON 结构。

**根因**：大模型在中文上下文中使用 ASCII 双引号作为中文引号，而 JSON 要求内层引号转义或使用 `「」`。

**修复**：Python 正则 + 逐行字符扫描替换内层 `"` 为 `「」`。

**预防**：Agent 2 Prompt 应明确要求「JSON 字符串内部禁止使用未转义的 ASCII 双引号，中文引用请用「」」。

### 🟡 文件命名不一致

**问题**：OCR 文件命名 `math_10_ch1_4` vs Agent 1 产出 `math_10_ch1_4_充分条件...` vs Agent 2 期望 `math_10_ch1_s4`，导致跳过逻辑失败。

**教训**：section_id 必须从输入到输出全程一致，脚本中用 `cut -d'_' -f1-4` 提取纯 ID。

### 🟡 Schema 漂移

**问题**：有的节用旧 schema（`knowledge_id/basic/tree/concept/relations `），有的用新格式（`id/title/content/key_terms/references `），质检 Agent 按旧格式校验新格式时标记为质量差。

**教训**：Agent Prompt 必须锁定 JSON schema 版本，不允许模型自行决定输出格式。

### 🟢 全自动管线验证成功

**经验**：Shell 脚本 + QwenPaw Agent CLI 的三阶段管线（A1 版面→A2 提取→A3 质检）跑通 24 节，单节失败不阻塞后续。

### 🟢 文件归档策略

**经验**：最终产出（节点 JSON）与中间产物（OCR 原始 JSON、Agent 版面 .md）分离存放，`knowledge-graph/` 独立目录免检索干扰。

### 🟢 补集修复流程

**经验**：单节点内容缺失时，不需要重跑全书。追加 OCR → 单节重跑 A1→A2→A3 → 更新索引，15 分钟内解决。

| 字段 | 内容 |
|------|------|
| **时间** | 2026-07-30 |
| **状态** | ⏳ 待确认（3 个待定点未拍板） |
| **背景** | 拍照录入的题目可能没有标准答案（主观题/无确定解/图形残缺）。此前设计的「对错判定」依赖标准答案，无答案时无法判定 |
| **方案** | 三层流程：① AI 判可解性（不看学生答案）→ 能则 AI 算答案走正常 K/A/T 全过程；不能则 ② 过程诊断（η 路径质量 + r 解题质量 → 更新 A/T，K 冻结）+ 思维链弹窗重点采集 Q；③ S 维度轻量自评弹窗「这题你觉得能拿几分？」→ 比对 AI 过程分析 → 生成稳定性报告 |

#### 纠偏（2026-08-07）— 追加，不改上表原文

上表「BKT、η×权重」「Q/S 无完整公式」为当日误写/易误解表述，保留原文；现行理解如下：

1. **K**：加权得分法 `S_k/D_k`（理论 §4.4），**非 BKT**。

## 决策 055：A 的重新设计 —— 从第一性原理推「熟练度」的可测代理（2026-09-25，用户拍板）

> 触发：用户连续追问「A 的计算方式也许需要修改一下」→「**怎么能不管对不对**」→「**抄错是哪个维度**」→ 要求从第一性原理重推。本次推导**纠正了两处旧设计**：① s 只由 η 构成（把对错拿掉了，错）；② 上一轮我主张 skill 类错"照常算"（也错，见第四节）。

### 一、第一性原理：三个词里哪些能测

| 想刻画 | 标准测法 | 我们有没有 | 结论 |
|---|---|---|---|
| **准确度** | 对错 | ✅ P / 官方分 | **它是输入信号，不是维度**——事实不用 AI 估 |
| **效率** | 时间 / 尝试次数 | ❌ 无采集 | **测不了** → 只能用"路径绕不绕"当代理 |
| **熟练度** | 反应时 + 错误率（认知心理学的自动化指标） | ❌ 无时间 | **测不了本体** → 只能用**过程形态**当代理 |

→ 第一性原理下的第一个结论：**不能直接测熟练度，只能测它的痕迹。**

### 二、把可用的痕迹列出来并筛（判据：客观可算 / 尽量全题型 / 与熟练单调相关）

| 痕迹 | 客观吗 | 全题型吗 | 去留 |
|---|---|---|---|
| **P（对错/半对）** | ✅ | ✅ | **留下** |
| **D（难度）** | ✅（有抖动） | ✅ | **留下——只当"这次值多少"的情境校准**，不当证据本体 |
| **过程分段 / 断段数** | ✅（可数） | ❌ 仅解答题 | **留下**（过程形态） |
| η（是否接近本质） | ⚠️ 主观打分 | ❌ 仅解答题 | **降级为辅助**（实测会抖） |
| 时间 / 尝试次数 | —— | —— | ❌ 没有 |

### 三、s 的合成（**对错必须进** —— 这是对用户质疑的直接回应）

```
s = P × (0.6 + 0.4·D) × q
  解答题：q = 1 − 断段数 / max(1, 总段数)
  选填题：q = 1（无过程可看）
```
- **P = 0 → s = 0 → A 必跌**（做错就是没用出来）
- `(0.6 + 0.4·D)`：同一份"做对"，**难题上更值钱**（难度只作情境校准，符合决策 049）
- **跳步不罚**：熟练的人本就不写全；漏写的后果已由 P 罚过，不重复罚

### 四、分流：谁进哪本账（**抄错 = S**，这条来自用户提问）

| `errorLevel` | 进 A？ | 进 K？ | 归 S？ |
|---|---|---|---|
| **skill**（算错 / **抄错**） | ❌ **不进** | ❌ | ✅ |
| **concept**（概念没懂） | ✅ 进（负向） | ✅ 进（负向） | — |
| **rule**（步骤 / 方法错） | ✅ 进（负向） | ❌ | — |

- **抄错的判据**：偶发手滑 = S（宪法 §8.1「表现与真实能力的**偏差**」；判定端把"抄写"写在 skill 里）；**系统性**反复错同一符号/步骤 → 那不是抄错，是 K（没懂含义）或 A（操作不熟），按 `errorLevel` 再看。
- **单次抄错判不出 S**：单次观测上"抄错"与"不会"长得一样；**S 本质是方差**，要靠跨题比较——这正是宪法 §8.4「S0 波动指数」存在的原因。
- 这不是"新增例外规则"，而是**各维各管一摊**：分类本来就存在（`errorLevel`），照它分流即可。

### 五、更新公式（学习率与起点沿用现有）

```
ΔA = 0.25 × (s − A) × (U − A)
A  = clamp(A + ΔA, 0, U)
U  : 连续 2 次 s ≥ 0.8 → U += 0.05(1−U)
     连续 5 次 s ≤ 0.6 → U −= 0.03(U−A)
起点：A = 0.30、U = 0.50   ｜   **D 不进公式主体**（决策 049）
```

### 六、数值示例（U−A = 0.2，λ = 0.25）

| 情形 | s | ΔA |
|---|---|---|
| 难题做对 + 过程干净（P=1, D=0.8, q=1） | 0.92 | **+0.011** 涨 |
| 简单题做对 + 过程干净（P=1, D=0.2, q=1） | 0.68 | **−0.001** 几乎不动 |
| **做对但一路卡**（P=1, D=0.6, q=0.4） | 0.56 | **−0.007** 跌（会做但很生） |
| **做错**（P=0） | **0** | **−0.035** 明显跌 ✅ |
| 选填做对（P=1, D=0.5） | 0.80 | 涨 |

### 七、自查（这套设计自洽吗）

| 检查 | 结果 |
|---|---|
| 做错会不会不跌 | **必跌**（P=0 → s=0）✅ |
| 做对就涨吗 | 不一定——很生（q 低）或简单题（D 低）都不涨 ✅ |
| 难题做对 > 简单题做对 | 是 ✅ |
| 选填题进不进 A | **进**（q 恒 1）→ 消灭 40/61 的盲区 ✅ |
| 要新采集吗 | **不要**（时间/尝试次数都没用上）✅ |
| 和 K 共线吗 | 部分相关但可分辨：K 看"本体 concept 级"，A 看 P×D×过程形态 → "概念对但过程乱" = K 高 A 低 ✅ |
| 和 S 的边界 | **S 管方差（同难度同题型上的波动），A 管水平** ✅ |

### 八、这一改解决的四件事

1. **选填题盲区**：从"完全不进 A"（40/61 题）变成进 A
2. **对错回到 A 里**（旧公式的方向项 `(2P−1)` 语义保留，只是不再乘 D）
3. **难度退出公式主体**（决策 049）：只作情境校准 + 分层抽检
4. **skill/concept/rule 分流写全**，A 不再替 K、S 背锅

**影响面**：`cloudfunctions/graphEngine/src/lib/updateMastery.js`（A 分支重写）、宪法 §5.5 修订块、`参数对齐审计.md`。
**验证**：与决策 052/053/054 一起做**一次性 6 例 × 2 轮**（约 1 元）。

## 决策 059：产品目标重定 —— 服务高分段学生，做「解答题过程审阅」（2026-10-02，用户重新推导后拍板）

> **独立性**：本决策**推翻的是产品的目标层**，不是某个功能。此前所有围绕「找薄弱知识点 / 五维诊断」的目标表述，自本决策起一律以 [`doc/TARGET.md`](TARGET.md) 为准。
> **方法论来源**：用户明确要求「前提全丢，只留一条——服务高分段学生，前期不做低分段」，从「这类人需要什么」重新推，**不从既有模型推**。

### 一、推翻了什么

| | 旧目标（作废） | 新目标 |
|---|---|---|
| 问的问题 | 你哪里不会？ | **你哪里会被扣分？** |
| 隐含假设 | 学生有不会的 | 学生基本都会，**丢分在细节** |
| 审什么 | 错题 | **错题 + 做对的题** |
| 输出 | 薄弱知识点 | **具体步骤的坏 / 松 / 绕** |
| 视角 | 老师教知识 | **阅卷老师挑毛病** |

被本决策直接作废的表述：`doc/architecture/产品形态总设计.md` 头部「核心命题＝只告诉学生哪里不会、为什么不会、然后怎么学」。

### 二、新目标（一句话）

> **给卡在瓶颈上的高分段学生，做解答题的「过程审阅」—— 告诉他哪里会被扣分，以及同一处他丢过几次。**

四条推出来的痛点：① 不知道为什么丢分（高分学生的错**自己看不出来**）② 没有扣分视角（缺的是**阅卷老师的眼睛**，不是解题能力）③ 重复的错抓不住（同一动作反复出问题，每次当新问题）④ 不知道解法是否最优（无标准解法可对照）。

**最反直觉的一条**：对高分学生，**"做对了的题"比"做错的题"更重要** —— 做错他自己知道，做对但过程不严谨才是他真正在丢分的地方。现报告「错题逐题」结构恰好漏掉这块 → **作废重写**。

### 三、硬边界：过程审阅 = 只做解答题（实测得出，非设计取舍）

2026-10-02 实查云端 `questions` 61 题：

|---|---|---|
| **解答** | **19** | **19（100%）** |
| 选择 | 20 | **0** |
| 填空 | 20 | **0** |
| 其他 / 未知 | 2 | **0** |

**选择/填空/其他 42 道，过程数据 0 道。** 所以「只做解答题」不是妥协，是**数据约束下的聚焦** —— 高分学生丢的本就是步骤分，选填没有过程可言。

连带老实账：做对的 17 道题里**只有 2 道有过程**，「把做对的题纳入审阅」当前无米下锅。但**不作为缺口补** —— 解答题占比会随目标用户聚焦自己上去（高分学生错题天然集中在大题）。**先锁用户群，数据问题跟着解；反过来先补数据 = 拿旧用户群的数据捏新用户群的产品。**

他的高级思维方法目前是**隐性知识**。隐性知识不可迁移 —— 让它满意的是他的判断力，不是工具。

- **不能** → 那是他的能力不是产品能力；此时「向下改更容易」不成立（要向下传的是能力，不是功能）

现状佐证：STATUS-MANIFEST:26「判定链路不读 reference 链，根/错因是模型自由归因」——**判据至今未立**。

### 划走的误解

**他的思维方法 ≠ 产品要评估的 Q（思维品质）。** 按 `doc/reference/Code-Wiki.md` §Q，Q 数据源是「思维链（弹窗触发，独占，不接受任何代理指标）」＝学生主观输入，同时撞上 ① 决策 048 采集冻结（零新增）② 目标「全部不需要学生主观输入」。

→ **不做成 Q 维度**；它在本项目只充当**验收标准**与**判据来源**。

## 决策 059 的补充 4：五维收敛为三维；「松」走 S 维度，不新造档位（2026-10-03）

> 触发：用户要求「先按我自己的情况重构一遍」，并指定先看报告结构与五维设计。
> 前置：全量实查线上库（`users` 19 字段 / `knowledge_progress` 52 条 / `reports` 33 份 / `questions` 61 道）。

### 🔴 发现 1：报告对象不能独立渲染（结构债）

`reports.report` 实测只有 4 字段（33/33 全覆盖），`questions[]` **每题仅 6 字段**（`questionId/questionText/status/questionType/pattern/knowledgeNames`）——**不含诊断文字**。三段诊断写在 `questions.diagnosis`（**49/61 有**），前端展开某题时调 `action=questionDetail` 二次拉取（`index.js:339-357`）。

→ 报告必须配一次往返才能显示，**报告对象本身不是自足交付物**。v3 收掉此债（内联诊断，`questionDetail` 降为兜底）。

### 🔴 发现 2：线上有三个**无来源的数字**

`users` 上 `qOverall=0.55 / sOverall=0.68 / tOverall=0.45` 全部有值，但 **Q/S/T 的工程实现从未落地**（`doc/掌握度链路-待办.md:20,23`）——这三个值不可能由真实数据算出。

→ 裁决：**重构前必须查清来源或清零**。不能让假数字在重构后被当真数据读。这是本次重构的**前置动作**。

另：`knowledge_progress` 52 条仍带 `sValue`/`dValue`（样本 4.775 / 8.45），而决策 052 的新 K 口径是 `attempts/correctCount`（`statService/kFormula.js`）→ `sValue/dValue` 是**已停写的旧字段残留**。

### 🔴 发现 3：「松」不必新造 —— S 维度就是它的位置

决策 052–057 重写了 K/A 公式，但「松」一直悬着（`TARGET.md` §10 未决 #1）。**现在有答案**：

> **「松」＝ 结论对但过程不严谨 ≈ S（执行稳定）要抓的失常信号。**

依据 `doc/掌握度链路-待办.md:20` 原文：「失常信号（**P 高但答错，如 P 0.8~0.95 且归因执行类**）无处归档。公式现成：`S0 = |P_exp − R_actual|`」。

**S 至今是 🟡 中优先级、"公式现成没人做"——因为旧目标下没有信号源；新目标下有了**：高分学生做对但过程松的题，正是他们丢分的全部原因。

→ **裁决：S 从 🟡 中优先级升 P0 主信号。** 走 S 比新造 `segments.status: 松` 档省一个数量级（公式/字段/落库口径现成，只差接线）。这也回答了 `TARGET.md` §10 未决 #1 的**来源问题**：判据即 S0。

### 五维收敛裁决

| 维度 | 裁决 | 依据 |
|---|---|---|
| **K** 知识掌握 | 🔻 **降副指标**，折叠到报告末尾 | 高分学生 K 饱和、区分度≈0；`kFormula` 只统计叶子行（`aggregated!==true`），本身是**练习量口径**非能力口径 |
| **A** 熟练度/难度分层 | 🔺 **升主指标** | 高分学生全部区分度在难度层。A 是唯一能表达「他在哪种难度上失手」的维度 |
| **S** 执行稳定 | 🔺 **升 P0 主信号** | 发现 3 |
| **Q** 思维品质 | ⛔ **不做** | ① 撞决策 048 采集冻结（零新增）② 撞「不需要学生主观输入」③ 作者的思维方法**不是被评估对象**（补充 3） |
| **T** 迁移能力 | ⛔ **推迟** | 需跨单元综合题输入；样本量不足（必修二~五已定推迟） |

→ **五维 → 三维：K（副）+ A（主）+ S（主信号）。Q/T 明确不做。**

### 报告 v3 结构：主轴从「题」换成「差异」

现结构：`分数+圆点 → 逐题展开 → 掌握度变化`；v3：`差异清单置顶 → 按动作跨题聚合 → 步骤级并排对照`。

依据来自目标痛点 3：**「重复的错自己抓不住，因为每次遇到都当新问题」** —— 题列表天然销毁该信息（同一处松 5 次，在 5 个折叠面板里显示 5 次）。

三类差异判据可落地：

| 差异 | 判据 | 信号现成度 |
|---|---|---|
| **坏** | 结论错，或 `status='断'` 且该步为根因 | ✅ 已有（19 道） |
| **松** | `S0 = |P_exp − R_actual| > 0` | ✅ **公式现成**（本次发现） |
| **绕** | 步骤数 > 标准解法 × 阈值 | ⚠️ 需比对 `referenceProcess`（49/61 有，够用） |

数据契约变更：`questions[]` 内联诊断（消除二次拉取）／新增 `processAlignment[]`（步骤级对照）／新增 `actionClusters[]`（跨题动作对齐）／`masteryChange` 降级折叠。

## 决策 059 的补充 5：推翻 v3 —— 报告从零重设计（2026-10-03）

> 触发：用户原话「**从头整理一遍，不要跟我说什么松这些的。抛掉所有前提重新设计一下。**」

### 作废声明

**`doc/REPORT-v3-结构重构.md` 整体作废**，由 `doc/REPORT-从零重设计.md` 取代。

**作废理由（本项目第一次推翻自己同一天内的推导）**：

| v3 主张 | 问题 |
|---|---|
| 「坏 / 松 / 绕」三类差异 | **这三个词是我造的，不是用户脑子里的东西。** 从零重来时第一个被扔掉 —— 用户的实际经验是**看到差异本身**，不是先看它归哪一类；先分类反而会让我去凑框架 |
| 「松」走 S 维度公式 `S0=\|P预期−P实际\|` | 那个公式是为了**算分**。但「少写一步」**看一眼就知道，不需要算** —— 为了可算而引入公式，是拿工程复杂度换了个不存在的问题 |
| 五维收敛为三维 | **存三个 ≠ 看两个。** 存着但不给人看的东西等于没收敛。正确口径：**报告上只留 2 个数字** |
| 步骤级并排对照 | ✅ **唯一活下来的** —— 它直接对应"差异必须落到行"这条要求 |

### 从零重设计的三条核心主张

**① 报告的主体是「该改的清单」，不是「题目列表」。**
理由（用户处境推导）：我是来**找该改什么**的，不是来看题的。题目是材料，差异才是内容。
现结构的根因问题：**同一处问题在 4 个折叠面板里显示 4 次，信息被自己销毁了。**

**② 差异必须落到「行」，且必须附「凭什么」。**
每条差异必须同时给：①我的原话 ②标准写法 ③**这为什么会被扣**。
第 ③ 项三种依据至少有一种：引标准原文 / 引阅卷事实 / 指具体缺什么。
→ **三种都拿不出来的就别报。宁可只报 2 条真的，也不要报 10 条凑数** —— 报错一条，学生就不会再信后面九条。

**③「我不服」能反驳「扣不扣分」，是前两条的地基。**
现状：页面已有**题型异议**与**过程异议**两个入口，但**改不了"这步扣不扣分"** —— 而那才是学生真正会争的东西。
不许反驳的判卷老师，学生不会信第二次。

### 附带的两个反向发现

- **做对的题也必须看**：理由不是"做对也有错"，而是**"做对"和"做全"是两种分数**。只看错题，"少写"这件事永远看不见 —— 因为它不改对错，只改分数。
- **五维 → 报告只留 2 个数字**（稳定度主 + 熟练度辅）。删知识（高分段饱和无区分度）／思维（要学生多写一段才能量，撞决策 048）／迁移（样本不足）。**这五个数字现在报告里一个都没显示，且线上三个值是假的**（见补充 4 发现 2）→ 重构前必须先清。

**已同步**：新建 `doc/REPORT-从零重设计.md`；`REPORT-v3-结构重构.md` 顶部加 ⛔ 作废声明（保留作历史留档，禁止据此写代码）。**本轮未动任何代码。**
