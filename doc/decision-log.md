## 决策 001：PDF 解析方案选型

| 字段 | 内容 |
|------|------|
| **时间** | 2026-07-28 |
| **状态** | ✅ 已定案 |
| **背景** | 教材 PDF 经 PyMuPDF 检测为图片型（267 页，0 文字，268 张图片），无法用 pdf.js 直抽 |
| **方案** | 腾讯云 OCR `GeneralAccurateOCR`（通用文字识别高精度版）|
| **理由** | MinerU 在 Mac 上因 MPS 兼容性+网络+速度问题无法使用；ppstructure 安装复杂；腾讯云每月 1000 次免费额度，整本 267 页在额度内 |
| **验证** | 封面页 98%、公式页 96%、文字页 94-98% 置信度，1.3 节 9 页全通过 |
| **产出路径** | `output/raw/ocr_pageXXX.json`（逐页）→ `output/sections/{section_id}.txt`（每节合并）|

## 决策 002：三 Agent 管线架构

| 字段 | 内容 |
|------|------|
| **时间** | 2026-07-28 |
| **状态** | ✅ 已定案 |
| **背景** | 知识点提取需要分步处理：先整理排版，再提取知识点，最后质检。单一 Agent 做不到高质量 |
| **方案** | Agent 1（版面分析）→ Agent 2（知识点提取）→ Agent 3（质检），Shell 脚本串行调度 |
| **调度方式** | `qwenpaw agent chat` CLI，不传 `--session-id` 每节新开会话 |
| **失败处理** | 重试一次，仍失败记入 `_failed.log`，跳过该节不阻塞后续 |

## 决策 007：TOC 页码偏移教训

| 字段 | 内容 |
|------|------|
| **时间** | 2026-07-28 |
| **问题** | TOC 记录的是教材印刷页码，但 PDF 物理页码偏移了 +6。直接按印刷页码跑 OCR，产出了 155 页全错的内容 |
| **根因** | 没有验证 OCR 第一页的实际内容是否匹配章节标题 |
| **预防** | ① OCR 前必须用 PyMuPDF 或页脚 OCR 验证 TOC 页码与 PDF 物理页的偏移量 ② 每个章节的第一页 OCR 后必须检查内容是否包含该章节标题 ③ 下次跑其他教材时先跑 1 个章节验证，不要整本盲跑 |
