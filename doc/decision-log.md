## 决策 010：知识图谱构建经验总结

### 🔴 TOC 页码偏移（最贵的一课）

**问题**：TOC 记录教材印刷页码，PDF 物理页码偏移 +6，直接按印刷页码跑 OCR 导致 155 页全错，重跑浪费数小时。

**预防**：OCR 前必须用 PyMuPDF 验证 TOC 页码与 PDF 物理页的偏移量，每章第一页检查内容是否含章节标题。

### 🔴 AI 生成的 JSON 内引号问题

**问题**：Agent 2 输出的 JSON 字符串内部包含 ASCII `"`（如 `称为"补集"`），破坏 JSON 结构。

**根因**：大模型在中文上下文中使用 ASCII 双引号作为中文引号，而 JSON 要求内层引号转义或使用 `「」`。

**修复**：Python 正则 + 逐行字符扫描替换内层 `"` 为 `「」`。

**预防**：Agent 2 Prompt 应明确要求「JSON 字符串内部禁止使用未转义的 ASCII 双引号，中文引用请用「」」。

### 🟡 文件命名不一致

**问题**：OCR 文件命名 `math_10_ch1_4` vs Agent 1 产出 `math_10_ch1_4_充分条件...` vs Agent 2 期望 `math_10_ch1_s4`，导致跳过逻辑失败。

**教训**：section_id 必须从输入到输出全程一致，脚本中用 `cut -d'_' -f1-4` 提取纯 ID。

### 🟡 Schema 漂移

**问题**：有的节用旧 schema（`knowledge_id/basic/tree/concept/relations `），有的用新格式（`id/title/content/key_terms/references `），质检 Agent 按旧格式校验新格式时标记为质量差。

**教训**：Agent Prompt 必须锁定 JSON schema 版本，不允许模型自行决定输出格式。

### 🟢 全自动管线验证成功

**经验**：Shell 脚本 + QwenPaw Agent CLI 的三阶段管线（A1 版面→A2 提取→A3 质检）跑通 24 节，单节失败不阻塞后续。

### 🟢 文件归档策略

**经验**：最终产出（节点 JSON）与中间产物（OCR 原始 JSON、Agent 版面 .md）分离存放，`knowledge-graph/` 独立目录免检索干扰。

### 🟢 补集修复流程

**经验**：单节点内容缺失时，不需要重跑全书。追加 OCR → 单节重跑 A1→A2→A3 → 更新索引，15 分钟内解决。

| 字段 | 内容 |
|------|------|
| **时间** | 2026-07-30 |
| **状态** | ⏳ 待确认（3 个待定点未拍板） |
| **背景** | 拍照录入的题目可能没有标准答案（主观题/无确定解/图形残缺）。此前设计的「对错判定」依赖标准答案，无答案时无法判定 |
| **方案** | 三层流程：① AI 判可解性（不看学生答案）→ 能则 AI 算答案走正常 K/A/T 全过程；不能则 ② 过程诊断（η 路径质量 + r 解题质量 → 更新 A/T，K 冻结）+ 思维链弹窗重点采集 Q；③ S 维度轻量自评弹窗「这题你觉得能拿几分？」→ 比对 AI 过程分析 → 生成稳定性报告 |

| **待确认点** | ① η/r 定义与取值区间（建议 0-1，Flash 计算，存 mastery_logs）；② AI 可解性判断是否需要置信度阈值（建议 ≥0.8）；③ AI 算的答案标记 `answerSource:'ai_computed'`，低置信度时不更新 K 只更新 A/T（防 AI 错答案污染 K） |

#### 纠偏（2026-08-07）— 追加，不改上表原文

上表「BKT、η×权重」「Q/S 无完整公式」为当日误写/易误解表述，保留原文；现行理解如下：

1. **K**：加权得分法 `S_k/D_k`（理论 §4.4），**非 BKT**。
2. **A/T**：按理论 A/U、T/U 原文（§5.5 / §6.5），不是「η×权重」口糊。

5. **K 何时更新**：未拍板（见 M4）；与本决策「怎么算」分开。

## 决策 015：过程证据采集 — 视觉逐步置信度 + 语音/文字 + 上传侧过程 AI

| 字段 | 内容 |
|------|------|
| **时间** | 2026-08-07 |
| **状态** | ✅ 已定案（方案定；ASR 选用与置信度阈值等工程细节可后续补） |
| **收口** | ROADMAP 待决策 #9（视觉「舍去」误读 / 过程不可全信视觉） |
| **一句话** | 视觉仍负责过程，但逐步带置信度；学生用自然语言（语音优先，可打字）描述情况；上传界面另设「过程 AI」按学生说法灵活改过程草稿；确认后的 `process_evidence` 再交给 diagnose |

### 怎么来的：踩坑 → 换工具（过程复盘，必须保留）

> 本节不是事后美化结论，而是记录：**原先押什么工具 → 哪里翻车 → 讨论过换什么 → 最后换到什么**。

#### 坑 1：高估视觉模型「读过程」的能力

| | 内容 |
|--|------|
| **原先工具假设** | 拍照 → Qwen 多模态一次吃透「题文 + 做题全过程痕迹」→ 直接供 Flash 做 η/r、过程归因 |
| **踩坑事实（POC）** | 题文转录尚可（含一页多题）；**涂改密集的过程转录不可全信**——「舍去」标记挂错对象、≥/≤ 符号歧义 |
| **代价** | 若继续让视觉过程当事实，A/T 参数与归因会被脏数据污染；对错路径虽已用门禁2隔离，**过程路径仍裸奔** |
| **已写入** | ROADMAP「POC 测试结论」+ 待决策 #9（当时方案待定） |

#### 坑 2：差点用错药——「换视觉工具」

| | 内容 |
|--|------|
| **当场选项** | 换更强 VLM / 换视觉厂商，继续「一张图看懂全过程」 |
| **为何没走这条** | ① 题文已经够用，瓶颈在过程层通病，不单是 Qwen；② 换底座 ROI 低、工期与成本涨；③ 过程重要性越高，越不该押在最不稳的模态 |
| **结论** | **不优先换主视觉模型**；视觉保留，但降级为「过程草稿生产器」，不是过程真相源 |

#### 坑 3：只靠文字自述 vs MVP 真要上线

| | 内容 |
|--|------|
| **轻量补丁** | 纯打字自述，零新工具 |
| **为何不够** | MVP 直接给学生用；过程是一等信号，录入负担过高压坚持率；用户明确 **MVP 要上语音** |
| **含义** | 语音不是体验锦上添花，是开用必备 → 必须部署 ASR（新工具），但不能把 ASR 原文当真相 |

#### 坑 4：语音也会不准（第二噪声源）

| | 内容 |
|--|------|
| **新风险** | ASR 误识别 + 口语含糊 → 「转写完直接当过程」会第二次踩坑 |
| **不能做的事** | 视觉不准就改押语音；语音不准再空转 |

#### 换工具：最终换到哪一套

```
【旧工具链 — 已证伪】
  拍照 ──▶ Qwen（题+过程当事实）──▶ Flash 诊断
              ↑ 过程不可信（踩坑）

【讨论过但未采用】
  换更强 VLM 继续「看懂全过程」  ← 否决为优先解

【新工具链 — 本决策】
  拍照 ──▶ Qwen（题文高信任 + 过程逐步草稿+confidence）
              │
              ▼
         ASR 语音 / 打字（学生自然语言说情况）  ← 新增部署：ASR
              │
              ▼
         过程 AI（上传界面，编辑器）          ← 新增工具：校准用 AI
           按学生说法增删改过程草稿
              │
              ▼
         学生确认 → process_evidence → Flash 诊断
```

| 动作 | 工具 | 角色变化 |
|------|------|----------|
| **保留** | Qwen 视觉 | 从「过程真相」→「带置信度的过程草稿」 |
| **不换** | 主视觉底座 | 明确否决「换 VLM 治过程」 |
| **新增** | ASR（微信插件或腾讯云一句话等） | 语音→文本输入法；失败落打字 |
| **新增** | 上传侧「过程 AI」 | 唯一允许灵活改过程稿的层；不算分、不写报告 |
| **下游不变** | diagnose / Flash / scoreFiveDim | 只吃确认后的 `process_evidence` |

#### 时间线（同日讨论压缩）

1. 指出：曾高估视觉，POC 已写入项目  
2. 问：换工具还是改契约？→ 建议先改契约、不优先换 VLM  
3. 强调过程重要 → 讨论过程采集（自述/问答）  
4. 语音要部署新工具 + MVP 必须上语音  
5. 承认 ASR 也不准 → 提出上传页过程 AI 用自然语言灵活更新过程  
6. 用户确认 → 写入本决策（含本踩坑复盘）

### 方案（契约）

```
Qwen：题文（高信任）+ 过程逐步草稿 trace_steps[]（每步 text/type/confidence）
        ↓
学生：语音（ASR→文本，可打字覆盖）自然语言描述/纠正/补充
        ↓
过程 AI（上传界面，编辑器角色）
  输入：trace_steps + 学生文本（可能含 ASR 噪声）
  动作：增/删/改/合并步骤；标来源 vision | student | merged
  护栏：不判对错、不打五维、不无根据编造未提及细节
        ↓
学生确认（短摘要「当前理解的过程」→ 对 / 再说一句）
        ↓
process_evidence → 交给 diagnose / Flash（η、r、过程归因只吃这份）
```

| 角色 | 负责 | 不负责 |
|------|------|--------|
| 视觉 Qwen | 题文 + 带置信度的过程草稿 | 单独定最终过程 / 对错 |
| ASR / 打字 | 降低输入负担，产出学生文本 | 原文当过程事实 |
| **过程 AI** | 按学生说法编辑过程草稿 | 诊断评分、五维、报告 |
| diagnose Flash | 门禁 / 归因 / 填参 / 报告 | 在上传页改过程稿 |

### MVP 约束

- 语音与打字同一字段入口；ASR 失败自动落打字，不堵主流程  
- 先做「整段自然语言改稿」；针对第 N 步追问可二期  
- 低置信 / 冲突步骤：优先靠学生说法更新；无确认则过程证据降级（避免脏 η/r），具体阈值工程阶段再定  
- **不换**主视觉模型作为本问题的解法；过程 AI 才是过程可信度主修复器
