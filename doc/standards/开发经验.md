# 开发经验（错误记录）

> 用途：记录每次开发/调试中出现的所有错误——现象 / 根因 / 修复 / 教训，防重复踩坑。
> 规则来源：CLAUDE.md「规则 D：出错必记录」（2026-08-11 用户要求）。
> 前端视觉/动画专项经验见《前端视觉与动画工程经验.md》。

## 一、前端渲染类

### 1. WXML `<text>` 内嵌 `<view>` → 编译错误页面打不开
- **现象**：知识图谱页白屏，navigateTo timeout
- **根因**：图例写 `<text><view class="sw"></view>已掌握</text>`，text 组件禁止嵌套 view
- **修复**：图例改 `<view class="lg">` 包裹
- **教训**：页面打不开先怀疑 WXML 编译错误（JS 语法 OK ≠ 页面可用）

### 2. `conic-gradient` / `mask` / opacity 动画在小程序渲染不可靠
- **现象**：掌握度环变白节点、节点全透明（依赖 opacity:0 动画）
- **根因**：小程序渲染层对浏览器 CSS 特性支持不稳，失败静默降级
- **修复**：掌握度环用 border 色环；动画只动 transform 不碰 opacity
- **教训**：小程序禁用 conic/mask/依赖 opacity 的动画

### 3. 合成节点（单元/小节）名字不显示
- **现象**：知识图谱「数学」页节点只有空心圆没有字
- **根因**：nodeView 的 `label` 条件排除了 `node.synthetic`，而合成节点名字全 >5 字走 label 分支 → 圆内外都无字
- **修复**：`label: (!isCenter && (longName || node.synthetic)) ? node.name : ''`
- **教训**：改显示条件时检查所有节点类型（synthetic/普通/长名/短名），别只覆盖一种

### 4. 节点数量过多 → 认知超载
- **现象**：知识点层 10+ 个卫星节点环绕过挤
- **依据**：工作记忆容量 7±2（Miller）、认知负荷理论（Sweller）——一屏 >8 元素理解下降
- **修复**：单屏卫星上限 8 个，超出折叠为「+N 更多」，点开展开全部
- **教训**：图谱/列表类 UI 默认遵守 7±2 组块化

### 5. Canvas 尺寸用 rpx 预计算 → 线节点错位
- **修复**：onReady 实测 boundingClientRect，Canvas 与节点共用坐标系

### 6. 开发者工具 navigateTo 全超时 → 先重启工具
- **修复**：模拟器卡死时重启微信开发者工具，不是改页面

### 13. 改错了页面：knowledge-map 有新 UI，用户打开的是 tab「图谱」graph
- **现象**：用户说「写成生产级」后编译仍是旧版放射图+Canvas
- **根因**：真正入口是 `app.json` tabBar → `pages/graph/graph`；`pages/knowledge-map` 只从 dimension-detail 的 `navigateTo` 进入，日常几乎打不开。生产化只改了 knowledge-map，没改 graph
- **修复**：把新版目录列表+演化链同步到 `pages/graph`，并保留 tab 特性（无返回键、根层不 navigateBack、底部 tabBar 占位）
- **教训**：改「知识图谱」前必须确认用户实际打开的是哪一页——查 `app.json` tabBar + 全部 `navigateTo`/`switchTab` 入口，不要假设同名页面就是入口

### 20. 小程序 katex（@rojer/katex-mini）构建 npm 后 wxss 字体内联被替换为 CDN 远程 URL
- **现象**：公式渲染缺字体（显示方块）；构建产物 `miniprogram_npm/@rojer/katex-mini/index.wxss` 只有 26KB，@font-face 指向 `cdnjs.cloudflare.com` 远程 URL
- **根因**：微信「构建 npm」改写 wxss，把源包 `dist/index.wxss`（1.4MB，字体 base64 内联）替换成 CDN 远程字体引用；小程序 WXSS 的 @font-face 不支持远程 URL，且 cdnjs 域名被墙加载必失败
- **修复**：`app.wxss` 不 import 构建产物 wxss，改用 `miniprogram/libs/katex-mini/index.wxss`（与源包 `dist/index.wxss` 逐字节一致，`cmp` 验证，base64 自包含）
- **教训**：构建 npm 产物不能盲目信任，wxss/字体类资源构建后要核对内容；npm 包内联资源（base64）在构建时可能被改写，字体类必须用自包含方案

### 21. katex-mini 解析选项是 `throwError`，不是 katex 原生的 `throwOnError`
- **现象**：页面用 `throwOnError: true` 期望非法公式抛错，实际不抛（错误被渲染成红色文本而非被 catch）
- **根因**：katex-mini 的包装只认自己的选项 `throwError`（官方 README），katex 原生 `throwOnError` 被忽略
- **修复**：用 `throwError: true` + try/catch 容错，非法公式正常抛错并展示错误提示
- **教训**：第三方 mini 包的 API 选项以官方 README 为准，不要想当然套用上游库的选项名

## 二、诊断管线 / LLM 调用类

### 7. thinking 开 + 难题 = content 全空（死锁）
- **现象**：deepseek-v4-flash thinking（high/max）+ 难题，content 空 ×8 次（含 json_object/流式/24000 token）
- **根因**：模型"想不完"——reasoning 6.4 万字符仍在思考，永不进入 content 输出（能力边界）
- **修复**：D 判定用 thinking disabled；分析类任务待实测
- **教训**：长思考 ≠ 高质量，难题思考会死锁；「宁等」等不到，是 API 行为

### 8. disabled 直接判难度 = 稳定地错（低估）
- **现象**：难题直接判档 D=0.76（真实 0.92）
- **修复**：学生视角体验（模拟学生卡顿）+ 我方 L1-L11 标尺判档 → 0.92 命中
- **教训**：难度是体验属性，学生视角比冷静分析准；模型数步骤会低估构造难度

### 9. 难度评分随"评估方式"漂移（视角决定难度）
- **现象**：同题：直接判 0.76 / 学生视角 9分 / 自拟标准 7.2 / 学生视角+标尺 0.92
- **修复**：定稿 = 学生视角 + 我方标尺 + temperature 0.2 + 同题缓存（3 次平均）
- **教训**：评估类任务先定"视角"，视角错全盘错

### 10. 脚本多次 python 字符串替换 → 语法坏
- **现象**：/tmp 脚本改几次后 SyntaxError（单引号/反引号/正则冲突）
- **修复**：直接重写整个文件（cat heredoc），不再累积 patch
- **教训**：临时脚本改动超过 2 处就重写，别叠加替换

## 三、通用

### 11. 删除函数漏删调用 → ReferenceError 白屏
- **现象**：删 gradOf 定义，nodeView 里调用残留 → 页面空白
- **修复**：删函数前 grep 全项目调用点
- **教训**：删除代码 = 查调用链

### 12. setData 异步时序误判
- **现象**：evaluate 同步读 data 拿到旧值，误以为渲染 bug
- **修复**：延时/回调后再读；实际功能正常
- **教训**：自动化验证要等 setData 完成，别把时序当 bug

### 13. 本地 knowledge-graph 文件与云端 knowledge_nodes 不一致
- **现象**：回填掌握度时用本地 `knowledge-graph/nodes/*.json` 匹配节点名，「基本不等式」匹配失败——本地 `math_10_ch2_s2_002` 叫「基本不等式定义」，云端叫「基本不等式」
- **根因**：云端数据被另行修正过（359 条 vs 本地 357 条），本地文件不是权威源
- **修复**：回填/匹配以云端 knowledge_nodes 为准（judgeOne 运行时查云端天然正确；本地脚本需手动补云端修正映射）
- **教训**：任何依赖节点名/节点清单的本地脚本，先比对云端，别假设本地文件=云端

### 14. AI 判定 knowledgeNodeName 是句子式描述，精确匹配节点名必失败
- **现象**：17 条已判题 knowledgeNodeName（如「集合的子集与真子集」「集合的包含关系」）对节点名（「子集」「真子集」）精确匹配率 0%
- **修复**：judgeOne 掌握度匹配改为「精确 → 子串命中取最长名（最具体）」
- **教训**：AI 自由文本关联知识节点必须容错匹配；子串最长命中是够用的近似，终极方案是二次复核让用户选节点

### 15. 云函数模块级函数引用未定义 `event`（新写 ragService 自查发现）
- **现象**：getUser() 函数体内写 `event && event.userId`，但 getUser 是模块级函数，无 event 参数——运行时必然 ReferenceError
- **根因**：从入口处复制身份逻辑到独立函数时残留了 event 引用
- **修复**：删除死函数，身份逻辑内联到入口
- **教训**：新写代码自查一遍「未定义引用 / 未使用函数」；node --check 只查语法不查语义

### 16. mastery_logs 的 isCorrect 存在两种存储格式（读侧必须兼容）
- **现象**：getErrorPattern 用数据库 where 过滤 `{ isCorrect: false }`，只匹配到顶层字段格式的记录
- **根因**：dispute 写的 score_poc 记录 isCorrect 存在 `report.isCorrect` 对象内（无顶层字段），judgeOne 新写的 diagnose_v1 才有顶层字段——同一集合两种格式
- **修复**：拉全量后内存过滤 + 统一 logIsCorrect() 兼容两种格式
- **教训**：跨云函数写同一集合时字段格式必须统一，或读侧兼容两种；数据库 where 过滤会把缺失字段的记录静默排除

### 17. unit_progress 集合从未创建 → A 维度静默失败（2026-08-17 实测揪出）
- **现象**：judgeOne 判定日志 `collection not exists: unit_progress`，但整体返回 success
- **根因**：A 维度代码一直查 unit_progress 集合，集合从未创建；外层 try/catch 吞掉错误只 console.error，主流程继续 → 判定成功但 A 更新全丢
- **修复**：MCP 创建 unit_progress 集合
- **教训**：try/catch 包「非核心更新」时，错误日志不能只看不看——用 MCP 查集合是否存在验证「以为在跑的功能」真的在写数据

### 18. pOk 作用域错误 → RAG 记录写入静默失败（2026-08-17 实测揪出）
- **现象**：mastery_logs RAG 记录（diagnose_v1）从没写入过，日志 `pOk is not defined`
- **根因**：RAG 写入块在掌握度 try/catch 之外，引用 try 内 const pOk——ReferenceError；node --check 只查语法不查作用域，部署不报错
- **修复**：pOk 提升为函数级 let（同 mainNodeId 处理）
- **教训**：跨 try 块共享变量必须提升作用域；改代码后要真机/真数据验证写入（不是只看返回 code=0）

### 19. MCP invoke 测不了长任务云函数（2026-08-17 reportService）
- **现象**：reportService（Flash 多轮生成 + 工具循环，耗时可能 60-120s）用 MCP invokeFunction 稳定 `network timeout at scf.tencentcloudapi.com`；reports 集合无记录
- **根因**：MCP→SCF API 的等待窗口 < 函数真实生成耗时；短函数（statService/judgeOne）秒回正常
- **修复**：① 加 `action=ping` 健康检查（秒回）区分「函数挂了」vs「生成慢」② 完整生成验证改由用户在小程序端触发（wx.cloud.callFunction 客户端等待窗口大）
- **教训**：新云函数先 ping 确认活着，再区分「慢」还是「坏」；长任务（AI 多轮生成）的端到端验证必须走真实客户端，MCP invoke 只适合快速入口

### 20. 拍照页 progress-mask 与 wx.showToast 叠层（2026-08-25）
- **现象**：识别失败/提交失败时，自定义进度遮罩与系统 toast 同时出现，文案互相挡住
- **根因**：`analyzing/submitting` 仍为 true 或刚关遮罩时调用 `wx.showToast`（如「未识别到题目」）
- **修复**：流水线错误改 `pipelineError` 页内条（知道了/重试）；遮罩期间不再 showToast；选图前校验仍可用 toast
- **教训**：有自定义全屏 loading 时，失败态用页内状态，勿叠系统 toast/Loading
