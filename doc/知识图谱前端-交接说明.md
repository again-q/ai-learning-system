## 1. 当前实现状态（小程序）

| 文件 | 状态 |
|------|------|
| `miniprogram/pages/graph/graph.js` | ✅ v2 镜头移动（世界坐标制 + 聚焦动画 + 分组分圈 + 演化模式） |
| `miniprogram/pages/graph/graph.wxml` | ✅ world 容器 + 线 view 细条 + 节点层 |
| `miniprogram/pages/graph/graph.wxss` | ✅ 镜头动画 + 苹果风视觉（柔影/类型色点/玻璃高光/呼吸脉冲） |
| `miniprogram/pages/knowledge-map/*` | ⚠️ 与 graph 完全同步的副本（入口仍注册在 app.json，无引用） |

**交互机制**（用户确认的最终版）：
1. 点击节点 → **整个 `.world` 容器整体平移**（`transform: translate`，0.7s `cubic-bezier(0.22,0.1,0.12,1)`）
2. 被点节点滑到中心，同时**逐渐放大（64→120px）+ 渐变变蓝**（width/height/background transition）
3. **旧层所有节点淡出消失**（opacity 0.35s）
4. **下一级子节点在移动过程中同步慢慢浮现**（从中心 scale 0.45→1，0.75s）
5. 返回/面包屑 → 世界移回目标层中心

**布局规则**：≤5 子节点单行均匀铺满（y=430）；6-8 两行（380/455，每行独立居中均匀）；>8 按类型分组（概念/性质/方法/记号），组内 >8 分圈。

**演化模式**：只显示前置祖先链 + 当前节点（无儿子）。

## 2. 参考原型（浏览器直接打开）

**`output/knowledge-graph-focus-demo.html`** — 最新交互 + 视觉参考（镜头移动 + 苹果风视觉）。含完整数据 mock（数学 5 章），直接点开看效果。

## 3. 数据接口

- 云函数：`graphService`，`action: 'getAll'` → `{ nodes: [...] }`
- 集合：`knowledge_nodes`（361 节点已入库），节点字段：
  ```
  knowledgeId / name / type(definition|property|method|notation) / subject / stage / grade
  level / parentId / path[章节单元小节] / concept.source_text / importance.curriculum_weight|exam_frequency / relations.reference|related
  ```
- 前端索引：`buildIndex()` 按 `path[2]单元 → path[3]小节 → 根知识点` 三级组织；`parentId` 关联子知识点。

## 4. 遗留问题（重改时注意）

1. **掌握度是 mock**（`MOCK_MASTERY` + hash 兜底），待诊断管线落地后从 `knowledge_progress` 接入
2. **命名规范未完全落地**：AI 已产出重命名方案（简洁主体名 + example 抽象），但**映射未应用回 knowledge_nodes 云端数据**（当前云端还是旧命名 + example 36 个 + reading 4 个未处理）
3. `knowledge-map` 是 graph 的副本，重改后建议删掉（入口在 app.json 第 12 行）
4. 数据侧待办（与前端无关但影响展示）：example→method 抽象、reading→method 归并、`knowledge_index.json` 与分文件的一致性

## 5. 重改建议

- 直接改 `miniprogram/pages/graph/` 四件套（isTab 逻辑在 onLoad 里，tab 页自适应）
- 连线是 **view 细条**（小程序无 SVG，canvas 与 view 滚动不同步是已知坑，已弃用）
- 动画全部走 transform/opacity（GPU 合成层），世界坐标制公式见 `graph.js` 的 `worldTransformOf()/worldPos()`
- 想换交互重写时，数据层 `loadAll/buildIndex/childrenOf/preReqsOf` 可直接复用
