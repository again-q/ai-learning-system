# AI 自主建构知识体系方法论（教材 → KF 图谱）

状态：Draft  
适用范围：Agent v4 / 外部 Coding Agent（Claude Code / Codex）编排 `kf` CLI  
核心参考：`apps/agent/src/prompts/system-prompt.ts`（寻宝→连线内核）、`docs/kf-cli-guide.md`  
相关版本：v4.105（CLI 工具箱）、v4.228（页面区域 Grounding Bridge）

---

## 0. 目标与基本产物

**目标**：给定教材章节（PDF/OCR/派生资料节点），AI 能在 KF 中自主产出“可用的章节级知识体系底座”，并可逐步扩展到全书/全学段。

**产物**（三类知识）：

1. **知识点卡片（Knowledge）**：概念/定义/表示/性质/操作/关系/来源/应用/辨析等。
2. **案例卡片（Case，可选）**：例题、习题、典型真实情境。
3. **关系（边）**：把知识组织成两张地图：
   - **演化脉络地图（Evolution）**：知识“如何从无到有产生/推导”（前置 → 后置）。
   - **结构脉络地图（Structure）**：知识“如何从有到稳组织/检索”（核心概念 → 分类展开）。

---

## 1. 核心原则（硬规则）

### 1.1 核心概念锚点（必须）

- 每一节/小节首先识别 **核心概念**（通常来自标题，如“1.1 正数和负数”）。
- **核心概念本身必须建卡**，并允许 **裸名**（不要求三段式），例如：`正数和负数`。
- 目的：让地图围绕“概念本体”组织，避免“表示法/例题/技巧”误当中心导致逻辑倒置。

### 1.2 命名规则：三段式强制（核心概念例外）

除核心概念外，知识点命名统一采用对人更友好的三段式：

> `概念的类型-核心内容`

示例：

- `正数的定义-大于0的数`
- `负数的定义-正数前加负号的数`
- `0的性质-非正非负`
- `正数和负数的表示-符号表示`
- `正数和负数的表示-颜色表示-算筹`
- `正数和负数的应用-温度`

类型词建议收敛为固定集合（可扩展，但同一项目内要一致）：

- `来源` / `定义` / `表示` / `性质` / `操作` / `关系` / `应用`

**localName 合规**（写入前必须校验）：

- 长度 1–35
- 不含空格
- 仅使用：中文 / 英文字母 / 数字 / 连字符 `-`（其他符号放到 `content`）

### 1.3 关系策略：主线用命名链接，依赖用标签（避免多进线）

**演化脉络拓扑约束**：

- 每个节点在演化脉络中原则上只有 **一条命名入边**（主线入边），保持树状可读。
- 除主线外的多前置依赖，统一用 **标签链接（HaveTag）** 表达，避免“多进线织网”。

依赖方向语义约定（固定）：

- A 依赖 B（B 是前置）→ 给 **A 打 B 的标签**（A 需要 B）

### 1.4 content 规则：所有边都必须可解释

**命名链接（Relevant/Reference）**：

- 必须填写 `content`（不可为空）。
- 演化脉络 E1–E4 级别：`content` 必须以 `[演化模式]` 开头（见 2.2）。
- 演化脉络 E5 级别：`content` 必填但不强制模式前缀。

**标签链接（HaveTag）**：

- 必须填写 `content`，说明”依赖点/依赖强度”。

推荐模板：

- `必要依赖：理解A的<点>需要先理解B的<点>`
- `启发联想：B有助于理解A的<点>`

## 2. 连线方法论（演化 / 结构）

### 2.1 演化脉络：先识别“主导演化模式”

教材常见五种演化模式（从 `system-prompt.ts` 提炼）：

1. 问题-解决链
2. 概念系统化研究
3. 演绎推导
4. 经验归纳
5. 抽象-具象迭代

每一批连线任务（通常以“一节”为单位）先判断主导模式，用它来决定主线方向与关键跳点。

### 2.2 演化边 content 规范（按等级分层）

**E1–E4（重要脉络）— 硬规则**：`content` 必须以 `[演化模式]` 开头，格式：

> `[演化模式] 具体演化逻辑`

示例：

- `[问题-解决链] 为区分相反意义的量，引入正数和负数`
- `[概念系统化研究] 围绕正负数概念展开其表示方式与应用场景`

**E5（一般链接）— 建议**：`content` 必须填写（不可为空），但不强制 `[演化模式]` 前缀。如果演化逻辑清晰可标注，不清晰时直接写关联说明即可。

> 注：此分层策略已同步到 `system-prompt.ts` 和 `methodology-kernel-thread-evolution.ts`。

示例（E5 无前缀）：

- `教材顺序上紧接提及`
- `作为补充说明出现`

### 2.3 演化脉络的线程等级（E1..E5）

建议按“跨越范围”保守定级，逐步升级：

- E1：跨多章/贯穿学科主干
- E2：跨多节的章级主线
- E3：一节内主线
- E4：一节内重要支线
- E5：一般链接（工具层面建议显式填 E5，不留空）

### 2.4 结构脉络：WWH / 7 要素树

结构脉络面向”组织与检索”，建议以核心概念为根节点，按 WWH 展开：

- 来源（Why）
- 本体（What）：定义 / 表示 / 性质 / 操作 / 关系
- 应用（How）

**结构边 connection-type**：统一使用 `Relevant`（与演化脉络一致，不使用 Include）。

结构边 `content` 必须标注”挂载位”，例如：

- `本体-定义`
- `本体-表示`
- `应用-温度`

结构线程等级（S1..S5）参考：

- S2：章级骨干（核心概念 → WWH 一级）
- S3：节级骨干（WWH 二级 / 7 要素）
- S4：重要细分结构（含递归展开）
- S5：一般结构关联

## 3. 寻宝：知识点提炼（识别 → 命名 → 写入）

### 3.1 逐段精读“两问法”

对教材逐段执行两轮提问：

1. 这段讲什么？是否有知识/案例？
2. 到底是什么知识？属于哪种类型？该怎么命名？

### 3.2 候选识别三层（宁多勿漏）

1. 显性：定义框/公式框/黑体术语
2. 半显性：性质、关键关系（未命名但可独立陈述）
3. 隐性：解释文字里的前提、约定、边界条件、常见误区

### 3.2.1 两阶段：先识别候选，再写入过滤（强建议）

同一段教材里的内容，先按“应收尽收”建立候选清单，再按质量红线决定是否真正写入 KF，避免过早收缩导致漏点。

1. **阶段一：识别候选（宁多勿漏）**
   - 逐段扫描，按 3.2 的显性/半显性/隐性三层列出候选
   - 粒度参考：一页正文通常可识别约 **8–12 个候选知识点/案例**（经验参考，不是硬性指标；空白多的页面会更少，密集页面可能更多）
2. **阶段二：写入过滤（严格把关）**
   - 过渡性文字、完全重复、粒度过粗的候选不写入
   - 证明/推导中的中间结论：若具备可复用价值或能独立陈述，则写入；否则写进卡片内容/案例步骤

### 3.2.2 几何证明粒度（补充规则）

几何章节中，“证明/推导”本身就是知识密度的主要来源，需要避免两种极端：过度聚合（只有几个大定理卡）或过度碎片（把每个编号角等式都建卡）。

- **优先抽象**：把可复用的构造/转化套路建为“操作”类知识点（例如“过顶点作对边平行线证明三角形内角和”）；把推论与逆命题/判定拆为独立知识点
- **避免碎片**：仅对某一幅图的编号角、特定点位成立的中间等式/结论，通常不单独建为知识点卡（写入 content 或作为案例步骤）

### 3.3 “表示法”专项扫描（必须）

对每个核心概念，单独扫描”表示”是否存在多模态/多方案：

- 符号表示（如 `+/-`、记作形式）
- 颜色表示（如算筹红正黑负）
- 图形表示（如数轴/方向箭头/示意图）

规则：

- 每一种表示方案 **单独建卡**：`<核心概念>的表示-<表示类型>(-限定)`。

### 3.4 页面区域框选原则（1 区域 : N 知识点）

v5.003 之后，页面区域选择的正式规则以 [../agent-v5/iterations/v5.003.md](../agent-v5/iterations/v5.003.md) 和 v5 正式文档为准。本节保留 v4 外部 agent 的历史入口心智，但执行时应采用 v5.003 的“区域组计划 + 布局合并判断 + overlay 截图验收”流程。

识别候选后，需要确定每个知识点在页面上的来源区域（page piece）。核心原则是 **一个紧密区域可以挂多个知识点**，避免区域过多导致页面标注混乱。

框选规则（与系统内 Agent 工具 `methodology-kernel.ts` 保持一致）：

- **最小包围**：区域应紧贴知识来源文本，不框入无关内容
- **按可视觉分离的段落拆分**：来自不同段落、不同定义框、或被其他内容隔开的知识点，应归属不同区域
- **短段落可合并**：1-3 行的短段落内若含多个知识点，用一个段落级区域包含，避免过度碎片化
- **不确定时看间隔**：知识点之间有明显视觉间隔（空行、分隔线、标题）→ 拆分；紧密连续 → 合并

示例：

- 反面：一段文字分三句话定义了”整数””分数””有理数”，三句话之间有明显换行/间隔 → 拆为 3 个区域，各自紧贴对应定义句
- 正面：同一个 1-2 行的短段落内同时提到”正数定义”和”负数定义” → 一个段落级区域，挂 2 个知识点卡片

操作模式：

1. 先将候选知识点按页面区域分组（相邻且紧密的候选归为一组）
2. 每组用 `kf ai locate-regions` 定位一个区域坐标
3. 用 `kf card create-page-piece` 创建一个页面区域
4. 在同一页面区域上创建该组的所有知识点卡片

## 4. CLI + Coding Agent 编排流程

### 4.1 生产环境基址

Web 域名（静态站）：`https://mf.daozhuixuetang.com/`  
CLI 访问的 API 网关：建议设置为：

```bash
export KF_API_URL='https://forestapi.daozhuixuetang.com'
```

Agent 服务基址（`kf ai` 命令需要）：

```bash
export KF_AGENT_URL='http://localhost:3101'
```

### 4.2 建构顺序（建议）

#### 阶段一：准备与理解

1. `kf project info` / `kf view list`：确认命名空间与视图，记录演化视图 guid 和结构视图 guid
2. `kf material tree`：获取章节结构，确定目标节的资料 guid 和资料节点 guid
3. `kf graph query --material-node <chapterNodeGuid>`：按目标节口径查重与理解当前图谱；如需检查 view 是否存在跨节污染，再额外执行一次不带 `--material-node` 的全局查询

#### 阶段二：逐页识别与建构

对目标节的每一页重复以下步骤：

4. `kf material page-image`：获取当前页图片 URL 和原始尺寸（coding agent 自己看图理解页面布局）
5. `kf material page-ocr`：获取当前页 OCR 文本（配合图片做知识候选识别）
6. Coding agent 自行识别知识候选：看图 + 读 OCR，按方法论 §3 的”两问法”和”两阶段”提炼候选清单
7. 按 §3.4 的区域框选原则，将候选知识点按页面区域分组（紧密相邻的候选归为一组，一个区域可挂多个知识点）
8. `kf ai locate-regions`：为每个区域组获取页面坐标（传入该组的代表性文本锚点或视觉描述）
9. 对每个区域组：
   - `kf card create-page-piece`：用 locate-regions 返回的 normalized_1000 坐标创建页面区域
   - `kf card create`（×N）：在同一页面区域上创建该组的所有知识点卡片
10. `kf material connect-card`：将知识卡关联到对应章节资料节点（`--relationship-content 定义|引用`）

#### 阶段三：连线与验收

11. `kf link create`：建立演化主线（Relevant + E* + `[演化模式]...`）
12. `kf tag add`：补齐依赖（HaveTag + content）
13. `kf graph query --material-node <chapterNodeGuid> --show-current-user-tags`：按目标节口径验收”依赖网”是否可见
14. 结构脉络：用结构视图 guid 重复 11–13（connection-type 仍为 Relevant，threadLevel 改为 S*，content 改为挂载位）

### 4.3 关键命令提示

#### 页面图片与 OCR

```bash
# 获取页面图片（返回 imageUrl、imageWidth、imageHeight）
kf material page-image --project <projectName> --material <materialGuid> --page <pageNumber>

# 获取单页 OCR 文本
kf material page-ocr --project <projectName> --material <materialGuid> --page <pageNumber>

# 获取整份资料聚合 OCR（适合快速概览，但可能被截断）
kf material ocr --project <projectName> --material <materialGuid>
```

#### 页面区域定位（grounding）

```bash
# 将区域描述转换为 normalized_1000 坐标
kf ai locate-regions --project <projectName> --material <materialGuid> --page <pageNumber> --input-file items.json
```

输入文件格式：每个 item 需要 `id`，以及 `text`（文本锚点）或 `imageDescription`（视觉描述）至少一个。优先提供 `text`，效果更稳定。

输出三态：`matched`（可直接使用）、`ambiguous`（多个候选，需 coding agent 判断）、`not_found`。

#### 创建页面区域

```bash
# 用 locate-regions 返回的 normalized_1000 坐标创建页面区域
kf card create-page-piece --project <projectName> --material <materialGuid> --page <pageNumber> \
  --left <left> --top <top> --width <width> --height <height> \
  --coordinate-system normalized_1000
```

坐标说明：`locate-regions` 返回 `normalized_1000`（0-1000），`create-page-piece` 默认接受 `normalized_1000` 并自动转换为 pixel 落库。详见 `docs/kf-cli-guide.md` 的 Coordinate Modes 章节。

#### 图谱查询

做某一节教材知识建构时，默认应先执行“节内口径”查询：

```bash
kf graph query --project <projectName> --view <viewGuid> --material-node <chapterNodeGuid>
```

如果需要把”依赖标签（HaveTag）”也拉出来：

```bash
kf graph query --project <projectName> --view <viewGuid> --material-node <chapterNodeGuid> --show-current-user-tags
```

如果要检查整个 view 的全局图，用于发现跨节污染、误连线或孤立测试卡片，则执行不带 `--material-node` 的查询：

```bash
kf graph query --project <projectName> --view <viewGuid>
```

说明：

- `--material-node` 会传到服务端的 `filterMaterialTreeNodeGuid`，决定结果是否按目标资料节点递归过滤。做“某一节”的建构、验收、与浏览器页面对齐时，应默认带上。
- 浏览器从教材页进入 `card-graph-view` 时，如果 URL 带 `learningMaterialGuid`，前端会自动将其作为资料过滤传给 `queryviewmodegraph`。因此页面上看到的“知识卡片数”默认是资料过滤后的口径，而不是整个 view 的全局节点数。
- `--show-current-user-tags` 只影响当前用户标签链接（HaveTag）是否返回，不决定节范围。该开关会在 query 里注入 `[我]` 占位符，由服务端替换为当前用户。
- 排障时如果出现“浏览器显示 24、CLI 显示 32”之类的差异，第一步先检查 CLI 是否漏传了 `--material-node <chapterNodeGuid>`；只有在双方过滤口径一致后，才继续检查标签显示或视图配置差异。

## 5. 质量门禁（每批必过）

### 5.1 命名检查

- 是否已创建核心概念裸名锚点？
- 非核心概念是否全部三段式：`概念的类型-核心内容`？
- localName 是否合规（无空格、无括号等非法字符、长度不超）？
- 同类知识的类型词是否一致（不要“定义/概念/含义”混用）？

### 5.2 图谱可读性检查

- 演化脉络是否近似树状（节点是否出现大量多进线）？
- 是否把依赖（前置条件）都通过标签表达，而不是用多条 Relevant 指向同一节点？
- 每条边是否都有可解释 content？

### 5.3 页面区域检查

- 每个知识点是否关联了页面区域（page piece）？
- 页面区域坐标是否合理（不是整页大框，而是紧贴目标区域）？
- `locate-regions` 返回 `ambiguous` 的候选是否已人工/AI 判断后选择？

### 5.4 内容检查（最小可用）

每张知识点卡片有内容。

## 6. 示例：七年级上 1.1《正数和负数》（结构骨架示意）

核心概念（裸名）：

- `正数和负数`
- `相反意义的量`（演化前置，如已存在于其他章节可跳过）

本体（定义/性质）：

- `正数的定义-大于0的数`
- `负数的定义-正数前加负号的数`
- `0的性质-非正非负`
- `数的定义-符号-正号与负号`

表示（多表示法专项）：

- `正数和负数的表示-符号表示`
- `正数和负数的表示-颜色表示`

应用：

- `正数和负数的应用-温度`
- `正数和负数的应用-海拔`
- `正数和负数的应用-收支`
- `正数和负数的应用-增长率`
- `正数和负数的应用-位移与水位变化`

辨析：

- `0的辨析-不是正数不一定是负数`

演化主线示例：

- `相反意义的量` → `正数和负数`
  - content：`[问题-解决链] 为区分相反意义的量，引入正数和负数`

依赖（标签）示例：

- `正数和负数的表示-符号表示` 依赖 `数的定义-符号-正号与负号`
  - tag content：`必要依赖：理解符号表示需先理解正号与负号的基本概念`
