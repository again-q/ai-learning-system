# 📋 项目状态更新清单

> 当你对我说「更新状态」时，我按此清单逐一修改对应文件。
> 本文档按**文档类型**分组，不依赖具体文件名和行号。

---

## 一、时间信息

**涉及的文件类型**：项目概览文档、路线图文档

| 字段 | 说明 |
|------|------|
| 距 9/1 剩余天数 | 所有出现天数的地方同步更新 |
| 时间线 | 路线图文档首段 |

---

## 二、进度概览

**涉及的文件类型**：项目概览文档、路线图文档

| 要更新的内容 | 说明 |
|-------------|------|
| 总进度百分比 | 项目概览文档的进度条 |
| 模块状态表 | 每个模块的状态（✅/🟡/🔴）+ 说明文字 |
| 知识图谱节点数 | 如有变动（增删节点时） |

---

## 三、待办完成状态

**涉及的文件类型**：路线图文档、工程待办文档、代码百科文档

| 要更新的内容 | 说明 |
|-------------|------|
| 已完成清单 | 路线图中的 [x] 完成项 |
| 待开发项表 | 代码百科中的模块当前状态（mock→已接入、占位→已实现） |
| 技术债表 | 代码百科中的已知问题清单 |
| 工程待办 | 工程待办中的 [x] 完成项 |

---

## 四、更新日志

**涉及的文件类型**：路线图文档

每次更新状态时，在路线图文档末尾追加一行：
```
| 日期 | 更新内容 |
```

---

## 五、历史文档的后记

**涉及的文件类型**：复盘文档、方法论文档

当重大里程碑完成时，在对应的历史复盘文档末尾追加「后续更新」备注段落。
不修改原文档正文，保持历史记录的准确性。

---

## 六、执行顺序

```
1. 时间信息 → 更新所有天数
2. 进度概览 → 更新百分比 + 模块表 + 节点数
3. 待办完成 → 更新 [x] + 待开发项 + 工程待办
4. 更新日志 → 追加一行
5. 历史后记 → 如有重大里程碑
6. git add + git commit + git push
```
