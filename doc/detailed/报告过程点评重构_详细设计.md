## 1. 判定层

### 1.1 `orchestrator.reviewProcess` — 带出重核结论

**现状问题**（`orchestrator.js:171-180`）：第②遍只对 broken 单元重核，`cmp2` 用来算 `unstable` 后**丢弃**，`r.cmp` 仍是首判。

**改为**：

```js
// 第②遍（按需复核 broken 单元）
const chk2 = await checkUnit({...});
const cmp2 = compare(r.unit, chk2);
r.rechecked = cmp2;                    // ★新增：带出重核结论
if (cmp2.status !== r.cmp.status) r.unstable = true;
```

**代码收敛（新增纯函数，可单测）**：

```js
/** 两判收敛：只有两遍都判 broken 才定案 */
function settleStep(r) {
  const first = r.cmp || {};
  const second = r.rechecked || null;
  if (first.status !== 'broken') return { status: first.status };
  if (!second) return { status: 'broken' };               // 未复核（成本保护）→ 采信首判
  if (second.status === 'broken') return { status: 'broken' };
  return { status: 'unknown', note: '两次判断不一致' };    // ★不定案
}
```

`results[]` 每项最终形态：

```js
{ i: unit.i, raw: unit.raw, status, claim, correct, reason, unstable }
```

> ⚠️ 红线：**不改 `compare()`、不改 `checkUnit()`、不改复核触发条件**（决策 061 红线 3）。只把已有结果带出来 + 加一层收敛。

### 1.2 `orchestrator.answerPath` — AI 做法 + 更优判定（**新增**）

```js
/**
 * @returns {Promise<null|{steps:Array<{step,content,note}>, moreEfficient:boolean,
 *                     betterAt:number|null, whyBetter:string|null, elapsedMs:number, calls:number}>}
 */
async function answerPath({ call, questionText, work, referenceProcess, correctAnswer, logger })
```

**Prompt**（`graphEngine/src/lib/prompts.js` 新增常量 `ANSWER_PATH_SYS`）：

```
你在给一名高一学生写**这道题的一种做法**，目的是让他对照自己的过程看是否更省。
输入：题干、学生过程（可能为空）、学生答案正误。
输出纯 JSON：
{"steps":[{"step":"步骤标题","content":"推导（LaTeX）","note":"为什么这么做"}],
 "moreEfficient":true|false,
 "betterAt":3,          // 学生的第几步可以被这段做法替换；没有就给 null
 "whyBetter":"≤40字"}
规则：
- steps 3~8 步，必须逻辑闭合、与正确答案自洽。
- moreEfficient 只在同时满足时才给 true：
  ① 你的做法步数明显更少，或分类讨论明显更少，或计算量明显更小（三者之一）
  ② 不引入学生没用到的新方法/新定理
  ③ betterAt 必须指向学生过程中真实存在的一步
- 否则 moreEfficient=false、betterAt=null、whyBetter=null。
- **做对的题同样要写**；不要因为做对了就说「已经很好了」。
- 禁止用「通法」「这类题一般」这类说法。
```

**代码侧解析 + 守卫**：

```js
function parseAnswerPath(text, workStepCount) {
  const j = extractJson(text);
  if (!j) return null;
  const steps = (Array.isArray(j.steps) ? j.steps : [])
    .map((s) => ({ step: String(s.step||'').slice(0,80),
                   content: String(s.content||'').slice(0,800),
                   note: String(s.note||'').slice(0,300) }))
    .filter((s) => s.step && s.content);
  if (steps.length < 2 || steps.length > 10) return null;
  let moreEfficient = j.moreEfficient === true;
  let betterAt = Number.isInteger(j.betterAt) ? j.betterAt : null;
  const whyBetter = String(j.whyBetter || '').trim().slice(0, 60) || null;
  // 守卫 ①②③（ADR-5）
  if (!whyBetter || !/步骤|步数|分类|计算/.test(whyBetter)) moreEfficient = false;
  if (betterAt == null || betterAt < 1 || (workStepCount && betterAt > workStepCount)) moreEfficient = false;
  if (/新方法|新定理|换个思路|通法/.test(whyBetter)) moreEfficient = false;
  if (!moreEfficient) betterAt = null;
  return { steps, moreEfficient, betterAt: moreEfficient ? betterAt : null,
           whyBetter: moreEfficient ? whyBetter : null };
}
```

> `workStepCount` 传**学生过程段数**（`raw.segments.length` 或编排 `units.length`）；为 0 时**一律不给更优**（无可比较的步骤）。

**触发条件**（`judgeAI.js`）：

```
questionType === '解答'  ∧  ANSWER_PATH !== 'off'
```

**失败降级**：`null` → `issues.push('N2: answerPath 失败')`，不阻塞判定。

### 2.2 `correctNote()` — 模板句（纯函数，**不调用模型**）

```js
/**
 * 做对的题：这题考什么（模板句）
 * @param {Array<{name:string,P:number}>} usage  knowledgeUsage
 * @returns {string}
 */
function correctNote(usage) {
  const names = (usage || []).map((u) => String((u && u.name) || '').trim()).filter(Boolean);
  // 用对的优先（P>=1），保持原顺序去重，最多 3 个
  const seen = new Set();
  const picked = names.filter((n, i) => {
    if (seen.has(n)) return false; seen.add(n); return true;
  }).sort((a, b) => score(b) - score(a)).slice(0, 3);
  if (!picked.length) return '';
  const list = picked.length === 1 ? `「${picked[0]}」`
    : picked.length === 2 ? `「${picked[0]}」和「${picked[1]}」`
    : `「${picked[0]}」「${picked[1]}」和「${picked[2]}」`;
  const lines = [`这道题考的是${list}。`];
  picked.forEach((n) => lines.push(`你能做对，说明「${n}」这块掌握得还可以。`));
  return lines.join('');
}
```

- 只在 `status === '对'` 时写入报告快照字段 `correctNote`
- 失败/无知识点 → `''`（前端不渲染）

### 2.3 `aiApproach()` — 对题 AI 做法（`generateV2.js`）

```js
async function aiApproach(q) {
  if (String(q.questionType) !== '解答') return null;
  if (Array.isArray(q.referenceProcess) && q.referenceProcess.length) return null;  // 判定层已给
  const user = JSON.stringify({
    questionText: (q.questionText || '').slice(0, 800),
    studentWork: studentWorkOf(q).slice(0, 1500),
    correctAnswer: q.correctAnswer || '',
    studentStatus: q.status,
  });
  const out = await callLLM(readPrompt('ai-approach.txt'), user, 2000);
  return parseAnswerPath(out, stepCountOf(q));
}
```

**并行位置**：`reportService/index.js` 的 `worker()` 内，与 `diagnosis` **顺序执行但同一 worker**（保持并发 5 不变，避免瞬时打爆模型限额）。

**守卫**：输出不合法（<2 步、缺 content）→ 返回 `null`，该题不渲染 AI 做法块。

**Prompt `sub-think-guess.txt`**：

```
你在猜一名高一学生在某一小问的某一步**当时是怎么想的**。注意：这是猜测，不是结论。
输入：整题、本小问、学生在这一小问写的内容（原文）。
硬性要求：
- 只输出 1~2 条**互相排斥**的可能，每条都必须引用学生原文中的一段（逐字复制，不得改写）。
- quote 必须能在学生原文里原样找到；找不到就不要写这条。
- why 说「凭什么这么猜」，只能引用学生写出来的东西，不许写「你粗心」「你没想到」「你以为」。
- guess 写「如果是这样，说明当时是怎么走的」。
- 学生原文为空 → 输出 {"guesses":[]}。
输出纯 JSON：{"guesses":[{"quote":"学生原文片段","why":"凭什么这么猜","guess":"如果是这样，说明"}]}
```

**代码侧逐字校验（防编造）**：

```js
function verifyQuotes(guesses, studentWork) {
  const norm = (s) => String(s || '').replace(/\s+/g, '').replace(/[，。；：、]/g, '');
  const w = norm(studentWork);
  return (guesses || []).filter((g) => g.quote && w.includes(norm(g.quote)));
}
```

**编排改动**（`subThinking/index.js`）：

```
generateSubThinking:
  ① 缓存命中（含新版本键）→ 返回
  ② 先 guess()  ← ★新增，用 sub.studentWork（splitter 已有）
  ③ 再 solve → verify → think（原有，结果放 otherWay）
  ④ 落库：{ subNo, guesses, selfThought, otherWay: thinking, solution, verified, ... , promptVersion }
```

**缓存键升级**：记录里加 `promptVersion: 'guess-v1'`；缓存命中条件加 `cached.promptVersion === CURRENT_VERSION`（否则重算）。

**前端展示顺序**：

```
AI 猜测 · 不是结论
  ┌ 「你写了：{quote}」
  │  AI 之所以这么猜：{why}
  │  如果是这样：{guess}
  └ （第二条同理）
  [ 我当时是这么想的：__________ ]   ← 输入框
```

## 7.5 流程门禁说明（2026-10-25 核查）

本设计的改动包含 `graphEngine`（判定层），按 `coding-rules.md` 需要 `gate.sh pre` + `gate.sh post` 验证。

实现阶段先跑一次 `gate.sh pre` 确认其可执行；若门禁脚本要求的东西本项目提供不了（如缺失的验证脚本），
