## 1. 功能描述

四个可独立验收的能力：

| # | 能力 | 一句话 |
|---|---|---|
| 1 | 小问切分 | 把一道解答题的作答与参考过程按 (1)(2)(3) 切开 |
| 2 | 按需生成思路 | 点某个小问 → 独立求解 → 验证 → 通过才出 3~6 步思路 |
| 3 | 追问 | 多轮对话，不截断 |
| 4 | 诊断更正 | 只改 `diagnosis.*` 三个字段，判定字段只读 |

### 3.1 `cards.js` — 54 项思维清单

**职责**：提供白名单名字，供 prompt 注入与输出校验。

```js
// lib/subThinking/cards.js
const CARDS = require('./cards.json');

/** 全部名字（去重，不含花色牌号） */
function allNames() {
  const names = [
    ...CARDS.jokers.map((j) => j.name),
    ...CARDS.suits.flatMap((s) => s.cards.map((c) => c.name)),
  ];
  return [...new Set(names)];
}

/** prompt 里用的名字串 */
function namesForPrompt() {
  return allNames().join('、');
}

/**
 * 校验模型输出的 cards：
 *  - 剥掉可能残留的花色牌号（如「♠10 转化策略」→「转化策略」）
 *  - 不在白名单里的名字剔除（不报错，静默过滤，避免整条思路作废）
 */
function sanitizeCards(input) {
  const list = Array.isArray(input) ? input : [];
  const white = new Set(allNames());
  const out = [];
  for (const raw of list) {
    const name = String(raw || '')
      .replace(/^[♠♥♦♣]\s*(A|K|Q|J|10|[2-9])?[\s:：]*/, '')
      .trim();
    if (name && white.has(name) && !out.includes(name)) out.push(name);
  }
  return out.slice(0, 2);   // 最多两个
}

module.exports = { allNames, namesForPrompt, sanitizeCards, CARDS };
```

**单测要点**：
- `allNames().length === 54`
- `sanitizeCards(['♠10 转化策略'])` → `['转化策略']`
- `sanitizeCards(['自造名词'])` → `[]`

### 3.2 `splitter.js` — 小问切分

**职责**：把整题的题面、学生作答、参考过程按小问切开。

#### 3.2.1 输入输出

```js
/**
 * @param {object} args
 * @param {function} args.call       模型调用
 * @param {string} args.questionText 题面
 * @param {string} args.studentWork  学生作答（traceReport 或 segments 拼接）
 * @param {Array}  args.referenceProcess 参考过程 [{step, content, note}]
 * @param {Array}  args.segments     判定分段 [{step, status, evidence}]
 * @returns {Promise<{
 *   subQuestions: Array<{
 *     subNo: string,        // '(1)' | '(2)' | '(3)' | '全题'
 *     ask: string,          // 该小问的设问
 *     studentWork: string,  // 学生对应该小问的作答片段
 *     refSteps: Array,      // 该小问对应的参考步骤
 *     isWrong: boolean,     // 该小问是否被判错
 *   }>,
 *   splitFallback: boolean  // 是否退化为整题
 * }>}
 */
async function splitSubQuestions(args)
```

#### 3.2.2 算法

```
① 用正则从 questionText 抓小问标记，但**必须通过三重校验**（否则会误判）：

   基础正则： /[(（]\s*(\d+)\s*[)）]/g

   ⚠️ 2026-10-18 实测踩到的坑：
      「已知 f(x)=(1)x^2，求 f(2) 的值」会被抓出 ['1','2'] ——
      但 (1) 是系数、(2) 是 f 的自变量，**都不是小问标记**。
      不加校验就会把一道单问的题切成两问，生成两次无意义的思路。

   三重校验（全部满足才认定是小问）：
   a) **编号必须从 1 开始且连续递增**：[1,2,3] ✅ / [1,2] ✅ / [2] ❌ / [1,3] ❌
   b) **标记后（跳过 `$` 与空白）必须紧跟设问动词**：
      判断/证明/求/若/已知/解/设/用/写出/计算/说明/化/比较
      —— 实测：题面的小问是 `$(1)$ 判断…` 这种 LaTeX 包裹，
         所以必须先剥掉 `$` 和空白再比对，否则会把真题全部误判为「不是小问」
   c) **相邻两个标记之间（剥掉 `$` 与空白）必须有 ≥ 8 个字符**，
      否则是「并列小项」而非小问

   ⚠️ 校验方向是【宁可漏判，不可误判】：
      漏判的代价 = 退化成整题生成（多花一点钱）；
      误判的代价 = 把一道单问的题切成两问，生成两次无意义内容（更差）。
      实测取舍：`解不等式 (1) x>1 (2) x<2` 这类「短小问」会被判为非小问 → 退化为整题（可接受）。

   通过 → 按位置切分题面，得到 subTexts
   不通过 → 视为单问

② 若校验不通过（或标记 < 2）→ 整个题面作为一问，subNo = '全题'

③ 学生作答对齐：
   - 若学生作答里也有同样的小问标记 → 按标记切
   - 否则用 AI 判断（sub-split.txt）：把作答按小问归属切开
   - AI 判断失败 → 全部归到第一个小问，其余小问 studentWork = ''

④ 参考过程对齐（referenceProcess 的 step 通常自带「第N问」）：
   - 正则 /第\s*[（(]?(\d+)[)）]?\s*问/ 匹配
   - 匹配不到 → 平均分配或全归第一问

⑤ 校验：
   - subQuestions.length 必须 ∈ [1, 6]
   - 每个 subNo 唯一
   - 所有 studentWork 拼接后，非空片段必须都能在原文找到（防丢内容）
   - 不通过 → splitFallback = true，返回单元素数组
```

#### 3.2.3 `isWrong` 判定

```js
function isSubWrong(sub, question) {
  // 优先用官方三态（若有）
  if (question.officialStatus) {
    return question.officialStatus !== '对';   // 半对/错 都算「值得看思路」
  }
  // 无官方分：按过程分
  return question.processScore != null && question.processScore < 1;
}
```

**注意**：PRD N3-改 规定**所有小问都给入口**，`isWrong` 只用于**显示标记**（✓/✗），不用于隐藏入口。

#### 3.2.4 关键边界

| 情况 | 处理 |
|---|---|
| 题面只有一个设问 | `subNo='全题'`，不调 AI 切分 |
| 双栏作答（第 17 题） | 优先取右栏（修正版）；用 `physicalLayout` 判断不可靠时，交给 AI 判断 |
| 小问数量 > 6 | 判为切分错误，退化整题 |
| 学生作答为空 | 各小问 `studentWork=''`，仍可生成思路（用于「这题怎么想」） |

### 3.3 `solver.js` — 独立求解

#### 3.3.1 输入输出

```js
/**
 * @returns {Promise<{
 *   answer: string,
 *   steps: Array<{ step, math, selfCheck }>,
 *   confidence: '高'|'中'|'低'
 * } | null>}  // null = 解析失败
 */
async function solve({ call, questionText, subNo, ask })
```

#### 3.3.2 关键约束

| 约束 | 实现 |
|---|---|
| **不看学生作答** | 入参里根本没有 `studentWork` 字段 |
| 开思考 | `thinking: { type: 'enabled' }` |
| `max_tokens` | 16000（实测：6000 会被思考吃光，正文为空） |
| 禁止跳步 | prompt 明令：「不允许『借助已有运算』『最终可得』『易证』『显然』」 |

#### 3.3.3 ⚠️ 实测踩坑（必须写进代码注释）

```
2026-10-18 实测：thinking=enabled 时，max_tokens 是【思考 + 正文】共享预算。
首次给 6000，思考吃光后 content 长度 = 0（模型什么都没输出，不是它不会讲）。
→ 必须给 16000，且要从 usage.completion_tokens_details.reasoning_tokens 确认。
```

### 3.4 `verifier.js` — 逐步验证与裁决

#### 3.4.1 输入输出

```js
/**
 * @returns {Promise<{
 *   overall: 'pass'|'partial'|'fail',
 *   raw: '成立'|'部分成立'|'不成立',
 *   problems: Array<{step, issue, severity}>,
 *   note: string,
 * }>}
 */
async function verify({ call, questionText, subNo, ask, solution })
```

#### 3.4.2 裁决规则（**判断权在代码**）

```js
// 模型返回的字符串 → 代码裁决成枚举
function decide(rawOverall) {
  const s = String(rawOverall || '').trim();
  if (s === '成立') return 'pass';
  if (s === '部分成立') return 'partial';
  if (s === '不成立') return 'fail';
  return 'fail';   // 无法识别 → 保守判失败
}
```

**关键**：`decide()` 是唯一裁决点，不允许 `thinker` 里再判断一次。

#### 3.4.3 重试策略

```
第 1 次验证 fail
  → 把「验证器指出的问题」反馈给 solver，重解一次（retry 1）
  → 再验证
第 2 次仍 fail
  → 再重解一次（retry 2）
  → 再验证
第 3 次仍 fail
  → 放弃出思路，返回 verified='fail'
```

**总调用次数**：最多 1 求解 + 1 验证 + 2×(1 求解 + 1 验证) = **6 次**
（注：PRD 写「单问 ≤3 次调用」指**正常路径**；重试是异常路径，PRD 需补注，见 §8 待办）

### 3.5 `thinker.js` — 思路生成

#### 3.5.1 输入输出

```js
/**
 * @returns {Promise<{
 *   goal: string,
 *   steps: Array<{
 *     n: number,
 *     have: string, lack: string, why: string, do: string,
 *     thinking: { cards: string[], say: string }
 *   }>,
 *   ending: string,
 * } | null>}
 */
async function think({ call, questionText, subNo, ask, solution })
```

#### 3.5.2 输出校验（代码侧）

```js
function validateThinking(t) {
  if (!t || !Array.isArray(t.steps)) return null;
  if (t.steps.length < 2 || t.steps.length > 8) return null;  // 允许 2 步（极简小问）
  for (const s of t.steps) {
    if (!s.have || !s.lack || !s.why || !s.do) return null;   // 四要素缺一不可
  }
  // cards 已在 cards.js sanitize
  return t;
}
```

**步数约束**：PRD 写 3~6 步，但实测 (1) 只有 3 步、极简小问可能 2 步。
**设计定**：`[2, 8]` 区间，prompt 引导 3~6，代码放宽到 2~8 避免误杀。

### 3.6 `corrector.js` — 诊断更正

#### 3.6.1 白名单

```js
const WRITABLE_FIELDS = [
  'diagnosis.comment',
  'diagnosis.inference',
  'diagnosis.hook',
];

const READONLY_FIELDS = [
  'errorType', 'processScore', 'errorLevel', 'errorDimension',
  'segments', 'breakpoint', 'processAvailable',
  'officialScore', 'officialStatus', 'officialStandardScore',
];
```

#### 3.6.2 校验流程

```js
async function correctDiagnosis({ db, questionId, userId, field, newText, evidence }) {
  // ① 白名单
  if (READONLY_FIELDS.includes(field)) {
    return { code: 403, message: '该字段是判定结果，不可修改' };
  }
  if (!WRITABLE_FIELDS.includes(field)) {
    return { code: 403, message: '只能更正诊断文案（comment/inference/hook）' };
  }
  // ② evidence 必填
  if (!String(evidence || '').trim()) {
    return { code: 400, message: '必须说明原诊断错在哪' };
  }
  // ③ 归属校验
  const q = await db.collection('questions').doc(questionId).get();
  if (!q.data || q.data.userId !== userId) {
    return { code: 403, message: '无权修改' };
  }
  // ④ 取值
  const key = field.split('.')[1];
  const before = (q.data.diagnosis || {})[key] || '';
  // ⑤ 先写 revisions，再改 diagnosis
  await db.collection('questions').doc(questionId).update({
    data: {
      revisions: _.push([{
        field, before, after: newText, evidence,
        confirmedBy: 'student', createdAt: Date.now(),
      }]),
    },
  });
  await db.collection('questions').doc(questionId).update({
    data: { [`diagnosis.${key}`]: newText },
  });
  return { code: 0, data: { updated: true, before, after: newText } };
}
```

**顺序要求**：先 `revisions` 后 `diagnosis`——若第二步失败，至少留痕可回溯。

### 3.7 `index.js` — 编排

```js
async function generateSubThinking({ db, call, question, subNo, logger }) {
  const t0 = Date.now();

  // 0. 缓存
  const cached = (question.subThinking || []).find((x) => x.subNo === subNo);
  if (cached && cached.verified === 'pass') return { ...cached, cached: true };

  // 1. 切分（只切一次，取目标小问）
  const { subQuestions } = await splitSubQuestions({ call, ...pick(question) });
  const sub = subQuestions.find((s) => s.subNo === subNo) || subQuestions[0];

  // 2. 求解
  let solution = await solve({ call, questionText: question.questionText, subNo: sub.subNo, ask: sub.ask });
  if (!solution) return { verified: 'fail', verifyNote: '求解失败' };

  // 3. 验证（含重试）
  let ver = await verify({ call, questionText: question.questionText, subNo: sub.subNo, ask: sub.ask, solution });
  let retries = 0;
  while (ver.overall === 'fail' && retries < 2) {
    retries++;
    solution = await solve({ call, ..., previousIssues: ver.problems });
    if (!solution) break;
    ver = await verify({ ... });
  }

  // 4. fail → 不出思路
  if (ver.overall === 'fail') {
    return { subNo, verified: 'fail', verifyNote: ver.note, thinking: null };
  }

  // 5. 出思路
  const thinking = await think({ call, questionText: question.questionText, subNo: sub.subNo, ask: sub.ask, solution });
  if (!thinking) return { subNo, verified: ver.overall, verifyNote: '思路生成失败', thinking: null };

  // 6. 存库
  const record = {
    subNo, ask: sub.ask,
    verified: ver.overall, verifyNote: ver.overall === 'partial' ? ver.note : '',
    solution, thinking,
    model: MODEL, elapsedMs: Date.now() - t0, generatedAt: Date.now(),
    followUps: cached ? cached.followUps : [],
  };
  await db.collection('questions').doc(question.questionId).update({
    data: { subThinking: _.pull({ subNo }) },   // 去掉旧的
  });
  await db.collection('questions').doc(question.questionId).update({
    data: { subThinking: _.push([record]) },
  });

  return record;
}
```

## 5. 提示词

### 5.1 `sub-solve.txt`

```
你是一名严谨的数学竞赛教练。请只针对指定的那一小问，给出完整、严格的解答。

要求：
1. 不允许出现「借助已有运算」「最终可得」「易证」「显然」这类跳过性表述，每一步写完整推导。
2. 若该小问依赖前面小问已证的结论，可以直接引用并写明引用的是哪一问。
3. 如果某步不确定，明确写「此处不确定」。
4. 最后判断这一小问是否成立。

输出纯 JSON：
{"answer":"这一小问的结论",
 "steps":[{"step":"这步在做什么","math":"完整数学推导","selfCheck":"成立/不成立/不确定"}],
 "confidence":"高/中/低"}
```

**⚠️ 禁止加任何具体数学例子**（决策 061 §8）。

### 5.2 `sub-verify.txt`

```
你是一名严格的证明审阅者。只审查给出的小问解答，逐行判断每一步在数学上是否严格成立。

规则：
1. 每步独立核对：依据是什么（题设条件？前面小问结论？本问前面步骤？），推理是否成立。
2. 不要因为结论对就放过中间步骤。
3. 特别注意：有没有把「要证的」当成「已证的」来用；有没有计算错误；有没有跳过性表述掩盖未完成的推理。
4. 引用前面小问结论时，核对那个结论本身是否已证。

输出纯 JSON：
{"overall":"成立/不成立/部分成立","problems":[{"step":第几步,"issue":"问题","severity":"致命/严重/轻微"}],"note":"整体评价"}
```

### 5.3 `sub-think.txt`

```
你在给一名高一学生讲**某一个具体小问**的解题思路。不是讲通法，不是讲套路，而是呈现这一小问是怎么一步步被想出来的。

对每一步，必须回答四件事：
1. 此刻手上有什么（题目给了什么条件、前面已经推出了什么）
2. 还缺什么（离目标差在哪）
3. 为什么下一步自然会往这里走（是什么让人想到要这么做）
4. **这一步用到了什么数学思维**——必须从下面这份名字里选，再用一句人话说清怎么用的：
   {{CARDS}}
   规则：
   - 只写【名字】，不要写花色、牌号、编号。
   - 优先选最贴合的那一个；一个说不清可以选两个（最多两个）。
   - 不允许自造名单外的名词。
   - 简单步骤（如直接代入条件）没有真思维含量时，cards 给空数组，say 写「直接套用条件」。

硬性要求：
- 每一步都要能明确推出下一步，逻辑闭合，中间不能跳跃。
- 不允许出现没有动机的步骤。
- 不允许用「通法」「这类题一般」「套路」这类说法。
- 只讲指定的这一小问，**不要讲其他小问**。
- 篇幅克制：一般 3~6 步即可，不要为了详细而拉长。

输出纯 JSON：
{"goal":"这一小问要证明/求出什么（一句话）",
 "steps":[{"n":1,"have":"手上有什么","lack":"还缺什么","why":"为什么走这步","thinking":{"cards":["转化策略"],"say":"一句人话解释"},"do":"这一步具体做了什么"}],
 "ending":"这一小问的思路是怎么闭环的"}
```

### 5.4 `sub-split.txt`（仅当学生作答无小问标记时调用）

```
把学生的作答按题目的小问归属切开。

规则：
- 只能切分，不能改写学生原文。
- 如果某段无法确定归属，归到最接近的前一个小问。
- 输出必须覆盖原文全部内容。

输出纯 JSON：
{"parts":[{"subNo":"(1)","text":"原文片段"}]}
```

const subQuestions = splitForDisplay(q);
